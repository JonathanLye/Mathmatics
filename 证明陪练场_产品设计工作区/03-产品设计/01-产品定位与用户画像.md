## 0. 一页纸

**一句话定位**：面向高校数学分析学生的**证明题陪练**——学生在手机或网页上分步写证明，AI 不写证明、不给答案，只指出「第一处可疑步骤」并按 L0–L4 逐级给最小提示，逼学生自己写完；老师看到的是**过程数据**，不是一个分数。

**三句话差异化**

1. **产出物不同**：通用 AI 给答案，我们给「学生自己写出来的证明」。
2. **数据不同**：通用 AI 只留聊天记录，我们留下每题每轮的阶段、提示等级、卡点、是否独立完成，教师可导出做教学与研究。
3. **题库不同**：题目必须经任课教师审核后学生才能看到，关键要点、各级提示都由教研预先写好，AI 只在框内说话。

**三个关键数字**（详见第 7 节）

- 试点目标：前后测平均分提升 ≥10%，实验班比对照班多 ≥8 个百分点；
- 产品体验目标：独立完成率 ≥70%，中途放弃率 ≤15%；
- 试点节奏：每周 3 题 × 4 周，D0 前测、D28–D30 后测（《契约》D7）。

## 1. 一句话定位与边界

### 1.1 定位

> **证明陪练场 = 一个「不替学生写作业」的 AI 助教 + 一套给老师看的过程数据。**

它不是题库 App（题库只是入口），不是答疑机器人（答疑只是兜底），也不是判分系统（首版不对整题判分）。它卖的是**「自己写出来」这件事发生的过程**。

### 1.2 对甲方怎么讲（30 秒版）

> 学生最痛苦的不是不会算，是「看懂答案却写不出证明」。我们做的是：学生每写一步，系统只问一句「你这一步的依据是什么」；卡住了，按 5 个等级一点点给提示，最多给到「示范一行，剩下你来」；全程不给完整证明。老师打开后台，能看到班里谁卡在哪个知识点、平均用了几次提示、多少人是自己写完的。这些数据也能导出给课题用。

### 1.3 产品边界

| 做 | 不做（首版） |
|---|---|
| 只做数学分析证明题 | 计算题、选择题、其他数学课（高等代数等） |
| 分步写证明 + 逐步反馈 | 拍照识题、公式键盘、自动批改并给分 |
| 提示阶梯 L0–L4 + 拒绝模板 | 「给我完整证明」的任何变通出口 |
| 教师审核题库与过程数据看板 | 家长端、社交、排行榜 |
| H5 快速原型 → 微信小程序壳 | 原生 App、多学校多租户 |

> 依据：《契约》第 9 节；《需求确认书》「明确不做」清单。**冲突提示**：需求确认书「最终交付必须包含」里写了「拍照上传自己做的题目」，而《契约》D4 默认口径是「本轮不做拍照问答（v2.0 视为混淆变量）」。本文按《契约》写，冲突见第 9 节。

## 2. 先把四个词说清（给非数学专业读者）

| 词 | 白话解释 |
|---|---|
| 证明题 | 不是算出数，而是要求你一条条讲道理：为什么这个结论一定成立。答案对不算完，每一步都得有依据。 |
| 级数 | 把一串数加起来，比如 1 + 1/2 + 1/3 + …一直加下去。加不完，就问「总和会不会稳定在一个数附近」。 |
| 收敛 / 发散 | 这一串数加起来「会稳住」叫收敛；「越加越大、刹不住」叫发散。 |
| 条件收敛 / 绝对收敛 | 带上正负号才收敛叫条件收敛；把负号全去掉、只加正数也收敛，叫绝对收敛。绝对收敛比条件收敛「更结实」。 |
| 莱布尼茨判别法 | 判断「正负交替的级数」是否收敛的三条检查规则（数越来越小、最终趋近 0、符号交替），像过安检，三条都要过。 |
| 提示阶梯 L0–L4 | 五级「挤牙膏式」提示：L0 只问你自己检查，L1 只点一个定义的名字，L2 只指方向，L3 只给一步操作，L4 示范一两行后立刻把笔交还。级别越高给得越多、次数越少。 |
| 过程数据 | 不是「对了几题」，而是：卡在第几步、用了几次提示、哪一步停留多久、有没有粘贴、最后是不是自己写完的。 |
| 独立完成 | 分三档：独立=全程只用最轻的 L0 追问；半独立=用过 L1–L2；依赖=用过 L3–L4 或出现粘贴标记。教师端分列看，不合成一个百分比（《契约》4.1 C1）。 |

## 3. 三类用户画像

> 说明：试点按《需求确认书》D1-02 覆盖「大一/大二在读 + 考研复习 + 补考重修」三类（甲方勾选了全部，建议以大一在读为主）。三类人的痛点不同，产品必须**一套流程、三种节奏**。

### 3.1 画像 A：大一跟课生「小周」——核心用户

| 维度 | 描述 |
|---|---|
| 一句话 | 上课听得懂，作业写不出，考试步骤分丢得最多。 |
| 年级/课程 | 大一下，数学分析（上册→下册过渡），正在学极限、连续、微分 |
| 目标 | 这周作业能自己写完；期末证明题能拿步骤分；不被同学说「用 AI 抄的」 |
| 当前能力 | 会套公式、会算极限，但写不出「任给 ε，存在 N」这种严格说法；分不清「要证什么」和「怎么算」 |
| 设备/网络 | 手机为主（微信小程序预期形态），宿舍 Wi-Fi 一般，偶尔流量；屏幕 6–6.7 英寸 |
| 使用时长/时段 | 单次 15–25 分钟；晚 20:00–23:00；每周 2–4 次 |
| 担心什么 | ① AI 直接给答案，自己还是不会；② 提示要花钱/次数太少；③ 老师看到「用了几次提示」觉得自己笨；④ 被判定作弊 |
| 产品怎么接住 | 首屏一句话说清「这里不给答案」；提示预算直接显示在按钮上（不用猜）；提示只进教师端「独立完成」标签、**不扣分**；粘贴只记录不处罚（《契约》第 6 节、v1.0 4.9.3「非惩罚原则」） |
| 产品暗示 | 教师端默认匿名导出；学生端不展示「提示多了会扣分」之类文案 |

### 3.2 画像 B：考研复习生「阿颖」——高价值、高要求

| 维度 | 描述 |
|---|---|
| 一句话 | 学过一遍但忘了，想要「恢复手感 + 能带走的方法」。 |
| 年级/课程 | 大四或二战，复习数分证明题（极限、级数、一致收敛是重灾区） |
| 目标 | 把判别法、证明套路重新捡起来；能形成自己的错题/规律笔记；不想在「AI 讲废话」上浪费时间 |
| 当前能力 | 概念有印象、会套判别法，但严格表述常漏条件；喜欢看「为什么这样想」 |
| 设备/网络 | 平板或电脑网页为主，网络稳定 |
| 使用时长/时段 | 单次 30–40 分钟整块时间；白天自习室；每周 3–5 次 |
| 担心什么 | ① AI 讲得太浅、像哄小孩；② 提示太啰嗦、来回好几轮才给有用信息；③ 自己写的规律、自检卡不能带走；④ 题目太简单 |
| 产品怎么接住 | 可选题、按知识点筛难题；L1/L2 文案专业但短；阶段 6 产出「规律 + 自检卡」可保存/复制；变式题难度与主题一致 |
| 产品暗示 | 后续版本可加「我的规律库」，首版先保证 S5 可保存（《契约》S5 关键元素含 3–5 条规律与自检卡） |

### 3.3 画像 C：补考重修生「小陈」——最容易被劝退

| 维度 | 描述 |
|---|---|
| 一句话 | 基础断层、怕被贴标签，最需要「一小步也算进步」。 |
| 年级/课程 | 大二/大三重修；可能同时补多门 |
| 目标 | 及格；拿到能拿的步骤分；别再挂 |
| 当前能力 | 定义基本忘光；看到「证明」两个字就想退；写一步就卡 |
| 设备/网络 | 手机（可能较旧）、网络不稳、常在地铁/宿舍 |
| 使用时长/时段 | 单次 10–15 分钟；碎片时间；容易中途放弃 |
| 担心什么 | ① 看不懂、被 AI 说「这么简单」；② 卡太久没面子；③ 老师看到名单里有自己被点名 |
| 产品怎么接住 | 允许「带病前进」（P1 两轮不过记录薄弱点但不阻塞）；更早触发 L1/L2；卡住时可直接换更小题（预算用尽出口 C）；语气支持、不评判；未完成只进教师「未完成名单」用于帮扶，不做公示 |
| 产品暗示 | 完成页先肯定「你自己写完了 3 步」，再谈掌握度；不出现红叉/分数排行榜 |

### 3.4 三类用户的共同点与冲突取舍

- 共同点：**都怕「被喂答案后还是不会」**，也怕「卡住没人管」——这正是「不给答案 + 按级提示」的立足点。
- 冲突：考研生要难、要快；重修生要简单、要慢；跟课生要贴合本周课程。**取舍**：题库按「章节 + 难度 + 必做/选练」分层，同一套流程不改，只改推题与提示触发阈值（重修生更早升 L1/L2，见 04 文档 5.3）。
- 试点优先级：大一跟课生 > 考研复习生 > 补考重修生（与《需求确认书》D1-02 建议 A、D1-03 规模一致）。

## 5. 与「豆包爱学」等通用 AI / 学习 App 的差异

> 说明：通用 AI 助手的产品形态与功能会快速变化，本表只对比**机制层面**的差异，不评价对方产品优劣；涉及外部产品的具体功能描述标记「待验证」，《需求确认书》仅提出「现有软件豆包爱学等，需有区分和不同」。

| 对比维度 | 通用 AI 答疑（豆包爱学类） | 本产品（证明陪练场） |
|---|---|---|
| 学生最终拿到什么 | 一段可抄的解答 / 讲解 | **学生自己写的证明**（终稿是唯一计分依据） |
| 是否给完整证明 | 通常给，越完整越「好用」 | **红线禁止**：完整证明、最终答案、可连成证明的 ≥3 步推导都不行（《契约》第 6 节） |
| 学生卡住时 | 直接重讲一遍 / 换种说法讲 | 先问依据（L0），再按 L1→L4 最小提示，给完立即交还 |
| 教师角色 | 基本没有 | 建班发码、**审核题库**、看过程看板、抽看、导出、复测 |
| 题目来源 | 开放 / 拍照识题 | 50 题审核题库，题目、关键要点、各级提示均人工校对 |
| 过程数据 | 只有聊天记录，不可结构化导出 | 每题每轮记录阶段、提示等级、卡点、用时、粘贴标记、独立完成（字段见 02 文档第 7 节） |
| 防「代写」 | 无 | 拒绝模板 + 替代动作 + 粘贴标记 + 变式题 + 复述关卡 |
| 评价方式 | 对错 / 给分 | **首版不判整题对错**，只定位第一处可疑步骤 + 覆盖表（D1 默认口径） |
| 教学闭环 | 无 | 前测 → 4 周练习 → 后测 → 延迟后测（可选） |
| 商业模式 | 订阅/会员 | 学校/课题免费使用（《需求确认书》D10-03 长期免费） |

**一句话对甲方讲差异**：别人卖「答案的获取速度」，我们卖「学生自己写出来的过程 + 老师能用的数据」。

| 指标 | 目标 | 公式 | 采集 |
|---|---|---|---|
| 独立完成三档 | 首版只记录、不设硬目标；独立+半独立合计参考 ≥70%（待验证） | 独立=全程只用 L0 的题次；半独立=用过 L1–L2；依赖=用过 L3–L4 或出现粘贴标记；三个数分列，不合成单一百分比 | 每题落 independence_level（《契约》4.1 C1） |
| 平均提示轮数 | 2.5–4.5；>6 视为引导失效 | Σ各级提示次数 / 完成题次 | 埋点 |
| 中途放弃率 | ≤15% | 中途退出题次 / 开始题次 | 埋点 |
| 提示后推进率 | ≥65% | 提示后下一轮有有效推进的提示数 / 提示总数 | 埋点 + 诊断复判 |
| 引导合规率 | ≥98% | 合规轮次 / 抽检轮次 | Judge + 人工抽检 10% |
| 不泄题率 | 线上红线 0 | 1 − 泄题命中轮次 / 总轮次 | 正则 + Judge 双检 |
| 覆盖表完成率 | 待验证 | 覆盖 ≥80% 的终稿数 / 提交终稿数 | 埋点 |

> 指标口径的完整定义与教师端展示位置见 `05-教师端与数据闭环.md`；口径种子来自 v1.0 第 8 节与《_research/drafts/04-引导策略与Prompt模板.md》4.8.2（研究草稿，最终以产品埋点为准）。

### 7.3 不建议作为首版 KPI 的指标

- **AI 消息满意度/点赞率**：会诱导 AI 讲更多、更容易泄题。
- **单题完成时长越短越好**：与「想清楚」冲突，只做异常预警（>25 分钟或 >预估 1.5 倍）。
- **提示使用次数越少越好**：会让不敢求助的学生宁可放弃；只统计、不惩罚（v1.0 4.9.3）。
