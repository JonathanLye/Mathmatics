## 2. 产品核心结论（10 条，先看这些）

1. **产品卖的不是答案，是陪练**。数学分析的难点是「看懂答案却写不出证明」，通用 AI 一问就给完整证明，反而削弱学习。
2. **学生端 8 步**：登录入班 → 今日任务 → 选题 → 读题（核对定义）→ 自己拆题 → 分步写证明 → 终稿核对 + 五问复盘 → 规律/自检卡/变式题。
3. **六阶段状态机**：P1 知识激活 → P2 学生拆题 → P3 分步推进 → P4 终稿核对 → P5 五问复盘 → P6 迁移总结；主流程 ≤16 轮、≤25 分钟。
4. **AI 每轮三段式**：【判断】锚定学生原话 →【提示】按 L0–L4 给最小信息 →【提问】只一个问句。正文 ≤130 字（L4 ≤200 字）。
5. **提示阶梯与预算**：L1≤3 / L2≤3 / L3≤2 / L4≤1（合计 ≤9）；L0≤6；小白解释≤2；预算用尽走软着陆（标记薄弱点 → 定义卡 / 更简单同题），不给答案。
6. **四条红线**：不完整证明、不最终答案、不可抄推导链、不大段编号骨架；「我要完整证明」三段式拒绝 + 60 秒替代动作。
7. **教师端看过程不看分数**：完成率、未完成名单、平均提示轮数、卡点知识点 Top5、独立完成三档（独立=仅 L0 / 半独立=L1–L2 / 依赖=L3–L4 或粘贴）。
8. **与豆包爱学等的差异**：不是答得快，而是「不答完 + 逼你写 + 教师审核题库 + 过程数据可导出」；模型可换，题库与过程数据是资产。
9. **本轮做了两套 Demo**：05 单文件静态原型（离线演示流程）+ 06 全栈 Demo（Node 后端 22 API、JSON 落库、服务端提示预算与防泄题闸门、111 条 E2E）；AI 仍为 mock，不做小程序/拍照问答。
10. **最大的不确定性在罗老师那头**：教学场景、题库范围、提示边界、课堂组织、试点节奏都待确认，问题清单已备好，可直接转发。

## 3. 学生怎么用（一页流程）

~~~ text
[登录入班] 邀请码 + 学号，30 秒
     ↓
[今日任务] 本周必做 3 题 / 继续上次 / 复测提醒
     ↓
[选题] 章节 · 知识点 · 难度（必做 / 选练）
     ↓
[读题] 用自己的话说「要证什么」← AI 只核对定义，不讲课（P1，≤2 轮）
     ↓
[拆题] 要证几件事？关键词？← AI 只补漏（P2，≤2 轮）
     ↓
[分步写证明] 写一步 + 写依据 → 提交
     ↺ AI 只指第一个可疑步骤 → 追问依据
     ↺ 卡住才升提示：L1→L2→L3→L4（每级有次数，L4 只示范 1–2 行）
     ↺ 学生改写 → 再提交（P3，≤9 轮）
     ↓
[终稿核对] 5 个要点问句化核对，覆盖 ≥80%（P4，1 轮）
     ↓
[五问复盘] 学生自己答：证什么/分几段/胜负手/何时算证完/什么能带走（P5）
     ↓
[迁移总结] 3–5 条规律 + 自检卡 + 1 道变式题（P6，≤2 轮）
     ↓
[完成] 掌握度 + 复习建议；一个月后复测提醒
~~~

教师侧闭环：建班发邀请码 → 审核题库（审核后学生可见）→ 看班级看板 → 抽看学生过程 → 导出 CSV/Excel → 组织前测/后测。
