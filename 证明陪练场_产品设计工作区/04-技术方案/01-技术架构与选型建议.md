## 1. 三条路线对比与推荐

### 1.1 对比表

| 维度 | A. 本轮单文件 HTML 原型 | B. 快速 MVP（轻前端 + Node API + DeepSeek API） | C. 微信小程序原生 / uni-app |
|---|---|---|---|
| 定位 | 演示与对齐用，预置回复 | 11.7 技术验证 + 11.29 内测载体 | 长期的学生触达形态 |
| 11.7 能否达标 | ❌ 不能（无真实模型、无数据库、无服务端闸门） | ✅ 能（本稿推荐） | ❌ 不能（小程序主体资质 + 审核 + 单独前端，7 天不够） |
| 开发量（7 天口径） | 已完成，0 | 约 12–13 人天（2 人）；1 人降级版约 8 人天 | 4–6 周，且需要企业/学校主体资质 |
| 手机体验 | 浏览器打开，够演示 | H5 可用，微信内可开；PWA 可后续加 | 最好（原生交互、可推送） |
| 与原型资产关系 | — | **直接复用原型的 UI 结构/CSS/文案，只把预置回复换成接口** | 全部重写，原型资产作废 |
| 迭代速度 | 极快 | 快（无构建/几乎无构建，改完即部署） | 慢（每次提审 1–7 天） |
| 合规/审核 | 不涉及 | ICP/AIGC 标识（与形态无关） | + 小程序类目审核、教育资质、用户隐私协议单独配置 |
| 后续演进 | 到 11.1 即退役 | 可平滑升级到 B1（Next.js 全栈）或抽 API 给小程序用 | 可接同一套 API |
| 主要风险 | 演示与真实效果差距大（评审误判） | 1–2 人运维 + 备案周期；前端工程化程度低 | 7 天做不完；资质卡点 |

### 1.2 推荐：B2（轻前端 + Node API），并说明为什么不选 B1（Next.js）

**推荐 B2 的三条理由（落到这周）：**

1. **原型资产不浪费**：10.31 的原型（05-演示原型/）是单文件 HTML，UI、文案、交互已经过产品评审。B2 把它拆成 3–4 个静态页 + 调 API 即可；B1（Next.js 全栈）要重写成组件与路由，按《06 草稿》估算至少多 3–4 人天，7 天窗口承受不起。
2. **API 先行，给小程序留后路**：《契约》§9 写「后续升级：接 DeepSeek API → 微信小程序壳」。B2 天然是"前端薄、服务端厚"，小程序阶段只换前端壳，服务端零改动；B1 的 Server Actions/Route Handlers 与页面耦合，反而要多一步抽离。
3. **运维面最小**：静态文件 + 一个 Node 进程 + SQLite，2C4G 单机足够（50–100 人、峰值 QPS < 5，见《05 草稿》§3.2）。1 人团队最大的隐性成本是"自己不完全理解的复杂度"，B1 的 SSR/缓存/边缘函数在 50 人规模没有收益。

**B1（Next.js 15 全栈）什么时候再上**：当出现下列任一条件时，11.21 之后可迁移，不必现在做——
- 需要 PWA 离线缓存最近 20 题（《06 草稿》v1 范围里有，但可后置）；
- 前端页面 > 15 个或需要 SSR 首屏优化；
- 团队前端人力 ≥ 2 人。

> 与前期材料的冲突（需 Lead 记录，不阻塞）：
> - 《05 草稿》推荐 **FastAPI + PostgreSQL + MinIO**；本稿改为 **Node/TypeScript + SQLite→PostgreSQL**，原因是 7 天窗口内"一种语言（TS）前后端通吃 + 原型直接复用"更稳。FastAPI 方案留作 11.21 后若重写后端的备选。
> - 《02 体检》路线 B 推荐 **Supabase / PocketBase** 托管账号与数据库；本稿**不用**：验证期引入第三方 BaaS 会多一层权限与数据出境/合规说明，且 4 张核心表自建成本很低（约 0.5 人天）。11.21 若扩到多班级多教师再评估。
> - 《契约》D3 默认口径「先 H5 快速原型，再微信小程序」与 B2 一致，无冲突。

### 1.3 三条路线各自"现在就能用"的部分

| 路线 | 现在（10.31）能拿出来的东西 | 7 天内要补的东西 |
|---|---|---|

**产品经理需要知道的 4 个设计取舍：**

1. **所有模型调用只在服务端**：API Key 不进浏览器（微信内置浏览器容易被抓包）。前端只拿"一句话"结果。
2. **模型不决定预算，代码决定预算**：L1≤3/L2≤3/L3≤2/L4≤1、单题≤16 轮这些数字由服务端计数并拒绝越权请求，不交给模型"自觉"。
3. **参考证明与学生端物理隔离**：即使模型被套话，它也拿不到参考证明全文——学生会话的 Prompt 里只有"关键步骤要点（≤5 句）"，这是《学生端方案》§1.3 的硬约束。
4. **事件写入异步**：教师看板与导出依赖过程数据，但写日志不能拖慢学生等回复；失败进本地重试队列，不丢。

## 3. 关键链路时序：提交一步 → 诊断 → 闸门 → 返回一句

~~~mermaid
sequenceDiagram
  autonumber
  participant St as 学生
  participant FE as 前端（H5）
  participant API as Node API
  participant DB as 数据库
  participant LLM as 模型编排
  participant G as 提示闸门
  participant J as judge 复核

  St->>FE: 写一步 + 写依据，点提交
  FE->>FE: 本地草稿先落盘（防丢）
  FE->>API: POST /api/attempts/{id}/steps（Idempotency-Key）
  API->>DB: 读会话：阶段/轮次/各级预算/已给提示/题目关键步骤与常见错误
  API->>LLM: 诊断（结构化 JSON：verdict / first_error_step / error_type / 置信度 / 建议等级）
  LLM-->>API: JSON（schema 校验，失败重试 1 次）
  API->>API: 状态机与预算判定（是否升/降级、是否触发拒绝或小白解释）
  alt 需要信息型提示
    API->>LLM: 按等级生成提示（L0–L4 模板 + 学生原话）
    LLM-->>API: 三段式草稿
  end
  API->>G: 规则层校验（结构/字数/问号/禁用词/编号/锚定/连读/重合度）
  alt 规则层不通过
    G-->>API: 命中项
    API->>LLM: 同等级重写一次（附命中项，不许加信息）
    API->>G: 二次校验
  end
  opt 高风险：学生索要答案 / 贴答案 / 多轮套话 / 规则层二次未过
    API->>J: 合规复核（4 把尺子，输出 JSON）
    J-->>API: compliant / violations
  end
  API->>G: 终裁：只保留【判断】【提示】【提问】三段，超长截断，必要时换 L0 固定模板
  par 异步落库（不阻塞返回）
    API->>DB: 写 attempt_steps / hint_events / events_raw（含 gate_result、judge、tokens、cost、latency）
  end
  API-->>FE: 返回一句（三段式）+ 剩余预算 + 阶段进度
  FE-->>St: 渲染；草稿清除本步标记
~~~

**失败与降级链（必须实现，按顺序）：**

1. 主模型 15s 超时 / 5xx / 限流 → 同协议切备模型（11.21 前接入第二家）；
2. 备模型也不可用 → 用题库预写的该等级提示（hint_bank）直接返回；
3. 预写提示也没有 → 返回固定 L0 追问 + "服务繁忙，草稿已保存"；
4. 任何降级都写 hint_events.fallback_reason，计入成本与质量日报。

## 4. 数据模型：题目 / 关键步骤 / 常见错误 / 预写提示 / 参考证明隔离

### 4.1 表清单（验证期先建 9 张，内测期补齐 13 张）

| # | 表 | 装什么 | 谁可见 | 验证期是否必建 |
|---|---|---|---|---|
| 1 | users | 学生/教师；邀请码入班；学号**加密**存、对外只显示 8 位匿名账号码 | 服务端；教师可见账号码与班级 | ✅ |
| 2 | classes | 班级、邀请码、有效期、教师 | 教师 | ✅ |
| 3 | class_members | 谁在哪个班 | 教师 | ✅ |
| 4 | problems | 题干（LaTeX）、章节、知识点、难度、来源、状态（草稿/已审/已发布）、版本 | 学生只读已发布；**无答案字段** | ✅ |
| 5 | problem_steps | 关键步骤要点 ≤5 条（每步一句、不含推导），内部可见 | 服务端诊断/教师复核；**不直接展示** | ✅ |
| 6 | common_errors | 每题 3 条常见错误 + 错误类型（量词/放缩/收敛判别/构造等） | 服务端诊断；教师 | ✅ |
| 7 | hint_bank | 预写提示：L1–L4 各 1 条 + L0 追问模板 + 小白解释三件套（类比/最小例子/严格表述） | 服务端（降级兜底 + 质量基线） | ✅ |
| 8 | reference_proofs | **参考证明全文 / 最终答案 / 关键构造配方**，隔离存放 | 仅评测与教师复核任务；**API 不可达** | ✅ |
| 9 | attempts | 一次作答：阶段、轮次、各级提示计数、拒绝次数、小白解释次数、粘贴标记、用时、结束原因、prompt 版本、模型 | 本人/本班教师 | ✅ |
| 10 | attempt_steps | 学生每一步原文 + 依据 + 诊断 JSON + 首错标记 + 是否独立改写（步骤级）；独立性档位在完成时判定 | 本人/教师 | ✅ |
| 11 | hint_events | 每次提示：等级、触发原因、内容、闸门结果、judge 结果、token、成本、时延 | 教师聚合；管理员 | ✅ |
| 12 | prompt_versions | Prompt 模板 + 模型 ID + 参数 + hash + 生效/冻结标记 | 管理员 | 内测期 |
| 13 | events_raw | 技术事件原始日志（request_id、设备、耗时、错误） | 管理员；90 天 | 内测期 |

> 与《05 草稿》§5.1 的差异：草稿把 answer_latex / solution_latex 放在 problems 表里。本稿**拆到 reference_proofs**，理由见 4.3。

### 4.2 关键字段（产品经理视角）

**题目（problems）**：题干、章节、知识点 1–3 个、难度 1–5、来源（真题/教材/自编）、状态、版本号。**不含答案**。

**关键步骤要点（problem_steps）**：最多 5 条，每条一句话、只讲"要做什么"不讲"怎么做"。例（演示题）："说明 u_n 单调递减"、"说明 u_n→0"、"引用莱布尼茨判别法"、"说明 ∑1/√n 发散"、"结论写明条件收敛"。
> 白话：莱布尼茨判别法是判断"正负交替的数列求和"是否收敛的一条现成定理；条件收敛指"原级数收敛，但把每项取绝对值后不再收敛"。

**常见错误（common_errors）**：每题 3 条，每条带"错误类型 + 学生可能写的原文样例 + 诊断锚点"。例："只说分母变大，没写 n 与 n+1 的不等式"。

**预写提示（hint_bank）**：L1 点名定理（不给用法）、L2 给方向（不给表达式）、L3 给一步操作、L4 示范 1–2 行 + 交接句；另存 L0 追问模板与小白解释三件套。作用有二：① 模型挂了能兜底；② 作为闸门的"重合度基线"（AI 回复与预写提示高度相似 = 可能复读或泄题，需换问法）。

**作答会话（attempts）**：阶段 P1–P6、轮次、L1–L4 各级已用次数、L0 次数、拒绝次数、小白解释次数、粘贴标记、用时、独立性档位（三档，完成时判定；教师端分列，不合成单一「独立完成率」）、用的 Prompt 版本与模型。

**学生步骤（attempt_steps）**：步骤文本 + 依据 + 诊断 JSON（verdict / 首错 step / 错误类型 / 置信度）+ 是否独立改写（步骤级）；整题独立性档位（独立/半独立/依赖）记在 attempts，完成时判定。

### 4.3 参考证明隔离（本轮最重要的技术红线）

| 层 | 做法 | 验收方式 |
|---|---|---|
| 存储 | reference_proofs 放独立 schema（SQLite 验证期放独立文件并单独加密），应用主账号**无 SELECT 权限**；只有 evaluation 只读账号能读 | 用应用账号执行 SELECT * FROM reference_proofs 必须报权限错误 |
| 接口 | 题目详情接口用**字段白名单**（DTO），禁止 SELECT *；学生端接口永远不返回 answer/solution 字段 | 契约测试：请求 /api/problems/{id} 断言响应 JSON 不含 answer/solution/proof 字段 |
| Prompt | 学生会话只注入 problem_steps（≤5 句）+ common_errors（≤3 条），**不注入**参考证明；代码层用白名单构造上下文，不靠"记得别放" | 单元测试：构造 prompt 的函数输入参数里没有 reference 字段 |
| 前端 | 不把题库 JSON 打包进前端（《02 体检》里 logiclearner 就是这么被扒题的，反面教材） | 前端产物搜不到题干全文 |
| 审计 | 任何读参考证明的代码路径写 audit_log（谁、何时、哪题、用途） | 评测任务跑完可查记录 |

**冲突提示（需 Lead 记录）**：《05 草稿》把参考证明放在 problems.solution_latex，且 API 列表里题目详情接口未明确字段白名单。按《契约》§6「学生端永不注入参考证明全文」，本稿要求拆表 + 白名单 + 契约测试。若开发沿用草稿表结构，必须在 11.7 前补上白名单与测试，否则是直接泄题风险。

### 4.4 事件字段（与《契约》§8 对齐）

每题每轮落 **14 项**：题号、章节、轮次、阶段、提示等级、提示原文、诊断结论、学生输入、要点覆盖、预算消耗、拒绝次数、小白解释次数、粘贴标记、用时（有效用时，扣除 idle >3 分钟）；**独立性档位「independence_level」在完成时判定**：独立 = 全程只用 L0；半独立 = 使用过 L1–L2；依赖 = 使用过 L3–L4 或出现粘贴标记（规则见《契约》§4.1 C1）。教师端**三档分列统计，不合成单一「独立完成率」**。另加技术字段（request_id、模型、Prompt 版本、tokens、成本、时延、闸门命中项、judge 结果、降级原因）。缺一不可导出 → 教师端指标算不出来。

## 5. 模型路由与成本估算

### 5.1 路由规则（产品经理版）

| 场景 | 用哪个模型 | 为什么 |
|---|---|---|
| 默认每轮诊断 + 提示 | deepseek-flash | 便宜、够用；Math 能力未实测，按《01 调研》§7 标注"待验证" |
| 学生连续 2 轮无进展 / 同一错误点连续 3 次 / 首错置信度 <60% / 难点（ε-δ、一致收敛、级数判别） | deepseek-v4-pro（或 kimi-k3） | 难判断时换强模型，单轮贵约 5–7 倍，但占比低 |
| 闸门复核 judge | 便宜异构模型（GLM-5.3-Flash / qwen3.8-flash） | 只做合规判定，不需强推理；异构降低同源错误 |
| 模型失败 | 备供应商（11.21 前接入） | 避免单点；《06 草稿》R05/R11 |

> 白话：ε-δ 是数学分析里定义"极限"的严格说法（"你给多小的误差，我都能找到足够近的范围"）；一致收敛是"整段区间能共用一把尺子"的收敛。它们是学生最容易卡住的地方，所以路由到更强的模型。

### 5.2 成本估算（引用《01 调研》§5，不重复推导）

| 口径 | 数字 | 来源/说明 |
|---|---|---|
| 50 人试点（每人每周 5 题、每题 8 轮） | 低成本档 **¥60–100/月**（≈¥1.5/生/月，≈¥0.07/题） | 《01 调研》§5.3 |
| 混合路由（30% 高难升 v4-pro + 复核） | **¥110–180/月**（≈¥0.12/题） | 《01 调研》§5.5 |
| 高可靠档（全 v4-pro + 2 次复核） | ¥380–550/月（≈¥9/生/月） | 《01 调研》§5.4；本轮不采用 |
| 11.1–11.7 验证期（10 题 × 10 轮 + 16 条红队 + 回归，约 300–600 次调用） | **约 5–20 元** | 按 flash 混合价 1.15 元/M 输入、4.6 元/M 输出，单次约 0.008 元；留调试余量 |
| 预算保护 | 单生单日 ≤30 次请求、单题 ≤16 轮、全站日预算告警（验证期 50 元/日，试点 20 元/日） | 超 80% 告警，超 100% 切轻模型/停非核心功能 |

**降本三个杠杆（按性价比排序）**：① 历史压缩（只回传"原题 + 当前步骤 + 已给提示摘要"，4k 压到 2.5k，省约 35%）；② 稳定 system prompt + 会话前缀命中缓存（省约 11–18%）；③ 简单轮次走 flash、只对卡点升 pro。

**成本观测**：每次调用写 hint_events（tokens_in/out、cost_cents、model_id），每日 08:00 汇总日报；单题成本 >0.2 元或日成本 >预算 1.5 倍告警。

### 6.2 草稿本地保存（防"写了半小时一刷新没了"）

| 项 | 方案 |
|---|---|
| 存储 | localStorage，key = draft:{attemptId}:{stepSeq}；不需要 IndexedDB（单条 <10KB） |
| 字段 | 步骤文本、依据文本、更新时间、服务端版本号、当前阶段 |
| 保存时机 | 输入停顿 800ms 防抖保存；提交前立即保存；页面隐藏（visibilitychange）再存一次 |

## 7. 防泄题：规则层 + 复核层落地

### 7.1 三层结构（与《学生端方案》§1.3 四把尺子、《04 草稿》§4.6.7 对齐）

| 层 | 位置 | 做什么 | 何时跑 | 失败怎么办 |
|---|---|---|---|---|
| 规则层（确定性，0 延迟） | Node API 内，模型返回后 | 结构/字数/问号/禁用词/编号表格/锚定/连读/重合度/危险 LaTeX | **每条输出都跑** | 同等级重写一次 → 仍不过则 L0 固定模板 + 记 gate_fail |
| 复核层（judge 模型） | 模型编排 | 用第二模型按"四把尺子"判 compliant，输出 JSON | **只在高风险时跑**：学生索要答案、贴答案、多轮套话、规则层二次未过、L3/L4 | violations 非空 → 重写/降级/转人工 |
| 人工抽检 | 教师端后台 | 每天抽 10% 会话，重点看"最近 3 轮提示能否拼成证明" | 每日 | 违规入库 → 改 Prompt/提示库 → 30 题回归 |

**成本控制**：judge 只在约 20–30% 轮次触发，按《01 调研》低价模型约 +10–15% 成本；换来的是"0 泄题"这条硬门槛，值得。

### 7.2 规则层具体规则（开发可直接实现）

见 03-质量、防泄题与合规清单.md 第 3 节完整表（12 条规则、阈值与处理）。这里只强调三条产品经理必须知道的：

1. **"连读检测"**：把最近 3 轮 AI 提示拼起来，若编号/连接词/句子数/与参考证明重合度达到阈值 → 判"可连成证明"，强制降级为一句 L0 追问。这是防"多轮套话"的关键，单轮看每条都合规，拼起来才泄题。
2. **"锚定"**：回复必须引用学生原话 ≥3 个连续字，否则重写。防"套模板、不读学生写了什么"。
3. **"兜底模板"**：规则层两次不过，就换成预置的 L0 追问（如"你这一步的依据是哪条定义？写在我这句话下面。"），保证返回永远合规。

### 7.3 与教师端的关系

- 教师看板不显示"判对错"，只显示过程：卡点知识点、平均提示轮数（带口径解释）、独立性三档分布（独立/半独立/依赖，分列，不合成单一百分比）、拒绝/粘贴标记。
- 教师抽检可标记"这条回复有问题"，进入模型问题库（《学生端方案》§8.3）。

## 8. Prompt 与模型快照版本冻结

| 项 | 做法 |
|---|---|
| Prompt 管理 | prompt_versions 表存：名称、用途（主导师/诊断/提示/judge/拒绝/小白解释）、模板全文、hash、模型 ID、采样参数、是否生效、冻结标记 |
| 每次对话可回溯 | attempts.prompt_version_id + attempts.model_id，同一会话内固定，不在中途换版本 |
| 冻结时点 | **11.21 18:00 功能冻结**：Prompt 与模型组合打 tag（如 tutor-v1.0 / diagnose-v1.0 / judge-v1.0 + deepseek-flash-2026-10），冻结后改动需：Lead 审批 → 30 题回归 → 版本号 +1 → 记录 |
| 模型快照 | 记录供应商名称、模型 ID、调用日期、参数（temperature/max_tokens/top_p）；《01 调研》明确价格与模型能力可能随时调整，每周一复查一次，若供应商改版则以 30 题回归结果为准 |
| 留档抽检 | 每日随机抽 20 条 AI 回复存 30 天（脱敏），用于冻结后对比与故障复盘 |
| 变更记录 | 每次改动写《决策记录》：为什么改、改前改后指标、谁批准 |

> 白话：Prompt 就是"给 AI 的岗位说明书"。冻结的意思是：内测前把这版说明书和用哪个 AI 型号写死，之后谁想改都要走审批和回归测试，避免"昨天还好好的今天全变样"。

## 9. 部署：大陆 / 香港、备案、AIGC 标识

### 9.1 两种部署对比

| 维度 | 香港服务器（11.7 验证期过渡） | 大陆服务器（11.29 内测前目标） |
|---|---|---|
| 备案 | 不需要 ICP | **需要 ICP 备案**（域名 + 服务器），周期约 2–4 周；上线后 30 日内公安联网备案 |
| 访问速度 | 境内可访问，延迟略高（通常 +30–80ms），验证期够用 | 更快更稳 |
| 数据合规 | 学生个人信息存香港可能构成"数据出境"，需单独告知/同意，或只放测试数据 | 数据留在境内，最稳 |
| 成本 | 2C4G 轻量约 30–60 元/月 | 2C4G 约 100–200 元/月 + 域名 60 元/年 |
| 适用 | 仅 11.1–11.7 技术验证，**只用虚构学生数据** | 11.21 前完成迁移，11.29 内测用真实学生 |

**推荐**：11.1 双线并行——香港机器当天可用；同时 11.1 提交 ICP 备案材料。若 11.18 前备案未下，11.29 内测继续用香港但**只收邀请制校内学生并单独告知**，同时法务确认（这是需要甲方拍板的点）。

### 9.2 合规清单（技术侧要落地的）

| 事项 | 落地动作 | 截止 |
|---|---|---|
| ICP 备案 | 域名实名 → 服务器商提交 → 管局审核；同步准备学校/公司主体材料 | 11.1 提交，11.18 前拿到 |
| 公安联网备案 | 上线后 30 日内 | 11.29 起算 |
| 生成式 AI 备案/登记 | 依据《生成式人工智能服务管理暂行办法》，面向境内公众提供生成式 AI 服务需履行备案/安全评估；**校内邀请制试点是否属于豁免范围待验证**，需咨询学校信息化/法务。注意：调用已备案的大模型 API **不当然豁免应用方义务** | 11.7 前问清，11.21 前定 |
| AIGC 标识 | 依据《人工智能生成合成内容标识办法》（2025-09-01 施行）：① 显式标识——每条 AI 回复下方固定"AI 生成 · 仅作学习提示"，页面顶部说明；② 隐式标识——API 响应头/导出文件元数据标注 | 11.21 前上线 |
| 数据出境 | 模型 API 用境内节点；学生数据 11.29 前留境内；香港验证期只用虚构数据 | 11.7 前 |
| 第三方数据告知 | 隐私政策写明"作答文本会发送至第三方大模型 API 用于生成引导"并取得同意 | 11.21 前 |
| 备份与恢复 | 每日 pg_dump + 对象存储，保留 30 天；11.29 前完成 1 次恢复演练 | 11.28 |
| 安全 | Caddy 强制 HTTPS/HSTS、安全响应头、请求体 ≤64KB、登录限流、API Key 只在 .env、90 天轮换、日志脱敏 | 11.7 前 |

> 外部依据：https://wxb.xzdw.gov.cn/wlcb/cbgz/202509/t20250902_601378.html （《人工智能生成合成内容标识办法》相关报道页，原文以国家网信办发布为准）；http://zc.gjzwfw.gov.cn/art/2023/7/28/art_14_65636.html （《生成式人工智能服务管理暂行办法》）。具体适用口径**待验证**（见 11.3）。

### 9.3 部署形态

- 单机 Docker Compose：caddy + web（静态）+ api（Node）+ db（SQLite 卷，内测期换 PostgreSQL 容器）；
- 一条命令起停，备份 = 备份数据卷 + 每日 dump；新机器 2 小时内可重建（《05 草稿》§8 手册可复用）；
- 监控：/api/health 5 分钟探活 + 邮件/微信告警；成本日报；错误日志表。

### 11.3 待验证清单（不写死结论）

1. DeepSeek flash 在数分证明题上的诊断准确率与幻觉率（无公开基准，需 30 题实测）。
2. 生成式 AI 备案对"校内邀请制、非公开、非收费"试点的适用口径。
3. 学校/学院能否作为备案主体、能否提供服务器与域名。
4. 微信内置浏览器对 SSE 流式与 localStorage 的兼容表现（真机实测）。
5. 连读检测阈值（句数/连接词/重合度）在真实对话上的误拦率（目标 ≤5%）。
6. 单题真实平均轮数与 token 量（《01 调研》按 8 轮假设，实际可能 10–12 轮）。
