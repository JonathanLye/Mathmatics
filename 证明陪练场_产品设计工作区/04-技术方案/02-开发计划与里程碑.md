## 0. 一页结论

| 问题 | 结论 |
|---|---|
| 7 天能做到什么 | 1 题端到端 + 10 题题库 + 服务端提示闸门 + 事件落库 + 16 条红队 0 泄题 + 3 台手机走通 + 教师端只读一屏。**这是技术验证，不是可上线产品。** |
| 需要多少人 | **2 名开发**（1 全栈/后端+AI，1 前端，AI 辅助编码）+ 教研 22h（罗老师为主）+ 产品/测试 21h（甲方产品负责人兼）。合计约 10.4 开发人天 + 43h 非开发。 |
| 只有 1 名开发怎么办 | 启动**降级版**：砍教师端只读屏、题库 10→7 题、红队 16→12 条、不做 judge 复核层（只留规则层）。门槛从"6 项全过"降为"G1/G2/G3/G4 过，G5/G6 出报告"。 |
| 日历假设 | 2026.11.1 是周日、11.7 是周六；假设 11.1 与 11.7 各投入半天（启动会/验收会），11.2–11.6 为 5 个完整工作日 → 每人等效 6 个工作日。**若周末不能加班，7 天计划不成立，需顺延到 11.10。** |
| 计划利用率 | 开发 83h / 可用 96h ≈ 86%，**没有缓冲**。D4（11.4）晚检查：闸门规则层 <80% 完成即启动降级预案。 |
| 11.7 结论怎么用 | Go：按 11.8–11.21 计划推进；Conditional Go：只修红线问题、砍范围；No-Go：暂停开发、先把题库/合规补齐（题库是关键路径，不是代码）。 |
| 最大风险 | ① 题库教研录入延迟（关键路径，等老师）；② 红队不通过（泄题=教学事故）；③ 备案周期赶不上 11.29；④ 单人瓶颈。应对见第 7 节。 |

### 1.1 做（六项门槛的支撑项）

| 能力 | 做到什么程度 | 对应门槛 |
|---|---|---|
| 邀请码登录 | 邀请码 + 学号，30 秒内进班；虚构测试数据 | G4 |

| 真实 AI | DeepSeek flash 真实调用；结构化诊断 JSON；失败降级 | G1/G2 |
| 提示预算 | 服务端计数（L1≤3/L2≤3/L3≤2/L4≤1、L0≤6、轮次≤16） | G1 |
| 提示闸门 | 规则层全量 + 重写一次 + L0 兜底；高风险走 judge | G3 |
| 拒绝与小白解释 | 「我要答案」三段式拒绝 + 替代动作；小白解释 ≤2 次 | G2/G3 |
| 事件落库 | 《契约》§8 字段齐全，可导出 CSV | G6 |
| 教师端 | **只读一屏**：完成率、平均提示轮数、卡点知识点 Top5 | G6 |
| 部署 | 香港服务器 + HTTPS + 虚构数据；监控与成本日报 | G1 |
| 测试 | 10 题端到端脚本 + 16 条红队用例 + 3 台真机 | G1–G4 |

### 1.2 不做（11.7 前明确砍掉，写进需求池）

- ❌ 教师布置作业、完整班级管理、学生详情抽屉（→ 11.14）
- ❌ CSV 之外的数据导出、复测模块、掌握度雷达（→ 11.21）
- ❌ 拍照识题 / OCR（《契约》D4 本轮不做）
- ❌ MathLive 公式键盘（先用"文字 + 简单 LaTeX 片段"，降低手机输入风险）
- ❌ PWA 离线、微信小程序打包、多班级多教师
- ❌ 第二家模型供应商接入（→ 11.14 前必须接，作为 11.7 后的第一优先）
- ❌ 生成式 AI 备案、完整隐私政策（→ 11.21 前，但 ICP 材料 11.1 就要提交）
