# 02 · 全新融合方案（v3）

> 融合来源：《关键条件》（红线）+《第一版》六层 +《第二版》拆解框架 +《技术方案 v2.0》+《需求确认书》
> 证据来源见 [04-关键文献与证据分级](04-关键文献与证据分级.md)；矛盾 1–3 的展开论证见 [03-三大矛盾专题](03-三大矛盾专题.md)。

## 0. 一页纸

- **定位**：面向数学分析（大一、大二）的**证明写作陪练**，同时是一个**可复现的教学实验平台**。它不是答疑机，也不是讲题机。
- **红线的可执行定义**：系统发给学生的任何字符串，都不得包含学生尚未写出的关键步骤中**可以直接照写的内容**。"关键步骤"由教师在题目包中逐条登记，不由模型临场判断。
- **六层保留为骨架**：每层的主语换成学生；每层有完成判据和跳过规则，不再每题强制走完六层。
- **模型只做三件事**：①把学生写的一步**归类**到题目包里的关键步骤或错误类型；②从教师预写的提示里**选一条**，并只改人称和指代；③**复核**每一条外发文本。模型不判对错，不在线生成数学内容。
- **提示预算按"透露量"计**：定义类、框架类提示不限次数；涉及关键步骤的提示每题至多透露 2 个关键步骤，而且必须在学生又尝试一次之后才能升级。
- **实验采用同平台主动对照 + 交叉设计**：两组用同一个界面、同一批题、相同时长，唯一区别是"分步引导"还是"提交后看参考证明"。

## 1. 用第二版的框架审视本产品

| 第二版问题 | 本产品的回答 |
|---|---|
| 解决什么问题（一句话） | 学生"看得懂答案却写不出证明"，而通用 AI 一问就给完整证明，进一步削弱写证明的能力 |
| 服务谁、目标是什么 | 主要服务：正在学数分、第一次写 ε-N/ε-δ 证明的大一和大二学生（新手）。次要服务：考研复习的学生（高先备，按跳过规则少走流程）。目标：独立写出结构完整、每步有依据的证明 |
| 采用什么结构 | 六层骨架 × 题目包 × 状态机（§3–§5） |
| 拉开质量差距的关键选择 | ① 关键步骤由教师登记，模型只做归类；② 预算按透露量计；③ 区分"形式框架"和"解题核心"两类提示；④ 大白话必须带失真说明；⑤ 测试窗口完全关闭辅助 |
| 完成标准 | 学生端：一题从读题到写完、自检完成，系统发出的文本里关键步骤透露数 ≤2，且每次透露都有记录。研究端：事件字段齐全率 ≥98%，红队回归泄题 0 条（只针对教师预写内容；在线生成内容不做此承诺，见 §4.3） |
| 可迁移 / 只适用本例 | 可迁移：题目包结构、提示分级、证明框架训练、失真说明规则。只适用本例：具体题目的关键步骤、常见错误、大白话卡片 |

## 2. 用户与场景

| 画像 | 先备知识 | 主要卡点 | 系统行为 |
|---|---|---|---|
| 新手（主体） | 刚学定义，不会把定义展开成量词结构 | 不知道从哪写起；把极限当成"无限接近"的动态过程 | 第 1、2 层展开；证明框架提示不限次 |
| 过渡者 | 能写框架，卡在构造（找 N、放缩、选判别法） | 解题核心部分 | 第 1 层通过前测即跳过；第 3 层提示阶梯起主要作用 |
| 高先备（考研） | 熟练 | 严谨性细节、边界情况 | 直接进第 3 层；只给 H0 追问；第 5 层迁移题为主 |

使用场景：晚上在手机或平板上做作业，单次 15–30 分钟，网络可能不稳定（技术方案已要求 IndexedDB 草稿）。

## 3. 六层骨架（主语换成学生）

每层统一按同样的字段描述：学生做什么、系统可做什么、系统禁止做什么、完成判据、跳过规则。

### 第 1 层　前置知识点 → 定义核验

- **学生**：用量词形式写出本题涉及的定义，例如 `lim a_n = A ⇔ ∀ε>0 ∃N ∀n>N |a_n−A|<ε`。
- **系统可做**：与教师定义卡逐个量词比对（这一步可以由规则判定），只指出"哪一个量词或顺序不对"；学生点击"看不懂"时提供大白话卡片（规则见 03 文档）。
- **系统禁止**：提及本题会用到哪个定理或方法。初版 `ai.mjs:102` 的做法恰好违反这一条。
- **完成判据**：定义的量词结构正确。
- **跳过规则**：本章定义前测已通过，或本学期同一定义已核验过 2 次。

### 第 2 层　题目解析 → 证明框架

- **学生**：写出证明的形式框架，即"设 ε>0 任意……（待构造 N）……对 n>N 有……故 |a_n−A|<ε"。框架之外再写一句"真正要解决的是什么"，例如"找到 N 与 ε 的关系"。
- **系统可做**：框架属于形式部分（Selden & Selden 的 formal-rhetorical part），只取决于命题的逻辑结构和定义，**不属于关键步骤**，可以给出强反馈，甚至用通用模板示范，例如"要证 ∀x P(x)，先写'任取 x'"。
- **系统禁止**：给出框架中间需要构造的内容，比如 N 的具体表达式、该选哪个判别法。
- **完成判据**：框架的首尾结构正确，并指出了待构造的对象。
- **跳过规则**：同类命题形式已经连续 2 题通过。

### 第 3 层　详细步骤 → 构造与推导（核心）

- **学生**：逐步写"这一步 + 依据"，顺序不限，可以先写草稿再整理。
- **系统可做**：把学生的一步归类到题目包里的关键步骤图（允许多条路线）或常见错误；只用**提问**指出第一处可疑；学生卡住时按提示阶梯 H0–H4 给出教师预写的提示（§4）。
- **系统禁止**：任务说明、通过反馈、"下一步"预告中出现任何关键步骤的内容（对应初版 A1/A2）；也不能说"这一步对了"，只能说"这一步与已知结论衔接上了"或"这里的依据我没看到"。
- **完成判据**：学生声明"写完"，并且所有必要的关键步骤都已在学生自己的文本中出现（归类器置信度 ≥ 阈值）。低于阈值的步骤交给教师抽检，不据此阻断学生。
- **"连续卡住"判定**：两次提交都没有新的关键步骤被匹配，并且停留超过 3 分钟。

### 第 4 层　完整讲解 → 学生自述与自检

- **学生**：针对**自己写的证明**回答 3 个局部问题，问题从 Mejia-Ramos 等（2012）的局部维度中抽取：
  1. 第 k 行是由哪几行、用什么推出的？（依据）
  2. 证明里这个量 X 起什么作用？（词项和陈述的含义）
  3. 你的证明在哪里用到了题设条件 C？如果去掉 C，哪一行会断？（逻辑地位）
- **系统可做**：检查回答是否指向学生自己证明里确实存在的行，可以规则化。
- **系统禁止**：提供"标准讲解"。页面不出现任何讲解文本。
- **依据与边界**：自我解释训练能提升证明**理解**，d=0.95（实验室）和 d=0.41（课堂），见 Hodds 等 2014；但那是**读证明**的研究。Barbieri 等（2023）发现，在例题学习中叠加自我解释提示反而起负向调节作用。所以本层**只问 3 题、可选，由教师按班配置**，并把它的效果列为待检验假设，不作为既定结论。

### 第 5 层　同类题 → 迁移题

- **学生**：独立完成一道教师预写的近迁移题，即同一证明思路换一个对象，例如把 ε-N 换成 ε-δ。
- **系统可做**：只出题面，走完整的第 3 层流程，但提示预算减半。
- **完成判据**：结构完整。完成情况记为迁移指标，对应 Mejia-Ramos 的"迁移"维度。
- **跳过规则**：教师未配置迁移题，或学生在本题已用满预算（此时改为推荐下一次练习）。

### 第 6 层　总结 → 第二版框架自写

学生用第二版的五问自写总结，每问一句话：

| 第二版问题 | 改写给学生 | 对应证明理解维度 |
|---|---|---|
| 解决了什么问题 | 这个证明证了什么？用一句话说 | 用高层思想概括 |
| 结构或流程 | 你的证明分几块？块与块是什么关系？ | 识别模块结构 |
| 关键选择 | 哪一个选择决定了成败（例如 N 怎么取）？ | 用高层思想概括 |
| 完成标准 | 写到哪一步才算证完？ | 逻辑地位 |
| 可迁移 / 只适用本例 | 哪个做法下次还能用？哪个只适用于本题？ | 迁移 |

- **系统可做**：与教师的"要点卡"比对，只对**缺失**的要点追问一句，例如"你的总结没提到 N 和 ε 的依赖关系，它重要吗？"，不补写答案。
- **产出**：学生自己的总结卡，进入复习。

### 第 7 步（课后，非 AI）教师讲评

题目关闭后（截止或全班提交），**由教师决定**是否发布参考证明和基于学生作品的讲评。

依据：在有效失败研究里，与"先尝试后教学"效应相关的忠实度指标之一，正是"教学建立在学生解法之上"（Sinha & Kapur 2021）；而纯粹没有指导的发现式学习证据很弱（Kirschner 等 2006）。

**这不违反红线**：红线约束的是"AI 在学生解题过程中给答案"。题目关闭后由教师发布讲评，属于教学安排。是否采用由罗老师决定（D-07）。

## 4. 提示阶梯与预算

### 4.1 五级提示（全部由教师预写，存于题目包）

| 级 | 名称 | 内容类型 | 是否透露关键步骤 | 例：ε-N 证明 lim (3n+1)/(n+2)=3 |
|---|---|---|---|---|
| H0 | 追问 | 通用元认知问题 | 否 | "你要让哪个量小于 ε？先把它写成最简的样子。" |
| H1 | 定义 / 框架 | 定义原文 + 证明框架 | 否（属于形式部分） | "回到目标：\|a_n − 3\| < ε。先单独处理 \|a_n − 3\|。" |
| H2 | 方向 | 指出一类方法，不给对象 | **0.5** | "通分以后，\|a_n − 3\| 会变成一个只含 n 的分式。" |
| H3 | 局部一步 | 给出某个关键步骤的一半 | **1** | "分子是 3n+1 − 3(n+2)。把它算出来，再看分母。" |
| H4 | 示范一行 | 一个关键步骤的完整一行，必须交还学生 | **1** | "\|a_n − 3\| = 5/(n+2)。下一行由你写：要让它 < ε，n 需要满足什么？" |

> 以上是关键步骤 K1（化简）的一组提示，与 08 原型一致。

> 需求书里的"L1 点名定理"在这里被拆开：点名**定义**属于 H1，不计透露量；点名**决定性定理**（如莱布尼茨判别法用于条件收敛题）属于 H2，计透露量，因为它是解题核心。由教师在题目包里为每条提示标注透露量。

### 4.2 预算规则

1. H0 和 H1 不限次数，但全部记录，对应需求书 D5-04"不限但记录"。
2. 每题累计透露量 ≤2，与技术方案"透露关键步骤 ≤2 个"一致。**计法**：每个关键步骤按它已到达的最高一级计（0、0.5 或 1），全题求和。所以 H3、H4 落在同一个关键步骤上只算 1 个，H4 总能走到。达到上限后不再升级，改为"回到第 1 层核验定义"或"标记为求助教师"。
   H4 示范过的那一行，学生必须在"依据"里用自己的话写出它为什么成立，才算学生自己写出的步骤（Shih 等 2010）。
3. **先尝试后升级**：从 H2 起，每升一级都要求学生自上次提示之后又提交过一次。服务端只读取可信状态来判断，不读学生的输入文字，避免被话术绕过（Pisan 2026 P2 原则）。
4. **最小停留时间**：同一级提示展示后 20 秒内不能再申请，用于抑制"连点到底"式的滥用（Aleven 等 2016；Baker 关于钻系统空子的研究）。
5. 学生要求完整证明时：一句拒绝，加上当前可做的 H0/H1，不说教。

### 4.3 生成与复核

- **默认路径（实验期）**：模型只输出 `{step_match, error_type, hint_id, confidence}` 这样的结构化 JSON，发给学生的文字 100% 来自题目包的预写文本。在这个前提下，"泄题 0 条"是可以检验的命题。
- **扩展路径（非实验期，可选）**：允许模型把预写提示改写成贴合学生原话的版本，但改写结果必须经过规则层和异厂商复核层，失败时回退到原文。这条路径不承诺"0 泄题"，只报告实测泄题率。
- **闸门作用于每一条外发字符串**，包括任务说明、反馈、核对问句、拒绝文本，以修复初版 A5。
- 低置信度归类（< 0.7）时，不说"这里可疑"，只给 H0 追问，并标记给教师抽检。依据：LLM 首错定位在大学证明上不可靠（Srivatsa 2025；QEDBench 2026）。

## 6. 系统架构（在技术方案 §4.1 基础上修改）

```text
学生端 PWA (Next.js + MathLive + KaTeX)
   │  只接收"通过闸门的字符串"
   ▼
API ── 策略核心（确定性状态机：层、预算、门槛；只读可信状态）
   │      │
   │      ├── 归类器（LLM，结构化 JSON，不产生学生可见文本）
   │      ├── 选择器（规则：状态 + 归类 → hint_id）
   │      └── 闸门（规则层 + 异厂商复核，作用于所有外发文本，fail-closed）
   ▼
PostgreSQL：题目包（版本化）· events（只追加）· attempts · steps
```

与初版 06 的差别：初版是"关键词匹配 + 模板字符串拼接"，没有归类器，闸门只覆盖部分路径。

## 7. 实验设计（修正技术方案 §5）

### 7.1 研究问题

主问题：在**同一平台、同一题目、同等练习时间**下，"分步引导（提示阶梯 + 首处可疑提问）"是否比"提交后看参考证明"更能提高**独立写证明**的能力？

这比"有系统 vs 纸笔"更窄，但可以归因。

### 7.2 设计

| 要素 | 方案 |
|---|---|
| 条件 A（引导） | 完整的六层 + 提示阶梯 |
| 条件 B（主动对照） | 同一界面，可写可存；提交后显示教师参考证明（等同于纸笔加看答案，但在平台上进行，事件可记录） |
| 分配 | 交叉设计：把 4 周拆成两个知识块（如数列极限、函数极限与连续），块内题目平行。**在每个班内按学生个体随机分配 AB 或 BA 顺序**，按班分层。两组用同一个平台，所以可以做到个体随机，这正是主动对照的主要好处。如果按班分配顺序，又会退回审计 A9 所说的"2 个群"问题 |
| 污染 | 同班学生会交流，B 组可能借到 A 组的提示。应对：每周问卷询问"是否看过同学的提示或证明"，事件里记录可疑的复制粘贴（长文本一次性粘贴），作为协变量和敏感性分析 |
| 携带效应 | 先用 A 的学生在第二块里可能保留"先写骨架"等习惯。作为局限写明，并用块 1 的数据单独做组间比较作为稳健性检验（与技术方案 §5.3 一致） |
| 测量 | ① 证明构造测验（教师按细则评分，20% 双评，报 ICC）；② 证明理解测验（按 Mejia-Ramos 七维出题）；③ 延迟后测 |
| 过程指标 | 透露量加权独立度、提示请求时机、首次尝试前停留时长、关键步骤自主覆盖率 |
| 协变量 | 前测、外部 AI 使用自报（每周一题）、练习时长 |
| 预注册 | 实验开始前在 OSF 存档分析计划（与技术方案 §5.5 一致） |
| 伦理 | 依《科技伦理审查办法（试行）》第二条（一），"以人为测试、调查、观察等研究活动的对象"需送本校伦理委员会审查；知情同意；数据匿名 |

### 7.3 统计功效

沿用技术方案 §5.4 的复算：交叉设计（ρ=0.5）30 人约等效于组间 60/60，最小可检测效应 d≈0.51。仍偏大，所以论文主结论应以**过程指标 + 证明构造分**的组合证据为主，不只押在总分差上。

需求书"≥8 个百分点"的成功标准建议改为"预注册的主效应方向一致，过程指标达到预设阈值"，由罗老师确认（D-09）。

## 8. 与豆包爱学 / ChatGPT 学习模式的区分（矛盾 4）

| 维度 | 豆包爱学 | ChatGPT 学习模式等 | 本系统 |
|---|---|---|---|
| 对象 | 中小学（官方定位） | 通用 | 数分证明，大一、大二 |
| 主要动作 | AI 讲（语音 + 动态板书），学生听和追问 | AI 苏格拉底式提问，可一键关闭 | **学生写**，AI 只提问 |
| 答案 | 2024-12 报道称学生模式的解析中仍可见答案（**可能已更新，待复核**） | 学生可随时关掉模式 | 实验期在架构上不可得；题目关闭后由教师讲评 |
| 内容来源 | 模型生成 | 模型生成 | 教师审核的题目包 |
| 数据 | 面向用户 | 面向用户 | 面向教师和研究：可导出、可复现 |

不应宣传"我们更聪明"，因为模型可以替换。可防守的差异只有三项：**教师审核的题目包、不可绕过的红线架构、研究级过程数据**。

## 9. 动机与"冰冷机器"（矛盾 5）

- **不用游戏化和情绪化人设**：对大学生，徽章、表情和夸张的鼓励容易显得幼稚。Tutor CoPilot 的随机对照试验显示，有效辅导的特征之一是"减少泛泛表扬、增加追问"（Wang 等 2024）。
- **胜任感**：可视化"你自己写出的关键步骤"（只显示学生自己的文本），以及"本周独立完成度"。
- **自主感**：学生可以自选跳层（受跳过规则约束）、自选何时求助，求助不扣分，只记录。
- **关联感来自人而不是 AI 人设**：教师讲评引用学生作品（匿名），同伴互评可作为二期功能。
- **语气**：平实、像助教批注，一次只问一个问题。

## 10. 针对性与通用性（矛盾 6）

| 层次 | 来源 | 例子 |
|---|---|---|
| 通用（任何证明都适用） | 证明框架模板、H0 元认知追问 | "你要证的命题是什么逻辑形式？" |
| 半通用（本章） | 定义卡、常见错误库 | "N 是否依赖 n？" |
| 针对本题 | 题目包里的关键步骤和 H2–H4 | "5/(n+2) 之后怎么用？" |
| 针对本人 | 归类器对学生原话的引用 | "你写的'取 N=5ε'里……" |

规则：越往下越针对，透露风险越高，也就越需要教师预写和闸门把关。模型只负责**选择层次和引用原话**，不负责产出数学内容。
