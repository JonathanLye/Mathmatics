# 07 · 数据库设计

> DDL：`contracts/schema.sql`（PostgreSQL 16+）。`npm run check:sql` 用 PGlite 完整执行并验证关键约束。本文说明设计意图；字段细节以 DDL 注释为准。

## 1. 原则

1. **研究数据只多不少**：`ev.events` 只追加（触发器禁止 UPDATE/DELETE）；作答相关表一律软删除（`deleted_at`）；学生的原始输入（文本、笔迹、照片、识别原文与确认后的文本）全部保留。
2. **服务端为准**：作答状态只由服务端写（`app.attempts.state`），同时保留可回放的事件；两者必须一致（回放完整性测试）。
3. **题目包分级**：公开部分在 `content.problem_versions.public`；保密部分在 `vault`；参考证明单独一张表并记录每次读取。已发布版本不可修改（触发器），要改就发新版本，作答固定在开题时的版本上。
4. **个人信息最少且加密**：学号、姓名只存密文（应用层 AES-256-GCM）与登录匹配用的 HMAC；对外、导出、日志一律用匿名码。
5. **派生数据可重算**：`attempt_metrics` 等派生表随时可以从事件与明细表重算，口径以 08 号文档为准。

## 2. Schema 划分

| schema | 内容 | 谁能读 |
|---|---|---|
| `app` | 用户、班级、名单、同意书、设备、会话、布置、实验、作答、证明行、笔迹、照片、识别、草稿、求助、提示、批注、模型调用、闸门决策、诚信信号、教师干预、导出、审计、派生指标 | 应用 |
| `content` | 题库源 PDF、页面 OCR、条目、导入任务与草稿、概念库、术语、题目、题目版本（公开部分）、审核记录、Lean 结果 | 应用；导入 worker |
| `vault` | 题目包保密部分、参考证明、参考证明访问日志 | 应用只读 `problem_secrets`；参考证明只给审核 worker |
| `ev` | 只追加事件（按月分区）、事件 ID 去重表 | 应用只插入；研究导出只读 |

## 4. 表的用途速查

> 本表以 `contracts/schema.sql` 为准；加表/改列先改 DDL，再同步本表。

| 表 | 一行是什么 | 关键字段 |
|---|---|---|
| `app.users` | 一个人 | `role`、`anon_code`（S-xxxxxx / T-xx） |
| `app.student_profiles` | 学生的加密身份 | `student_no_enc`、`student_no_hash`、`age_band` |
| `app.roster_entries` | 名单里的一行 | `student_no_hash`、`claimed_by` |
| `app.consents` | 一次签署 | `version`、`items{service,crossBorderHosting,crossBorderModel,monitoring,research}` |

| `app.attempt_lines` | 学生写下的一行（各层通用） | `layer`、`role`、`statement`/`_canon`、`justification`、`provenance`、`cls`、`keys`、`classifier_path` |

| `app.hint_deliveries` | 一条下发的提示 | `key_id`、`level`、`cost`、`reveal_before/after`、`text_shown` |
| `app.annotations` | 一条批注 | `line_id`、`kind`、`source`、`text_shown` |
| `app.model_calls` | 一次模型调用 | `purpose`、`model`、`model_version`、`prompt_version`、`shadow`、`output`、`confidence`、`cost_cny` |

## 5. 事件表

- 分区：`ev.events` 按 `ts_server` 月分区；worker 每月 25 日预建下月分区；`DEFAULT` 分区兜底。
- 去重：前端事件的 `id` 先插 `ev.ingest_ids`（主键冲突即重复，直接跳过），再插 `ev.events`。
- 顺序：同一作答的事件 `seq` 由 `app.attempts.last_event_seq` 在同一事务内递增分配；无作答的事件（登录、导航）按用户另计。前端的 `clientSeq` 只用于发现丢包。
- 只追加：触发器 `events_no_update` 拒绝 UPDATE/DELETE；生产库再用权限收紧（应用账号只有 INSERT、SELECT）。

## 7. 保留与删除

| 数据 | 保留 | 删除方式 |
|---|---|---|
| 作答、证明行、识别、提示、批注、事件 | 2 年（或研究计划规定的期限） | 到期后按用户匿名化（断开 `user_id` 与身份）后保留统计；学生申请删除时 30 天内执行 |
| 笔迹、照片 | 1 年 | 删除文件，保留元数据 |
| 原始访问日志（IP 等） | 90 天；IP 只存掩码（IPv4 /24，IPv6 /48） | 定时清理 |
| 学号、姓名密文 | 账号存续期间 | 账号删除时清除 |
| 模型调用输出 | 2 年（评测与复现需要） | 同作答 |

删除学生数据时：`users.status='deleted'`，清空 `student_profiles` 的密文、`roster_entries.name_enc`；事件不删除，但 `user_id` 置空、`user_anon` 保留（匿名码与身份已断开）。这一操作写 `audit_log`。

## 8. 迁移

- 初始迁移 = `contracts/schema.sql`。之后每次变更写增量 SQL（`apps/server/migrations/NNNN_*.sql`），同时更新 `schema.sql` 使其始终代表最新全量结构，`check:sql` 保证它能独立执行。
- 只加列、加表、加索引；不删列（改名同样"新增 + 保留旧列一个学期"）。
- 题目包 JSON 的结构升级通过 `schemaVersion` 区分，引擎同时支持新旧两版直到旧版作答全部结束。
