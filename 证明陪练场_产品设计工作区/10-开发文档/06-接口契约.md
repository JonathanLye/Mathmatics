# 06 · 接口契约

> 机器可读版本：`contracts/openapi.yaml`（OpenAPI 3.1，Redocly lint 0 警告）。本文是它的导读与约定；两者冲突以 YAML 为准，并立即修正本文。

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 基础路径 | `/api/v1` |
| 格式 | JSON UTF-8；时间 ISO 8601（UTC，前端按北京时间显示） |
| 鉴权 | 两端各一个 Cookie（HttpOnly、Secure、SameSite=Lax）：学生 `pg_sid_s`、教师 `pg_sid_t`；`/teacher*`、`/auth/teacher*` 读教师 Cookie，其余读学生 Cookie，只有 `/me`、`/auth/logout`、`/events/batch` 由请求头 `X-Pg-App: student\|teacher` 指明（缺省学生）；写接口另带 `X-Requested-With: proof-gym`。旧 `pg_sid` 只读兼容，`GET /me` 时换成新 Cookie（05 §7） |
| 幂等 | 写接口带 `Idempotency-Key: <uuid>`；24 小时内同键重放返回首次成功的响应（带 `Idempotent-Replayed: true`）。同键不同请求 → 422 `VALIDATION_FAILED`（`detail.reason=idempotency_key_reused`）；同键请求仍在处理 → 等待后重放，等太久 429 `RATE_LIMITED`（`detail.waitSec`）；失败的请求不缓存，可用同键重试。当前已实现于 `/attempts/*`（含 `/help`、`/hints/claim`）与 `/student/assignments/*/attempt`；`/events/batch` 用事件 id 去重，不走本机制 |
| 并发 | 作答写接口可带 `If-Match: <stateVersion>`；版本落后返回 409 `STATE_STALE`，`detail.state` 是最新状态 |
| 响应 | 作答相关写接口一律返回 `{ state: AttemptState, … }`，前端只渲染它 |
| 错误 | `{ "error": { "code": "…", "message": "给用户看的中文", "detail": { … } } }` |
| 分页 | 游标式：`afterSeq` / `nextSeq`（事件）；列表接口暂不分页（单班规模） |
| 版本 | 字段只增不删；破坏性变更走 `/api/v2` |

幂等补充约定：

- 重放体是**首次成功响应的快照**（含当时的 `state` / `stateVersion`），不是最新状态；客户端收到 `Idempotent-Replayed: true` 时只确认“首次已成功”，state 必须按 `stateVersion` 与新状态比较后再应用。
- 重放在 preHandler 短路，**不校验 `If-Match`**；后续写仍由 If-Match 保护。
- 同键重试必须复用同一请求体（键序不同已归一化；数组顺序和值必须一致，否则 422）。
- 已知窗口：业务事务提交后、响应写入 `app.idempotency_keys` 前进程崩溃，30 秒后可被**同一请求**接管并重放；不同请求体不会接管（422）。接管只可能重放一次成功响应，不会无限重复；该窗口与根治（outbox/同事务）见 07 §7。
- `/help` 重放可能带回首次的 `previewToken`；令牌只有 60 秒，过期后重放会拿到已过期 token。客户端遇到 `HINT_PREVIEW_EXPIRED` 应换新键重新 `/help`（同键只会重放同一过期 token）。

## 2. DTO 白名单（硬性）

学生可调用的接口（`/student/*`、`/attempts/*`、`/recognitions/*`、`/events/batch`、`/consents`、`/me`）**只能返回 OpenAPI 里列出的字段**。服务端实现上只允许通过 `toStudentView()` 与各自的序列化函数输出，禁止直接把数据库行或题目包对象 `JSON.stringify` 出去。

契约测试"DTO 泄露扫描"：对每个学生接口的响应，先解析 JSON，再递归对每个字符串值单独 canon；不得包含：**未透露 key** 的 `leak` 片段、`patterns` 原文、`referenceProofs` 文本、`keys[].label`。已由 H3/H4 正常下发且计入透露量的 key 的片段**不在扫描范围**（与闸门允许清单同一逻辑）；不要对 `JSON.stringify(body)` 整体 canon（JSON 转义会丢 LaTeX）。学生 DTO 必须 `additionalProperties:false`。

### 3.8 学生密码（登录协议）

- **已设密码**：`POST /auth/student/login` 必须带 `studentNo` + `password`；学号不存在、密码错、都返回同一条 401 `INVALID_CREDENTIALS`（学号或密码不对），不泄露学号是否存在。同时带有效 `inviteCode` 则顺带加入该班（加入第二个班的唯一路径；名单规则不变）。
- **未设密码或还没有账号**：必须带 `inviteCode` + `studentNo`，按名单认领；`Me.needsPassword=true`，前端先去设置密码页，再走年龄分档 → 同意书 → 首页。
- **已设密码却只带邀请码**：401 `PASSWORD_REQUIRED_LOGIN`，不创建会话（同学拿到邀请码也不能冒登）。
- **强制设密码**：服务端开关 `STUDENT_PASSWORD_ENFORCE`（生产默认开，开发/测试默认关）。开启后，未设密码的学生除 `/me`、`/auth/logout`、`/auth/logout-all`、`POST /auth/student/password` 外的学生接口一律 403 `PASSWORD_SETUP_REQUIRED`（`detail.reason` 不是 `wrong_app`）。
- **密码规则**：8–64 个字符（按字符计）、不限字符类型、不能与学号相同、不能是常见弱密码；不通过返回 422 `VALIDATION_FAILED`，`message` 可直接展示。改密必须带 `currentPassword`，不对返回 **403** `INVALID_CREDENTIALS`（刻意不用 401，否则客户端会当作会话失效跳回登录页）；连续输错同样按用户锁定（429）。
- **忘记密码**：找老师在名单里「重置密码」；重置后学生用邀请码 + 学号重新激活，再设新密码。重置是账号级的（该生在其他班也要重设）。
- 已知残余风险：拿到邀请码的同学可能抢先认领尚未激活的账号；靠名单里的「已设密码」列和教师重置兜底。

### 4.1 加入一行（手写）

```http
POST /api/v1/recognitions/ink
{ "attemptId": "…", "draftId": "d1", "target": "line_statement", "ink": "<gzip+base64>" }

200 { "recogId": "r1", "status": "ok", "text": "$|a_n-3|=\\frac{5}{n+2}$",
      "confidence": 0.93, "agree": true, "rendered": true }

POST /api/v1/recognitions/r1/confirm
{ "text": "$|a_n-3|=\\frac{5}{n+2}$" }
200 { "recogId": "r1", "edited": false, "rendered": true }

POST /api/v1/attempts/{id}/lines           Idempotency-Key: …   If-Match: 17
{ "statement": "$|a_n-3|=\\frac{5}{n+2}$", "justification": "通分",
  "input": { "provenance": "ink", "draftId": "d1", "recogId": "r1" },
  "justificationInput": { "provenance": "keyboard", "draftId": "d2" } }

200 { "state": { "stateVersion": 18, "budget": { "revealUsed": 0, "revealMax": 2, "keysOwn": 1, "keysTotal": 4 },
                 "steps": { "lines": [ { "lineId": "…", "n": 1, "statement": "…", "justification": "通分", "provenance": "ink", "flagged": false } ] },
                 "notes": [ { "kind": "annotation", "who": "批注", "lineId": "…", "text": "第 1 行和前面衔接上了。", … } ], … } }
```

> 示例里的 `d1`、`r1` 是缩写，实际 `draftId`、`recogId` 都是 uuid。手写与拍照必须**先 confirm 再提交**；未确认、非本人/本次作答、来源类型不符、提交文字与确认文字不一致，一律 409 `RECOG_NOT_CONFIRMED`。两路识别都失败返回 503 `UPSTREAM_UNAVAILABLE`（界面提示"再写一次，或者用键盘"）；空结果（`status=empty`）不可确认（422）。拍照的一个 `recogId` 可分批 confirm（每批带 `lines`，已确认的行累加）并被多次 `/lines` 引用。

### 4.2 卡住了 → 预览 → 领取

```http
POST /api/v1/attempts/{id}/help   { "intent": "stuck" }
200 { "routed": "stuck",
      "preview": { "level": "H2", "cost": 0.5, "revealAfter": 0.5, "allowed": true, "previewToken": "pt_…" },
      "state": { … } }

POST /api/v1/attempts/{id}/hints/claim   { "previewToken": "pt_…" }
200 { "routed": "stuck",
      "note": { "kind": "hint", "who": "H2 · 透露 0.5", "level": "H2", "cost": 0.5,
                "text": "试着把上一行的分式放大成更简单、关于 $n$ 单调的式子。" },
      "state": { "budget": { "revealUsed": 0.5, … }, "help": { "nextLevel": "H3", "nextCost": 1, "waitSec": 20, "needAttempt": true } } }
```

H0/H1（不计透露量）在 `/help` 里直接以 `note` 返回，没有 `preview`。不能领取时 `preview.allowed=false`，`reason` 为 `need_attempt` / `dwell`（带 `waitSec`）/ `rapid_lock`（仅旧状态里还有的锁）/ `budget`（带 `softLanding`）/ `layer` / `test_mode` / `complete`。30 秒内第 3 次起的连续求助返回一条 `note`（`kind: system`，“先试着写一行，或者过一会儿再问我。”），不带 `preview`、不扣额度。

已下发的提示写入 `app.hint_deliveries`，行批注与概念回答写入 `app.annotations`，与状态变化同一事务；`Note.noteId` 就是行 ID，刷新（`GET /attempts/{id}` 的 `state.notes`）读回同一个 ID，客户端按 `noteId` 去重。`POST /attempts/{id}/flag-teacher` 写 `app.help_flags`（教师看板显示求助），额度用完或卡住满 `stuckMs` 后可用（`state.help.canFlag`），重复调用幂等，测验模式 403。开了 `help.llm` 时，`concept` / `free` / `check_line` 的回答由模型生成并过三重闸门（09 §7.2），`note.aiGenerated = true`、响应头 `X-AIGC: 1`；被拦或模型不可用时回退模板回答。学生对 AI 回答点“有用 / 没用”：`POST /student/notes/{noteId}/feedback {useful}`（204）。同期补齐：`POST /attempts/{id}/layers/{layer}/enter`、`PATCH/DELETE /attempts/{id}/lines/{lineId}`（改行/删行重算 `matched`，`reveal` 不减少，事件 `line.edit`/`line.delete`）、`PUT /attempts/{id}/draft`、`GET /student/assignments/{id}`。

## 5. 错误码

| code | HTTP | 含义 | 前端处理 |
|---|---|---|---|
| `BAD_REQUEST` / `VALIDATION_FAILED` | 400 / 422 | 参数不合法 | 提示并保留输入 |
| `UNAUTHORIZED` | 401 | 未登录或会话过期 | 跳登录，登录后回到原页 |
| `INVALID_INVITE` | 401 | 邀请码错误 | 输入框提示 |
| `NOT_IN_ROSTER` | 403 | 学号不在名单 | 提示联系老师 |
| `INVALID_CREDENTIALS` | 401 / 403 | 登录：学号或密码不对（401，统一文案）；改密：当前密码不对（403，不跳登录页） | 就地提示 |
| `PASSWORD_REQUIRED_LOGIN` | 401 | 这个学号已设置密码，请用密码登录 | 切到「学号 + 密码」 |
| `PASSWORD_SETUP_REQUIRED` | 403 | 账号还没设密码，服务端开启了强制 | 跳设置密码页（不当作错误，也不回登录页） |
| `CONSENT_REQUIRED` | 403 | 未签同意书 | 跳同意页 |
| `AGE_BAND_REQUIRED` | 409 | 未选择年龄段（13 §4） | 跳年龄段选择页（≥18 / 14–17 / <14） |
| `AGE_BAND_LOCKED` | 409 | 年龄段已记录且不可自改 | 提示联系老师；不重复提交 |
| `AGE_RESTRICTED` | 403 | <14 岁不开通（13 §4） | 显示「暂未开通」说明，不再发写请求 |
| `FORBIDDEN` | 403 | 无权限；`detail.reason=wrong_app` 表示浏览器里只有另一端（学生/教师）的会话 | `wrong_app` 与 401 一样跳本端登录页；其它 403 就地提示，不跳转 |
| `NOT_FOUND` | 404 | — | — |
| `WRONG_LAYER` / `LAYER_LOCKED` | 409 | 当前层不允许该操作 / 层未解锁 | 用 `detail.state` 刷新 |
| `STATE_STALE` | 409 | 版本落后 | 用 `detail.state` 刷新，保留未提交输入 |
| `ATTEMPT_LOCKED` | 409 | 作答被锁（测验） | 显示锁定遮罩 |
| `ASSIGNMENT_CLOSED` | 409 | 布置已关闭（教师关闭/取消或超过 `close_at`） | 只读：按 code 分支，停止发写请求，用 `GET /attempts/{id}` 拉最新 state（本错误**不带** `detail.state`） |
| `RECOG_NOT_CONFIRMED` | 409 | 用了未确认的识别结果 | 打开确认面板 |
| `HINT_NOT_READY` | 409 | 门槛未满足 | 显示 `detail.waitSec` / `needAttempt` |
| `HINT_PREVIEW_EXPIRED` | 409 | 预览令牌过期 | 重新 `/help` |
| `BUDGET_EXHAUSTED` | 429 | 透露额度用完 | 显示 `detail.softLanding` |
| `RATE_LIMITED` | 429 | 限流 | 显示等待时间或"改用键盘" |
| `PAYLOAD_TOO_LARGE` | 413 | 笔迹或照片过大 | 前端抽稀/压缩后重试 |
| `PHOTO_DISABLED` / `TEST_MODE_RESTRICTED` | 403 | 本布置不允许（练习区查看解答：老师布置、测验作答、班里该题有未结束的测验都属此类） | 隐藏入口 |
| `TEST_IN_PROGRESS` | 409 | 班里这道题有没结束的测验，不能从路径或练习区开始 | 直接展示 `message`，不重试 |
| `UPSTREAM_UNAVAILABLE` | 503 | 识别等外部服务不可用 | "识别暂不可用，请用键盘" |
| `INTERNAL` | 500 | — | "出了点问题，你的内容已保存" |

补充约定：

- 作答写接口（`/student/assignments/{id}/attempt`、`/attempts/*` 的 POST/PATCH/DELETE）在布置关闭后一律返回 `409 ASSIGNMENT_CLOSED`；`GET /attempts/{id}` 与 `/events/batch` 遥测不受影响（事件仍可用于断线重连）。
- 错误优先级：若同时带落后的 `If-Match`，可能先收到带 `detail.state` 的 `409 STATE_STALE`；按版本重试一次后仍是关闭，则按终态处理，避免死循环。
- 数据库时钟是关闭判定的唯一口径；极窄的并发窗口内（检查通过后、提交前教师刚好关闭）允许关闭前最后一笔写入提交。
- `/help` 与 `/hints/claim` 的写路径同样受此约束；help 侧对已关闭布置返回 409 或按接口约定不写入求助记录。
