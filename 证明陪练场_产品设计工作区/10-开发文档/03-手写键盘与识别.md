# 03 · 手写、证明键盘与识别

> 适用：`packages/ui-math`（手写画布、证明键盘、MathText 编辑与渲染、图解组件）、服务端 `src/ocr`、worker `recog` 队列。
> 原则：**手写为主，键盘为辅，拍照可选；识别是抄写员，不是批改员；学生确认后才提交。**

## 1. 输入管线总览

```text
            ┌── 手写（ink-v1 笔迹）──► /recognitions/ink ──┐
学生 ──输入──┼── 拍照（JPEG）────────► /recognitions/photo ─┼──► 识别结果（MathText）──► 学生确认/修改 ──► /recognitions/{id}/confirm
            └── 证明键盘 / 系统键盘 ─────────────────────────────────────────────► MathText ──┐
                                                                                         ▼
                                     提交（/definition、/lines、/selfcheck …）带 InputMeta{provenance, draftId, recogId}
```

- 每个输入落点（定义、骨架、这一行、依据、自检、总结、求助文本）各自独立，一个落点一个 `draftId`。
- 提交时 `provenance` 取值：`ink` / `keyboard` / `photo` / `mixed`（识别后又用键盘改过）/ `paste`（含粘贴）。服务端核对：`ink`/`photo`/`mixed` 必须带已确认的 `recogId`；没有任何笔迹、击键、识别记录却出现的文本 → 诚信信号 `no_provenance`（11 号文档）。

## 2. 手写画布

### 2.1 采集格式 ink-v1

```json
{
  "v": 1,
  "w": 1200, "h": 360, "dpr": 3,
  "t0": 1762344000000,
  "orientation": "landscape",
  "fullscreen": true,
  "strokes": [
    { "id": 0, "p": "touch", "pts": [[12.5, 40.0, 0, 0.5], [13.1, 41.2, 16, 0.5]] }
  ],
  "ops": [
    { "op": "erase", "ids": [3, 4], "t": 5230 },
    { "op": "undo", "t": 6100 },
    { "op": "scratch", "ids": [7], "by": 8, "t": 7400 }
  ]
}
```

- 坐标：CSS 像素，相对画布左上角；`t`：相对 `t0` 的毫秒；`pressure` 0–1，设备不支持时固定 0.5。
- `p`：`pen` / `touch` / `mouse`（来自 `PointerEvent.pointerType`）。
- `ops` 保留全部编辑操作（研究用：犹豫、改写都是过程数据）。最终参与识别的笔画 = 全部笔画 − 被擦除/划掉/撤销的笔画。
- 上传：`gzip(JSON)` 后 base64，单行上限 256 KB（H5 用 `CompressionStream`，不支持时用 pako）。超限时前端按 1 px 距离抽稀点。

### 2.2 采集与渲染

- 事件：`pointerdown/move/up/cancel`，`move` 时读 `getCoalescedEvents()` 补齐高频采样；画布 `touch-action: none`。
- **防手掌误触**：一旦检测到 `pen`，本次会话只接受 `pen`，忽略 `touch`。
- 渲染：可变线宽笔迹（按压感或速度计算宽度），算法用 perfect-freehand（MIT，纯函数，H5 与小程序都能用）；当前笔画画在上层画布，抬笔后合并到底层画布，保证每帧只重绘一笔。
- 高清：画布像素尺寸 = CSS 尺寸 × dpr。

### 2.3 工具

| 工具 | 行为 |
|---|---|
| 撤销 / 重做 | 以"笔画/操作"为单位，栈深 100 |
| 橡皮 | 擦除与橡皮轨迹相交的整笔（不做像素级擦除，保证笔迹数据干净） |
| 清空 | 记为一组 erase 操作（可撤销） |
| 划掉删除 | 见 2.4 |
| 续写 | 写到画布右侧 85% 处时，画布自动向左平移，给出空白继续写 |

### 2.4 划掉删除手势

一笔满足以下条件即判为"划掉"：笔画包围盒内水平方向来回 ≥ 3 次（方向反转计数）、路径总长 ≥ 包围盒宽度 × 2.5、与已有笔画包围盒重叠面积 ≥ 60%。命中后删除被覆盖的笔画和这一笔本身，记 `scratch` 操作。误判可撤销。

### 2.5 一次只写一行

一个画布对应一个输入落点的一行。若检测到两组笔画在竖直方向间隔 > 0.8 × 笔画中位高度，提示"一次写一行会认得更准"，并按间隔拆成两次识别，确认面板里显示为两行供学生合并或分开。

### 2.6 全屏手写

手机点 ✍ 进入全屏（02 §4.5）。建议横屏但不强制；进入/退出全屏、方向变化都写进 ink-v1 的 `fullscreen`、`orientation`。

## 3. 识别

### 3.1 手写行识别流程（`/recognitions/ink`）

```text
1. 服务端保存 ink（app.ink_captures），去掉无效笔画后栅格化：黑笔白底，高 160 px，左右留 16 px，PNG。
2. 入 worker 队列 recog（并发 = 已购 SimpleTex QPS；每生同时最多 2 个请求）。
3. 主识别：SimpleTex 轻量公式接口（latex_ocr_turbo）→ LaTeX + conf。
   conf < 0.7 时再调标准接口（latex_ocr），取置信度高者。
4. 交叉：Qwen3.8-Flash 视觉，提示词 P-OCR-1（09 §5.1，逐字转写、不纠错）→ MathText。与第 3 步并行。
5. 统一成 MathText：SimpleTex 返回的 LaTeX 里，\text{…} / 中文片段放到 $ 外，其余放进 $…$（latexToMathText，见 3.4）。
6. 比对：canon(主) 与 canon(交叉) 相同 → agree=true；不同 → agree=false，按 canon 串做字符级最长公共子序列，
   求出差异片段，映射回主结果的位置，返回 diff[{start,end,alt}]。
7. 写 app.recognitions、recog.request / recog.result 事件，返回前端。
```

排队超过 4 秒或 SimpleTex 报错/超时 → 以 Qwen 结果为主（`provider: qwen3.8-flash`）。两路都失败 → `status: error`，前端提示"没认出来，再写一次，或者用键盘"。

### 3.2 确认（`/recognitions/{id}/confirm`）

学生在确认面板里可以：直接确认；在差异处二选一；用键盘改；放弃重写。确认时服务端记录最终文本、是否改过、编辑距离（canon 上的 Levenshtein），并检查 KaTeX 能否渲染（不能渲染的片段原样保留为文字，不阻止提交）。**只有确认过的识别结果才能用于提交。**

### 3.3 拍照识别（`/recognitions/photo`）

```text
前端：拍照或选图 → 画布重编码（去 EXIF、长边 ≤ 2000 px、JPEG 0.85、≤ 2 MB）→ multipart 上传
服务端：
1. 存 app.photos；SimpleTex 通用图片识别（rec_mode=document）→ Markdown（含 $…$）与版面块。
2. 按块与换行切成行，每行一个 MathText + bbox + conf。
3. Qwen3.8 视觉对整页做一次逐字转写交叉；逐行比对得 agree / diff。
4. 返回 lines[]。
前端：照片上叠行框，下方逐行列出识别结果；学生逐行确认/修改/删除/合并，然后"依次加入证明"，
      每行作为一次 /lines 提交（provenance=photo，recogId 相同）。
```

拍照来源在教师端显示 📷 徽标；测验模式下拍照禁用。

### 3.4 LaTeX → MathText 转换规则

| 识别输出 | 转成 |
|---|---|
| `\text{任取}\varepsilon>0` | `任取 $\varepsilon>0$` |
| 纯中文 | 原样（不加 $） |
| `\begin{array}{l} … \\ … \end{array}`（多行） | 拆成多行，确认面板里提示学生"识别出 2 行" |
| `\mathrm{lim}` 等 | `\lim` |
| 全角标点 | 保留在 $ 外 |

### 3.5 识别评测（P1 第 2 周，决定主识别厂商）

- 数据：150 条真实学生行（手机手指、平板笔写各半；纯公式、中文混排、含常见笔误各占一定比例）+ 30 张草稿纸照片。两人标注"学生实际写的内容"（包括错的地方）。
- 候选：SimpleTex（轻量/标准）、Qwen3.8-Flash 视觉、DeepSeek V4.1 Flash 视觉、自部署 PaddleOCR-VL 或 MinerU 2.5（如有 GPU）。
- 指标：canon 完全一致率；canon 字符错误率；**顺手改对率**（标注里学生写错、识别结果却是对的）—— 必须接近 0；P95 延迟；每行成本。
- 决策：顺手改对率不达标的直接淘汰；其余按"一致率 ≥ 85% 前提下成本最低"选主识别，另一家做交叉。

## 4. 证明键盘

### 4.1 布局

数据在 `contracts/keyboard-layout.json`，分 6 层：

| 层 | 内容 |
|---|---|
| 常用 | ∀ ∃ ε δ N n < > ≤ ≥ / = ≠ → ∞ ⇒ ( ) + − · / 模板：分式、绝对值、根号、上标、下标、aₙ、取整、lim、∑、{aₙ} |
| 证明句式 | 任取 ε>0、存在 N、当 n>N 时、取 N=、取 δ=、当 0<\|x−x₀\|<δ 时、要使…只需、于是、所以、由…得、不妨设、反设、矛盾、综上、收敛、发散 |
| 关系·集合 | ∈ ∉ ⊂ ⊆ ∪ ∩ ∅ ℕ ℝ ℤ ⇔ ¬ ∧ ∨ ≈ ≡ ± … |
| 希腊 | α–ω 常用 20 个 |
| 函数·分析 | sup inf max min ln sin cos eˣ f(x) f′ ∫ d/dx limsup liminf ∏ x→x₀⁺ (a,b) [a,b] nᵖ (−1)ⁿ |
| 123 | 数字、运算、常用字母 |

右侧固定动作列：← → ⇥ ⌫ 中 ✍ 完成。

**证明句式层只是句式，不含任何解题内容**（不会出现"取 N=⌈5/ε⌉"这类针对某题的片段）。

### 4.2 行为

- `insert` 里的 `#0` 是插入后的光标位置，`#1 #2…` 是"⇥"依次跳到的占位；占位在预览里显示为 ▢。
- `mode: "math"` 的键：光标不在 `$…$` 内时，编辑器自动包成 `$…$` 并把光标放进去；`mode: "text"` 的键（句式）原样插入（句式自带 `$…$`）。
- 长按显示 `variants`；松手选中。
- 记住学生上次停留的层。
- 每次按键轻微震动（`uni.vibrateShort`，可在设置里关）。
- 键盘会话结束时上报 `kbd.session`（按键数、数学键数、模板数、删除数、时长、是否切过系统键盘）。

### 4.3 MathText 编辑器（P0）

P0 采用"源码 + 实时预览"：输入框里是 MathText 源码（键盘插入的都是 LaTeX 片段），**输入框上方实时显示 KaTeX 渲染结果**，学生主要看渲染结果。占位符显示为 ▢，光标所在占位高亮。学生很少需要直接看源码（主要输入方式是手写）。

P2：H5 端在 `$…$` 片段内换成 MathLive 结构化编辑（分式、上下标所见即所得）；小程序端维持 P0 方案。

## 5. MathText 与 canon()

### 5.1 MathText 语法

- 普通文字 + `$…$` 行内 LaTeX；字面 `$` 写作 `\$`；不允许 `$$…$$` 跨行公式（出现时按行内处理）。
- 允许的 LaTeX：KaTeX 支持的数学命令；`trust: false`，禁止 `\href`、`\url`、`\htmlClass` 等。
- 存储：原文（`statement`）+ 规范化串（`statement_canon`）。

### 5.2 canon() 规则

参考实现 `contracts/tools/canon.mjs`，回归用例在 `contracts/tools/check-seeds.mjs` 的 `CANON_CASES`。服务端 `packages/engine/canon.ts` 必须与之逐字节一致。

| 步骤 | 规则 | 例 |
|---|---|---|
| 1 | 按未转义的 `$` 切段；**每段**都按 LaTeX 线性化（$ 外也可能有学生直接敲的 `u_{n+1}`） | |
| 2 | `\frac{a}{b}` → `a/b`；分子顶层含二元 `+ - = < > ≤ ≥ ≠ ,` 时加括号；分母不是"单个数/单个字母/已加括号/√简单量/\|…\|/⌈…⌉/简单幂"时加括号 | `\frac{5}{n+2}`→`5/(n+2)`；`\frac{3n+1}{n+2}`→`(3n+1)/(n+2)`；`\frac{1}{n^2}`→`1/n^2` |
| 3 | `\sqrt{x}` → `√x` 或 `√(x)`（同分母规则）；`\sqrt[n]{x}` → `root(n,x)` | `\sqrt{n+1}`→`√(n+1)` |
| 4 | 上下标：`_{…}` `^{…}` 按分母规则加括号 | `u_{n+1}`→`u_(n+1)`；`(-1)^{n-1}`→`(-1)^(n-1)` |
| 5 | 命令映射：希腊字母、关系符、量词、箭头、`\lceil`→`⌈` 等（见实现中的表）；`\left \right \big \displaystyle \quad` 等删除；`\text{}` `\mathrm{}` 取内容 | `\varepsilon`→`ε`，`\leq`→`≤` |
| 5b | 常见等价命令：`\over` 按 `\frac` 规则；`\div`→`/`；`<=`→`≤`、`>=`→`≥`、`!=`→`≠`、`->`→`→` | `5 \over n+2`→`5/(n+2)`；`a \div b`→`a/b` |
| 5c | 普通 `{}` 仅作分组、输出时删除；集合花括号必须写 `\{...\}` | `{a_n}`→`a_n`，`\{a_n\}`→`{a_n}` |
| 6 | 文字规范化：先把 ² ³ ⁿ ₁ ₙ 转成 `^2 ^3 ^n _1 _n`，再 NFKC（全角转半角），再统一：各种减号→`-`，`×·⋅`→`*`，`，；：。`→`, ; : .`，`≦≧`→`≤≥`，`ϵ`→`ε`，`∣`→`\|` | `\|a_n − 3\|`→`\|a_n-3\|` |
| 7 | 删除全部空白；**不做大小写折叠**（N 与 n 必须区分） | |

### 5.3 等价写法

canon 只解决"同一写法的不同编码"，不解决数学等价（`5/(2+n)` 与 `5/(n+2)`）。处理办法：

1. 题目包的 `patterns` 用正则覆盖常见变体（如 `5/\(n\+2\)|5/\(2\+n\)`）；
2. `leak` 片段列出主要变体；
3. 导入时由模型生成等价变体，教师审核；
4. P1 起，规则未命中时由 Jev 做语义归类（09 §4）。
5. leak 片段可能以 canon 形式存储；闸门/门禁比较时"原样匹配 + canon 后再匹配"两路都做（避免二次 canon 破坏 `u_(n+1)` 这类片段）。

## 6. 草稿与离线

- 每个输入落点的草稿（文本、笔迹、识别结果）存 IndexedDB（H5）/ `uni.setStorage`（小程序），键为 `attemptId:target`。
- 每 15 秒或切后台时 PUT `/attempts/{id}/draft` 备份到服务端。
- 断网时可继续写和识别排队（识别需要网络，断网时提示"联网后识别"，笔迹保留）；提交按钮变为"保存草稿"。

## 7. 图解组件

### 7.1 类型

由概念库的 `VisualSpec` 驱动（`contracts/concept.schema.json`）。前端只认下面几种，参数化渲染；**不执行任何来自数据的代码**。

| type | 画什么 | 交互 | 计算 |
|---|---|---|---|
| `seq-band` | 数列点 (n, aₙ)，n=1…nMax；水平带 A±ε | 拖动 ε 滑块 | N(ε) = 最小的 N，使 N < n ≤ nMax 的点都在带内；标注"图中只画到第 nMax 项" |
| `partial-sums` | 一条或多条级数的部分和折线 Sₙ | 拖动 n 上限 | 累加 |
| `func-band` | 函数图像；水平带 A±ε；竖直带 x₀±δ | 拖动 ε | 数值扫描求最大可用 δ（步长 1e-3，标注"数值近似"） |
| `monotone-steps` | 相邻两项比较 uₙ 与 uₙ₊₁ | 拖动 n | 差值符号 |
| `number-line` | 数轴上的区间/邻域 | 拖动端点 | — |

### 7.2 受限表达式

`expr` 只允许：数字、变量 `n` 或 `x`、`+ - * / ^`、括号、函数 `sqrt abs sin cos exp log min max pow`。前端自带递归下降解析器求值（约 150 行），解析失败则不显示图解、只显示文字。由模型在第 1–2 层生成的图解参数同样只能是这种表达式。

### 7.3 渲染

H5 用 SVG（文字清晰、可缩放）；小程序用 canvas 2d（P2）。坐标轴刻度用等宽字体；滑块在图的下方；颜色用 token（带子用 `--accent-soft`，点用 `--accent`，带外的点用 `--ink-2`）。离开某一步时上报 `lesson.visual`（交互次数、最后的参数值、停留时长）。
