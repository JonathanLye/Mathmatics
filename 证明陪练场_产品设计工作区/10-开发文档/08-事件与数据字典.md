# 08 · 事件与数据字典

> 机器可读：`contracts/events.schema.json`（由 `contracts/tools/events-catalog.mjs` 生成，78 种事件）。本文 §3 的表由同一脚本生成（`node tools/events-catalog.mjs --markdown`），改事件只改脚本；§3 已加 `GENERATED` 标记，`npm run check` 会运行 `tools/check-generated.mjs` 校验生成物是否同步。

## 1. 为什么要这么多事件

老师的要求是"数据只能多不能少"，用来支撑教材研究和数学教育研究。所以：

- **过程**全部记录：每一次输入会话（手写笔画数、时长、擦改；键盘按键数、模板数）、每一次识别与确认、每一次提交与归类、每一次求助与路由、每一条提示与批注、每一次切层、每一次离开。
- **系统自己的决定**也记录：归类来自规则还是模型、模型的影子判断、闸门拦了什么、降级发生在哪里。这样研究者能区分"学生的行为"和"系统的行为"。
- **检验标准**：用事件回放必须能完全重建学生当时看到的页面（§6）。重建不出来，就说明少记了东西。

## 2. 事件信封

| 字段 | 说明 |
|---|---|
| `id` | uuid v7，前端生成；重试不变，用于去重 |
| `seq` | 服务端分配；同一作答内严格递增（回放排序以它为准） |
| `type` | 事件类型（§3） |
| `source` | `student` / `server` / `teacher` |
| `tsClient` / `tsServer` | 客户端时间（参考）/ 服务端入库时间 |
| `sessionId` / `deviceId` / `clientSeq` | 前端会话、设备、会话内序号（发现丢包） |
| `userAnon` / `role` | 匿名码 / 角色 |
| `classId` / `assignmentId` / `attemptId` / `problemId` / `problemVersion` | 归属 |
| `layer` | L1–L6 |
| `mode` / `arm` | 练习/测验；实验分组 |
| `appVersion` / `platform` | 前端版本；`h5-ios`、`h5-wechat-android`、`mp-weixin`、`teacher-web`、`server` 等 |
| `promptVersion` / `modelVersions` | 本事件涉及的提示词与模型版本 |
| `payload` | 按类型定义（§3） |

前端只能上报 `source=student/teacher` 的类型（schema `$defs/ClientEvent`）；服务端类型由服务端在状态变化的同一事务里写入，前端伪造会被拒（`check-events` 有用例）。

## 4. 指标口径

所有指标都从事件与明细表计算；教师端、导出、论文用同一套 SQL（`apps/worker/src/metrics/*.sql`）。

### 4.1 作答级

| 指标 | 定义 |
|---|---|
| 完成 | 存在 `attempt.complete` |
| 用时 `durationMs` | `attempt.complete.tsServer − attempt.start.tsServer`（首次开始） |
| 前台有效时长 `activeMs` | 相邻事件间隔 ≤ 60 秒且页面可见的时间之和 |
| 透露量 `reveal` | 最后一条 `hint.deliver.revealAfter`；无则 0 |
| 独立度 | `1 − (reveal + 教师补发的 H4 数) / keysTotal`（0–1）。教师补发（软着陆）不增加 `reveal` 字段，但每条按透露 1 计入，所以含补发的作答不会被算成"独立完成" |
| 独立度分档 | ≥0.85 独立 / 0.5–0.85 有提示 / <0.5 依赖（阈值可配置） |
| 自己写出 `keysOwn` | `matched` 中的关键步骤数（H4 示范过的需写出依据才计） |
| 自主覆盖率 | `matched` 中**从未领取过 H2 及以上提示**的关键步骤数 / `keysTotal` |
| 首次求助前时长 | 进入 L3（`layer.enter`）到第一条 `cost>0` 的 `hint.deliver`；从未领取则记为删失（值 = L3 停留时长，标记 censored） |
| 提示后停留 | 每条 `cost>0` 的 `hint.deliver` 到下一条 `line.submit` 的时长；作答取中位数 |
| 连点次数 | `hint.rapid_lock` 次数 |
| 平均提示轮数 | `cost>0` 的 `hint.deliver` 条数 / 作答题数（主题与迁移题分开统计） |
| 卡住次数 | `proactive.offer` 次数 |
| 求助构成 | `help.request.routed` 各类次数 |
| 施压次数 | `pressure` 次数 |
| 第 1 层尝试次数 / 是否看了微课 / 微课完成度 | `def.submit` 次数；`lesson.open`；`lesson.close.completedSteps/totalSteps` |
| 识别修改率 | `recog.confirm.edited=true` 的比例；平均编辑距离 |
| 输入构成 | 证明行 `provenance` 各类占比 |
| 离开 | `integ.visibility(state=visible)` 中 `awayMs ≥ 2000` 的次数与这些 `awayMs` 之和（与 11 §2 一致：离开 ≥ 2 秒计 1 次；短于 2 秒的切屏不计） |
| 诚信信号 | `integ.flag` 各类次数与最高分 |
| 闸门拦截 | `gate.block` 次数（按 stage） |

### 4.2 班级 / 布置级

| 指标 | 定义 |
|---|---|
| 完成率 | 已完成作答数 / 已开始作答数（另给"/ 名单人数"） |
| 独立度、自主覆盖率、首次求助前时长、提示后停留 | 作答级指标的中位数与四分位 |
| 层漏斗 | 每层 `layer.enter` / `layer.done` / `layer.skip` 的人数 |
| 关键步骤卡点 | 每个关键步骤：自己写出（keyCost=0）、经提示写出（keyCost>0）、当前卡在这里（按路线顺序的下一个未匹配 key 且处于卡住状态）的人数 |
| 卡点知识点 | 按题目包 `public.tags`/`chapter` 聚合 key 级卡点人数，取 Top5 |
| 识别质量 | 修改率、两路分歧率、P95 延迟 |
| 样本量规则 | n < 10 时只显示人数，不显示比例 |

### 4.3 研究用

| 指标 | 定义 |
|---|---|
| 迁移表现 | 迁移题子作答的完成、独立度、用时 |
| 延迟后测 | 测验模式布置（无提示）的完成与教师评分（P2：评分表单） |
| 外部 AI 使用（协变量） | 每周问卷自报（P2）+ `integ.flag(ai_style)` |
| 实验条件 | `arm`、`arm_order`、知识块 |

## 6. 回放完整性

**约束**：对任何作答，`replay(public, meta, 该作答全部 source=server 事件按 seq 排序)` 得到的引擎状态，必须与 `app.attempts.state` 逐字段相等；学生视图投影 `toStudentView` 也必须相等（批注文本取自 `annotations.text_shown`、`hint_deliveries.text_shown`）。

**实现**：

- 服务端每个改变状态的命令，`decide` 产生的领域事件与新状态在同一事务里落库。
- `apply` 只读事件 payload，不读题目包保密部分、不读时钟。
- e2e 测试结束后对所有作答跑一次比较；CI 中任何不一致即失败。
- 线上每晚抽 5% 作答跑一次，不一致发告警。
