# 15 反馈与信箱

> 早期阶段需要大量真实反馈。本篇定义：学生在任意页面一步反馈、系统自动带上精确上下文（探针）、开发者在小后台分类/回复/结单、学生在应用内「信箱」看到回复，以及「捉虫小能手」勋章。决策见 00 U23。实施分线：B 契约与服务端（本篇 §3–§5 已落地）、A 学生端（§6–§8）、C 教师端开发者页（§9）。

## 1. 目标与非目标

- **目标**：(1) 任何页面两次点击内说清问题；(2) 自动带上位置、题目、步骤、设备与最近的错误，开发者不用追问；(3) 每条反馈有编号、状态和回音（Khan Academy 的「Report a problem」被诟病成黑洞，我们不重蹈）；(4) 视觉、动效、语气全部沿用现有小方风格（02 §0）。
- **非目标**：不发邮件、不收邮箱；不做公开投票看板；不做会话回放；不做新反馈的外部 webhook（会把学生数据发到站外，另议）；不做 XP 奖励和反馈排行榜。

## 2. 状态与分类

| 状态 | 学生看到 | 谁改 | 说明 |
|---|---|---|---|
| `new` | 已收到 | 系统 | 提交后的初始态 |
| `open` | 正在看 | 开发者回复时自动，或手动 | 学生追问会回到这里 |
| `need_info` | 想问问你 | 开发者 | 等学生补充；学生回复 → `open` |
| `resolved` | 已解决 | 开发者 | 必须写说明，说明会作为回复发给学生；14 天内学生追问可重开 |
| `closed` | 已关闭 | 开发者 | 必须选原因（`fixed` 已修复 / `duplicate` 重复 / `wontfix` 暂不处理 / `no_repro` 无法复现）并写说明；关闭后双方都不能再回复，学生可新写一条 |

- **分类**（开发者设）：`category` = `bug` 功能故障 / `display` 显示异常 / `content` 题目有误 / `suggestion` 建议 / `question` 咨询 / `other` 其他；`area` = 页面区域，服务端由 `context.route` 推导（home、practice、practice-zone、mistakes、proofbook、proof-detail、me、…），开发者可改。学生自己选的 `kind`（有问题/有想法/题目有误/其他）保留不变。
- v1.1 再做：`severity`、`duplicate_of`、快捷回复模板、`resolved` 7 天无回复自动关闭。

## 3. 数据与接口（权威：`contracts/openapi.yaml`、`contracts/schema.sql`，迁移 `0007_feedback_inbox.sql`）

- `app.student_feedback` 增列：`ref_no`（展示 #0042）、`status`、`category`、`area`、`context jsonb`、`student_unread`、`dev_unread`、`student_event`（一次性庆祝：`confirmed`/`resolved`，学生打开后清空）、`last_activity_at`、`confirmed_at`、`resolved_at`、`closed_at`、`close_reason`、`resolution_note`。新表 `app.feedback_messages`（学生与开发者的对话；学生的第一句话在反馈行的 `body` 里，接口把它拼成对话第一条）。
- 学生：`POST /student/feedback`（**201**，返回 `{id, refNo}`；旧版是 204）、`GET /student/feedback`、`GET /student/feedback/{id}`（打开即已读，并带回一次性 `event`）、`POST /student/feedback/{id}/messages`；`GET /me` 增 `feedbackUnread`（红点用）。提交与回复要求已签同意书；读自己的不要求。限流：提交 10/分钟、回复 20/分钟（按会话）。
- 开发者（**仅 `admin` 角色**；普通教师 403）：`GET /teacher/feedback`（状态/分类/区域/未读/关键词、分页、各状态计数）、`GET /teacher/feedback/{id}`（含上下文与对话，打开即标已读）、`PATCH`（改分类/区域/状态）、`POST …/messages`（回复，可同时 `setStatus: need_info|resolved`）、`POST …/confirm`（确认复现）。开发者只看到匿名码和班级，看不到学生昵称。
- 错误码：`FEEDBACK_CLOSED`（409）有两种来源——反馈已关闭，或已解决超过 14 天不能再追问；客户端两种都提示「可以再写一条新的」。
- 请求 ID：客户端给每个请求带 `X-Request-Id`（8–64 位字母数字、下划线、连字符），服务端沿用并写进日志、回写响应头；不合格式的忽略。开发者据此把一条反馈与服务端日志对上。

## 4. 探针（自动上下文）

客户端把以下内容放进 `context`（契约 `FeedbackContext`，全部可选，服务端白名单、总大小 ≤16KB，路径与面包屑会去掉 query/hash）：

| 内容 | 字段 |
|---|---|
| 位置 | `route`、`pageName`、`problemId`、`attemptId`、`layer`、`mode`、`stepNo` |
| 精确定位 | `targets`：学生点到/圈到的 `data-fb` 元素名（关键组件打 `data-fb="step:3"`、`data-fb="answer-input"` 等） |
| 版本与环境 | `app.version`/`app.sha`、`env.os/browser/viewport/dpr/theme/online/motion` |
| 最近的错误 | `errors`：最多 20 条，只记 `Error` 的 name 与 message（≤200 字），不记任意 `console.error` 参数 |
| 最近的操作 | `breadcrumbs`：最多 30 条，`nav` 路径、`tap` 的 `data-fb` 名、`api` 的「方法 路径」+状态+耗时+requestId |

**绝不采集**：证明正文、输入框内容、答案、请求/响应体、手机号等（13 §1）。做题编辑区默认 `data-fb-mask`。`context` 是不可信输入，开发者页面按纯文本渲染。**采集设备/错误是否需要升同意书版本，是合规待确认项（§10），A 线上线前必须有结论。**

## 5. 开发者确认复现与勋章「捉虫小能手」

- 开发者对 `category` 为 `bug` 或 `display` 的反馈点「确认复现」：写入 `confirmed_at`，信箱里该条标「已确认复现」，并给学生发勋章 `bug_hunter`（`app.student_badges`，幂等：学生已有则不重复，之后的确认只在对话里发一句感谢）。**由开发者人工触发，不自动发放**，防止刷反馈。不发 XP。
- 学生下次打开该条时收到一次性 `event: confirmed`，播放小方庆祝（见 §7）。
- **红色奖章（01 §7、02 §0 的例外）**：此勋章按产品负责人的决定用红色（`--chili`）奖章，**仅限这一处**；不得把红色用在其它反馈元素上。

## 6. 学生端入口与流程（A）

- **全局悬浮「小方」按钮**：48px 靛蓝小方脸（`PgMascot`，`breathe`+`blink`），硬边 + `--lip`，按下 `pg-press`；手机在 tab 栏之上（`bottom: calc(var(--tabbar-h) + var(--safe-bottom) + 12px)`），平板/桌面在右下；z-index 50（高于 tab 栏 30，低于默认 Sheet 60）。首次出现用 `PgCoachmark`：「哪里怪怪的？点小方告诉我们」。
- **宿主**：以 `AppShell` 为主（home、me/*、mistakes、practice-zone、proof-detail、proofbook），再显式挂到做题页和 `not-found`（致命错误落地页）。`PgSheet` 用 uni 标签，只有 `PgToast` 是纯 `div` 可独立挂载，故不走全局独立挂载。
- **不显示**：登录/同意/改密/年龄/引导/隐私政策/镜像页（没有会话或未签同意，接口无法提交）；**考试模式（`mode=test`）完全隐藏**（11 §5.2）；任何 Sheet/Dialog/考试遮罩/庆祝层打开时隐藏；做题页缩成顶部右侧小标，数学键盘展开时隐藏。登录前的反馈通道另议（§10）。
- **更多入口**：「我的 → 问题反馈」行保留；做题页题干旁「题目有误」直达（预选 `content` 并带 `problemId`）；错误 toast（`errorBoundary`、接口 5xx）加 action「告诉小方」，带着刚发生的错误打开。
- **反馈 Sheet**（`PgSheet`，手机底部弹出、≥768px 居中）：顶部小方 `think`；`PgSegmented` 四类（有问题/有想法/题目有误/其他）；按类型变化的快捷标签（卡住了 · 打不开 · 公式输不进 · 太慢 …，点一下即填）；自由描述；一行「小方会一起带上：这一页、手机型号、最近的小错误」（透明展示，可关）；主按钮「送出去」。关掉不丢草稿（本地 key 用 `pg.fbbox.v1`，避免与学习反馈 `pg.feedback.v1` 混淆）；离线时排队重发；失败文案「没发出去，请再试一次，写的内容还在」。
- **发送成功**：小方 `happy`+`hop`、`correct` 音效、`pg-pop`：「收到啦！编号 #0042，小方已经交给开发者了。可以在『信箱』看进度。」
- **截图与圈一圈（A2，由功能开关控制，开关与上传接口等 B 在 A2 契约里补，合规确认前不上线）**：点 FAB 的瞬间先截屏，带硬超时，超时或失败静默降级；从「我的」「关于」入口打开时不截（会截到反馈页自己）；标注层支持圈、箭头、遮住隐私矩形、撤销；圈中的矩形经 `document.elementsFromPoint` 命中最近 `[data-fb]`，上报 `targets`。截图上传接口与存储（保留期、清理）待合规确认后另开契约。
- 命名避让：仓库里「feedback」已指学习反馈（`PgFeedbackPanel`、`feedbackAllowed()`），新模块用 `feedbackbox`。

## 7. 信箱页与可爱规范（A）

- **入口与红点**：「我的」新增「我的反馈」行；FAB、「我的」tab 图标出现小圆点（**橙/金，不用红**；红色只用于不可逆操作与捉虫奖章）。回复到达时 FAB 弹跳一下。红点来自 `GET /me` 的 `feedbackUnread`；启动、回到前台、进入「我的」时拉取，不做长连接。
- **列表**：每条一张 `PgCard`（`lip`），状态 `TagChip`（已收到/正在看/想问问你/已解决/先放一放），最新回复预览，未读点；空态用 `PgEmpty`：「还没有反馈。发现哪里怪怪的，点小方告诉我们。」
- **详情**：对话气泡；开发者回复用 sea 蓝卡 + 小方头像（署名「小方 & 开发组」）；学生可追加回复（`need_info` 时突出）。
- **庆祝**：`event: resolved` → 小方 `cheer` + 轻量彩带（受 `feedbackAllowed()` 控制）：「解决啦！谢谢你帮小方找到它」；`event: confirmed` → 红色奖章 `pg-pop`/`pg-stamp` 盖章 + 彩带 + `celebrate` 音效：「抓到虫啦！你帮小方找到了一个真问题」；「我的 → 勋章」页出现红色奖章（`badgeIcon` 增加 bug 图标，如瓢虫/放大镜）。测验模式不弹。
- **规范**：组件只用 `PgSheet/PgSegmented/PgButton/PgCard/TagChip/PgEmpty/PgToast/PgCoachmark/PgMascot`；颜色全用 token，不硬编码；动效用 `pg-sheet-up/pg-pop/pg-item-in`、`--ease-spring`、`hop/cheer/think-tilt`；全部走 `feedbackAllowed()` 与 `prefers-reduced-motion`/`data-motion=off`，考试模式静音；文案只放 `apps/student/src/copy/`，口语短句、第二人称，不出现「工单、日志、探针、bug、上报」（`copy-lint.test.ts` 拦截）；不出现对错表情；暗色模式、44px 触控、16px 输入字号、`--safe-*`、`--keyboard-inset`。验收：A 在 `pages/dev/gallery.vue` 补 FAB、Sheet、信箱列表/详情、庆祝的状态，供负责人看图审「可爱」。

## 8. 防作弊与合规约束

- 考试模式不显示入口；反馈入口不得成为 AI 问答或退出全屏的旁路（11）；做题页里打开 Sheet、输入、粘贴不得触发完整性信号（visibility/focus/paste），A 需用测试验证。
- 隐私政策（`apps/student/src/copy/privacy.ts` 数据表与保留期）、13 §2/§3、07 §7 需同步更新「反馈里附带的页面位置、设备型号和最近的错误」；若有截图，还要写保留期。

## 9. 开发者页（C，教师端「反馈」页，TDesign）

- 仅 `admin` 角色可见（`/me.role`）。列表：状态 Tab + 计数、category/area 筛选、关键词搜索、未读加粗。详情抽屉：左边对话与回复框（「回复并解决」「想问问你」「确认复现并发勋章」），右边分类下拉与自动上下文（路由、题目、版本、设备、最近错误、面包屑、requestId），按纯文本渲染。结单必须选原因、写说明。

## 10. 待确认（门控上线，不阻塞契约与服务端合并）

1. 采集设备/错误/截图：只更新隐私政策，还是要升同意书版本重签（13 §1 把设备数据限定为设备 ID 与打码 IP，13 §2 要求改同意书文本升版）。**未确认前，A 线只能上线「位置 + 题目 + 步骤」这类不涉及设备与错误的最小上下文。**
2. 登录/同意页的反馈通道（这些页没有会话，无法提交；"登录不了"很可能是早期最常见的问题）。
3. 截图保留期与存储（建议 180 天，落 `STORAGE_DIR`，只经鉴权路由读取）。
4. 开发者账号：沿用 `admin` 角色。创建：`TEACHER_PASSWORD=… node apps/server/src/db/cli.ts create-teacher <用户名> --admin [--totp]`（生产用 05 §8 的 `docker compose … run --rm … migrate node apps/server/src/db/cli.ts create-teacher …` 写法）；已有教师账号想提升，运维执行一条 `update app.users set role = 'admin' where id = …`。

以上数字（14 天重开窗口、16KB、20/30 条、10/20 次每分钟）都是建议默认值，可改。
