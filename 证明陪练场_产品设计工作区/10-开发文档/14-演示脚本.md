# 14 · 演示脚本（10 分钟走查）

> 给老师演示用。写的是 v3 做完后的产品：学生开场动画 → 路径首页 → 写一题拿反馈 → 问 AI → 完成庆祝 → 错题重做 → 切到教师端看实时看板。
> 学生端界面和文案以现场为准；这里只写学生"会看到什么"，没有列出的功能不要向老师承诺。
> 演示数据由 `tools/demo-seed.mjs` 准备（只建「演示班」和虚构学生，不碰真实数据）；用完用 `--cleanup` 清理。

## 1. 演示前（至少提前 10 分钟）

| 步骤 | 做什么 | 看到什么才算好 |
|---|---|---|
| 1 | 启动服务（本地：`pnpm dev`，教师端另开 `pnpm --filter @proof-gym/teacher dev`）。确认题库已载入：`node apps/server/src/db/cli.ts seed`（可重复运行） | `/health` 返回 ok |
| 2 | 教师账号存在。没有就建一个（服务停着时做，本地数据库一次只能一个进程打开）：`TEACHER_PASSWORD=… node apps/server/src/db/cli.ts create-teacher demo` | 无报错 |
| 3 | 播种：`DEMO_TEACHER_PASSWORD=… node tools/demo-seed.mjs --i-know-this-is-a-demo`（加 `--wait-stuck` 会等到"卡住"出现再返回） | 末尾打印"演示班已就绪"、学号和共用密码 |
| 4 | **等 5 分钟再开始演示。** 看板上的"卡住"按真实时间算：写出最近一个关键步骤后 3 分钟没进展才算卡住；脚本最后一行会打印出现的时间点 | 播种结束 3 分钟后，看板上有橙色"卡住"的同学 |
| 5 | 准备两个窗口：学生端用手机，或浏览器开发者工具里选 390 宽；教师端用电脑浏览器 1280 宽。两端可以同时登录同一浏览器，互不影响 | 两端各有自己的登录 |
| 6 | 把播种打印的密码抄在一张纸上（不要写进任何文件、不要截图发群） | — |

演示班里的 13 个同学（全是虚构的，学号以 `DEMO` 开头）：

| 学号 | 状态 | 演示里的用处 |
|---|---|---|
| DEMO01、DEMO02 | 独立做完六层 | 看板"已完成"；证明本里有内容 |
| DEMO03 | 用过提示、有一行含糊，做完 | **错题重做**用这个号 |
| DEMO04 | 写完证明，停在自检 | 看板"在写" |
| DEMO05 | 写出 3 个关键步骤，正在写 | **现场写一题**用这个号（还差最后一步） |
| DEMO06、DEMO07 | 停在写证明这一层 | 约 3 分钟后看板显示"卡住" |
| DEMO08 | 领完提示、额度用完，点了"求助老师" | 看板"需要你"（需要服务端已支持"求助老师"，见第 5 节） |
| DEMO09 | 定义已过，停在搭骨架 | — |
| DEMO10 | 登录过，没打开题目 | 看板"未开始" |
| DEMO11、DEMO12 | 在"路径"里自学（交错级数） | 教师端"自学进度" |
| DEMO13 | **没有账号**，只在名单里 | **现场走一遍第一次登录**（开场动画） |

## 2. 十分钟走查

下面每一步的"说什么"都是一两句话，照着念或自己改都行。点击写的是手机上的位置。

### 0:00–1:30 第一次打开：开场动画（学生，DEMO13）

| 点什么 | 看到什么 | 说什么 |
|---|---|---|
| 打开学生端首页 | 登录页：小方、大标题、学号和密码、"先试一道"、"我是老师"。第一次打开会先播开场动画 | "这是同学第一次打开时看到的。" |
| 看动画，不要跳过 | 四幕：什么是证明陪练场；小方沿着六步路走完一道证明；写不出来就问，它不会替你写；每天一点点（连胜和证明本） | "六步是：回忆定义、搭骨架、写证明、自检、换题试试、总结。AI 只提问和提示，不替学生写。" |
| 点"跳过"让老师看一眼（可选） | 任何一幕都能跳过 | "老手不用每次看。" |
| 按页面提示输入邀请码（播种时打印）和学号 `DEMO13`，设一个密码 | 设密码 → 选年龄 → 同意书，一次一个问题，不会塞满屏 | "学生用学号加密码登录；邀请码只在第一次用。忘了密码找老师重置。" |
| 填昵称，选每日目标，选默认输入方式 | 目标是几张带小动画的卡片；输入方式（手写 / 键盘 / 拍照）有小演示 | "这些以后都能在'我的'里改。" |
| 回到路径首页 | 三步聚光灯导览：路径上的节点 → 今日目标 → 我的 | "导览只出现一次，也可以在'我的'里重看。" |

兜底：现场网络慢，动画卡住 → 点"跳过"，直接说"这里有四幕动画，前面这一步我们略过"。

### 1:30–3:00 路径首页（换成 DEMO05）

| 点什么 | 看到什么 | 说什么 |
|---|---|---|
| 退出，用 `DEMO05` 和共用密码登录 | 路径首页：顶部连胜、经验、今日目标；"老师布置"置顶，带截止时间；下面是蜿蜒的路径，完成的节点是金色，当前节点有"继续"气泡和小方 | "老师布置的题永远在最上面，自己选题的路径在下面。" |
| 点单元横幅上的"单元讲义" | 一张抽屉：本单元的摘要和概念卡片 | "每个单元先有一页讲义。" |
| 点当前节点 | 弹出卡片：题目预览、六步进度、"继续" | "这题已经写了三步，继续。" |
| （可选）点底部"练习" | 练习区：一个大按钮"随机来一道"，下面按章、难度、状态筛选 | "想多练可以随机来一道，也能按难度挑。" |

### 3:00–5:00 写一题拿反馈（DEMO05）

| 点什么 | 看到什么 | 说什么 |
|---|---|---|
| 进入题目 | 顶部：关闭、一条贯穿六层的进度条、求助灯泡；题面一行，可展开；"关键步骤 3/4"；已写的行连成一条竖线 | "上面这条线就是六层，学生一直知道自己在哪。" |
| 点"写下一行"，选"键盘"页签，输入最后一步（取 N 之后的"当 n>N 时，… < ε"）和依据 | 一个面板里手写 / 键盘 / 拍照三选一；键盘有数学符号，下面实时显示排好版的公式 | "手写、键盘、拍照都能用，写出来的公式实时排版。" |
| 提交 | 底部滑出绿色面板"衔接上了"，有音效、+经验飘字，小方跳一下 | "系统只核对关键步骤是否齐全，不会在证明行上打红叉。" |
| （可选）故意写一行含糊的，如"先把 N 取大一点" | 底部出现蓝色面板：助教的一个问题，没有对错判断 | "它是用问句提醒，不说'错'。" |

兜底：公式不会输 → 用事先复制好的这一行（`当 n>N 时，|a_n−3| = 5/(n+2) < 5/n < ε`，依据"前三行连成一条链"）粘贴。

### 5:00–6:00 问 AI（同一题里）

| 点什么 | 看到什么 | 说什么 |
|---|---|---|
| 点右上角的灯泡 | 一张抽屉，三张大卡片（现有文案："我卡住了，不知道下一步"、"这个概念/符号我不懂"、"帮我看看这一行"），下面可以直接问一句 | "三种求助，都从这一个入口进。" |
| 点"这个概念/符号我不懂" | 小方"思考"，随后出现一条助教气泡，逐字出现，带"AI 生成"标记和"有用 / 没用" | "AI 的回答都标明是 AI 生成的，学生可以点有用或没用，这些都会被记录下来。" |
| 点"我卡住了，不知道下一步" | 预览卡片，明明白白写着这一条要用掉多少"提示额度" | "提示要花额度，用完以后可以回去看定义、看讲解、先做下一题，或者求助老师——这样学生不会一路点下去。" |

兜底：模型回答慢（超过约 10 秒）→ 说"这里在实时调用模型，我们先不等"，点关闭继续写；行批注、关键步骤核对、提示额度都不依赖模型实时回答。

### 6:00–7:00 完成庆祝

| 点什么 | 看到什么 | 说什么 |
|---|---|---|
| 写完所有关键步骤，点"写完了" | 每完成一层有一页过场：小方、这一层做了什么、下一层一句话说明，点"继续" | "每过一层都停一下，让学生知道刚做完什么、下一步是什么。" |
| 走到最后（自检 → 换题试试 → 总结；时间紧就让 DEMO01 的完成页提前准备好） | 全屏庆祝：彩纸、经验数字累加、连胜、"4 步里 3 步靠自己"、新徽章，还有一行说明：系统核对关键步骤是否齐全，最终以老师讲评为准；按钮"下一题 / 换题试试 / 看我的证明" | "注意这句：系统只核对关键步骤，最终还是老师讲评。" |

### 7:00–8:00 错题重做（DEMO03）

| 点什么 | 看到什么 | 说什么 |
|---|---|---|
| 退出，用 `DEMO03` 登录，点"错题" | 按卡点分组：定义没写全、依据缺失、放缩卡住、靠提示写出的步骤、自检没通过（空的分组不显示） | "做完之后，卡点自动归到错题里。" |
| 点某一项的"重做" | 进入一份新的重做作答，题目上有"重做"标记，强制练习模式，不再计经验 | "重做不影响班级数据，也不再给经验。" |
| 点"证明本"，打开一张卡片 | 完整证明、总结；老师发布讲评后这里有"看讲评" | "做完的证明自动收进证明本，可以打印。" |

### 8:00–10:00 切到教师端：实时看板

| 点什么 | 看到什么 | 说什么 |
|---|---|---|
| 教师端登录，进"我的班级"→「演示班」 | 白色小卡：班名、已认领人数、邀请码。页面顶部写着"教师端"，整体比学生端安静 | "老师端是工具，不要游戏化。" |
| 看"实时看板" | 顶部六个数字（需要你 / 卡住 / 在写 / 离开中 / 已完成 / 未开始），点一个就筛选。每个同学一张白卡：左边一条色条表示状态——红色是"求助老师"，橙色是"卡住 N 分钟"，青绿是"在写"，绿色是已完成；卡片本身不上色。右边是"优先处理"队列和全班在哪一层 | "红色条的是点了求助老师的人，橙色是卡住的人，先看他们。" |
| 点 DEMO08 或"卡住"的同学 | 右侧抽屉"学生作答详情"：证明行（公式已排版）、领取的提示、诚信提醒、求助老师、操作记录 | "每一行是怎么写出来的（手写 / 键盘 / 拍照）都看得到。" |
| 抽屉里点"回放"（可选）、输入一句话点"发送"（可选） | 回放按学生当时的状态重现；发给学生的话不能包含他还没写出的步骤 | "老师可以发一句话，但系统会拦住直接泄题的话。" |
| 回到班级页，点"自学进度" | 每位同学在各单元做完几题、正在做几题、看过解答几题；说明这些不进看板、指标和导出 | "同学自己练的题单独看，不影响布置的数据。" |
| 点"布置"页签，点"题目"下拉 | 可输入关键字搜索，滚到底点"加载更多"；只列已发布、未下架的主题 | "题库几百道题也不会卡，直接搜。" |
| 左边点"题库" | 状态、来源（全部 / 老师审核 / AI 整理）、关键词筛选；每行有来源标签；"下架"一点确认，学生的路径和练习区里就不再出现 | "AI 整理的题标得很清楚，老师可以随时下架。" |

## 3. 如果出问题

| 现象 | 怎么办 |
|---|---|
| 看板上没有"卡住"的同学 | 播种后还不到 3 分钟，再等一会儿；或者现场让 DEMO05 停手 3 分钟 |
| 看板上没有"求助老师" | 服务端还没有"求助老师"接口时，播种会提示。更新服务后先 `--cleanup` 再重新播种，或在学生端额度用完后现场点一次 |
| 忘记某个同学的密码 | 教师端「演示班」→"名单"→ 该同学"重置密码"；同学用邀请码加学号重新激活，再设一个新密码 |
| 模型很慢 | 见第 5 分钟的兜底。不要等，往下走 |
| 手机屏幕太小，老师看不清 | 学生端投到电脑浏览器，用开发者工具选 390 宽；或把手机屏幕投屏 |
| 页面打不开 | 先看 `/health`；学生端和教师端是两个入口：`/` 和 `/t/` |

## 4. 演示后清理

```bash
# 本地（PGlite）：先停服务，再清理
DEMO_TEACHER_USER=demo node tools/demo-seed.mjs --cleanup --i-know-this-is-a-demo --dry-run   # 先演练：只列出会删什么，不提交
DEMO_TEACHER_USER=demo node tools/demo-seed.mjs --cleanup --i-know-this-is-a-demo
```

清理只删教师名下叫「演示班」的班级、它的演示学生，以及他们名下的作答、事件、证明本内容；教师账号、题库和其他班级都不动。
清理直接连数据库（服务端没有删班级和学生的接口），连的是 `DATABASE_URL`（有则用），否则是本地的 `PGLITE_DIR`；目标不是本机时默认拒绝，必须再加 `--allow-non-local-target`。

## 5. 已知限制（演示前心里有数）

- "卡住"要等 3 分钟才出现，所以播种要提前。
- "求助老师"依赖服务端的求助接口；没有它时 DEMO08 只会停在"提示额度用完"。
- 开场动画、庆祝页、路径等界面由学生端各分支陆续完成；演示前在目标环境里完整走一遍第 2 节，以实际界面为准。
- 播种脚本不碰真实数据，但它会在目标服务里新建账号：不要对线上服务运行（默认拒绝非本机地址）。
