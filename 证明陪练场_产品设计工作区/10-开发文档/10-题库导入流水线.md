# 10 · 题库导入流水线

> 目标：老师不用一题一题手写题目包。把华东师大版《数学分析同步辅导及习题全解》PDF 交给流水线，AI 双模型起草、仲裁、自动校验，老师只做审核。
> **U16（2026-11-06，见 00 §4.1）**：批量导入的题**不经人工审核直接发布**——通过 S8 自动校验与参考证明回放的题即发布，不再等 S9 教师审核（覆盖 U3 对导入内容“教师审核后才进入题目包”的要求，也不再受 Q1“罗老师抽时间审核”的制约）。发布后师生在界面上都能看到“AI 整理”标识；教师仍可事后在审核界面改动或下架，改动走新版本。S8 门禁与参考证明回放一项不省。
> P0：搭好 CLI 版流水线，导入 2–4 题作为加分项（首批上线内容以 v3 两题为准）。P1：审核界面与批量导入。

## 1. 源文件分析

文件（相对本目录）：`../华东师大版数学分析答案（上下册）.pdf`

| 项 | 实测 |
|---|---|
| 页数 / 页面尺寸 | 586 页；508.8 × 598.4 pt |
| 书名（页眉） | 数学分析同步辅导及习题全解（上册 / 下册） |
| 章 | 23 章（第一章 实数集与函数 … 第二十三章 流形上微积分学初阶） |
| 每章结构 | **内容提要** → **典型例题**（【例 n】+ "解题分析 / 解题过程"或"分析 / 证明"）→ **历年考研真题评析**（【题 n.m】（学校，年份）+ 解题分析 + 解析过程）→ **课后习题全解**（习题 n.m 及小题 (1)(2)…，"解 / 证"） |
| **文字层** | **不可用**：正文用方正书版自定义编码的 Type 1 字体，`pdftotext` 提取的中文部分可读，但所有公式变成 `!$#&%` 之类乱码 |
| 结论 | **必须把页面渲染成图片再做 OCR**，不能读文字层 |

## 2. 流水线

```text
S1 登记源文件 ─► S2 渲染页面 ─► S3 页面 OCR ─► S4 切条目 ─► S5 选证明题
      ─► S6 双模型起草题目包 ─► S7 对齐与仲裁 ─► S8 自动校验 ─► S9 教师审核 ─► 发布新版本
```

每个阶段是 worker 的一个任务（pg-boss），可单独重跑；中间结果都入库（`content.*`），任务进度写 `content.import_jobs.stage/stats`。

### S1 登记

计算 sha256，写 `content.sources`（`license_note`：仅限本课程内部教学使用）。同一文件不重复登记。

### S2 渲染

`pdftoppm -r 200 -png`（或 pdfium），每页一张 PNG 存对象存储，写 `content.source_pages.image_key`。整本约 586 张，单线程约 3 分钟。

### S3 页面 OCR

| 候选 | 方式 | 成本（整本） | 备注 |
|---|---|---|---|
| MinerU 2.5（pipeline 模式） | 自部署（需 GPU）或官方云 API | 自部署近乎 0 | pipeline 模式"不产生幻觉"，公式识别在中文公式基准上 CDM 约 95 |
| SimpleTex 文档识别 | API，¥0.02/页（每月前 1000 页免费） | 约 ¥0–12 | 境内、已在用 |
| Mathpix PDF | API，$0.005/页 | 约 $3 | 印刷体中文支持；境外 |

**做法**：先用 10 页样本（覆盖例题、真题、习题、多行推导、矩阵/分段函数）对比，人工核对公式，选准确率最高者跑整本；另一家作为抽检交叉。输出 Markdown（中文 + `$…$` / `$$…$$`）与版面块坐标，写 `ocr_md`、`ocr_json`、`ocr_conf`。

### S4 切条目

规则为主，模型辅助：

1. 按页眉/标题识别章（`第[一二…]+章`）。
2. 识别栏目：`内容提要`、`典型例题`、`历年考研真题评析`、`课后习题全解`。
3. 识别条目起点：`【例\s*\d+】`、`【题\s*\d+\.\d+】`（后接"（学校，年份）"）、`习题\s*\d+\.\d+` 与小题 `\(\d+\)`。
4. 识别条目内的段：`解题分析|分析` → `analysis_md`；`解题过程|解析过程|证明|证|解` → `solution_md`；之前的部分 → `stem_md`。
5. 跨页拼接：条目在页尾未结束时与下一页开头合并。
6. 规则判断不了边界（置信低）的页，交给 DeepSeek Flash 只输出边界 JSON（`[{start_line, end_line, type, no}]`），不改写内容。

写 `content.source_items`（含页码、真题出处）。

### S5 选证明题

- `is_proof`：题面含"证明 / 试证 / 求证 / 证："，或题面是判断类且解答中含完整证明（Jev noul 辅助）。
- 老师按章节挑选（P0 用 CLI 列表；P1 在界面勾选）。首批建议：第二章 数列极限、第三章 函数极限、第四章 函数的连续性、第十二章 数项级数中的例题与考研真题，每章 3–4 题。

### S6 双模型起草

两个模型各自独立起草**完整题目包**（`problem-package.schema.json`，public + secret）：

| | 模型 A | 模型 B |
|---|---|---|
| 型号 | DeepSeek V4.1 Flash（开思考，错峰时段跑） | Qwen3.8-Flash |
| 输入 | 条目的题面、解题分析、解答；相关章节的内容提要；概念库；题目包 schema；两个 seed 题目包作为范例 | 同左 |

起草要求（P-IMP-1，见 §3）：拆关键步骤（≤ 6 个，标 formal/core，允许多条路线）、为每步写 canon 形式的 `patterns`、`examples`、`leak`、`jev` 说明、H0–H4 与透露量；常见错误 3 条；定义成分与骨架检查；自检题 6–8 道；要点卡 2–3 条；从同章习题中挑一道（或改写一道）作为迁移题并为它起草完整题目包；参考证明取自书中解答（只进 vault）。

### S7 对齐与仲裁

1. **对齐关键步骤**：A、B 两稿的关键步骤用 Jev choice 做语义配对（"A 的 K2 对应 B 的哪一步？"），得到对照表。
2. **找分歧**：关键步骤数量不同、同一步的 leak 片段不同、提示级别对应的透露量不同、错误类型不同、迁移题不同。
3. **仲裁**：每处分歧交 DeepSeek V4 Pro（思考模式，P-IMP-2）给出采用哪一稿或合并，附一句理由；结果写 `import_drafts.disagreements`。
4. **透露量校准**：对每条提示用 Jev score（档位：0 只追问或只讲定义 / 0.5 指出方法方向 / 1 给出局部一步或示范一行）独立打分；与草稿标注的 `cost` 不一致的提示标红，留给教师决定。

### S8 自动校验（发布门禁，与 `contracts/tools/check-seeds.mjs` 同一实现）

| 检查 | 不通过时 |
|---|---|
| JSON Schema | 不能进入审核 |
| KaTeX 可渲染（所有 MathText） | 标出字段 |
| 规则自测：每个关键步骤的 `examples` 都命中自己的 `patterns`，且不被错误类型截走 | 标出步骤 |
| **穷举泄题**：按路线顺序模拟"当时已写出的关键步骤"，所有预写文本不得含未透露片段；H0–H2 不得含本步骤片段，只有 H3/H4 可以 | 标出文本与片段 |
| 片段不是题面的子串：每个 leak 片段 canon 后都不能出现在 canon(题面) 里（否则引用题面的提示会被误拦，DTO 泄露扫描也会误报） | 标出片段 |
| 提示阶梯单调：H(k+1) 的 Jev 透露评分 ≥ H(k) | 提醒 |
| 题面保真：题面与 OCR 原文逐字比对（只允许 LaTeX 规范化差异） | 标出差异 |
| 概念卡不含本题对象：概念微课与图解中不出现题面里的数列/函数 | 标出 |
| Lean（可选，P2） | 记录 |
| **参考证明回放**（`replayReferenceProof`）：用引擎把参考证明逐行提交，必须 `canFinish`、每个关键步骤都命中、作答能完成 | 进失败报告，不发布 |
| 导入题附加门禁（`runImportGates`）：只开 L3、L6；一条路线；有解题思路与关键点；`$` 成对；模式不能太宽、不能命中空话、核心步骤不能命中题面；H2 不含可照抄的式子；片段真实且不太短 | 进失败报告，不发布 |

### S9 教师审核

> U16：批量导入**不走本节**。S8 与参考证明回放全部通过即发布并打“AI 整理”标识；没通过的题进失败报告 `failed.json`（带原因），**不进人工队列、也不发布**。本节只保留给教师主动审核或修订已发布的题，以及教师自己用 `import:submit` 暂存的单题草稿。

导入题的 `secret.walkthrough`（思路 `approach` 与关键点 `keyIdeas` 必填，易错点 `pitfalls` 可选）由起草步骤生成，供练习区“查看思路”使用；缺少 `approach` 或 `keyIdeas` 的导入题按失败处理。导入题只启用 L3（写证明）与 L6（总结），其余层 `enabled=false`。

审核界面见 04 §8.2。通过后：写 `content.problem_versions`（`review_status='published'`）、`vault.problem_secrets`、`vault.reference_proofs`、`content.review_records`（含用时）。退回的草稿可编辑后重新跑 S8。

## 3. 提示词

### P-IMP-1 · 起草题目包（A、B 共用，版本化）

```text
系统：你在为"数学分析证明写作陪练"编写题目包。学生自己写证明，系统只能给教师预写的分级提示，绝不能替学生写。
你要输出一个符合 <schema> 的 JSON 题目包。参考 <examples> 里两个已审核的题目包的粒度与语气。
<schema>{problem-package.schema.json}</schema>
<examples>{seed/epsN.json, seed/series.json}</examples>
<concepts>{概念库中相关概念的 id 与标题}</concepts>
<item>题面：{stem_md}  解题分析：{analysis_md}  解答：{solution_md}</item>
要求：
1. 关键步骤 ≤ 6 个，每个是"写出来就推进了证明"的一步；区分 formal（只依赖命题形式）与 core（解题核心）；若存在另一条常见证法，写成第二条路线。
2. patterns 是作用在 canon 形式上的 JS 正则（canon 规则：\frac{a}{b}→a/b、分母复杂加括号、\varepsilon→ε、去空格、全角转半角…），要能覆盖学生的常见写法；examples 至少 2 条学生式写法。
3. leak 列出"可以直接照写"的片段（canon 形式），包括等价变体。
4. 提示 H0–H4：H0 只追问；H1 只讲定义或框架；H2 指出方向但不给对象（透露 0.5；点名决定性定理也算 H2）；H3 给出该步骤的一半（透露 1）；H4 示范该步骤的完整一行并把下一行交还学生（透露 1）。
   H0、H1、H2 不得包含本步骤的 leak（只有 H3/H4 可以）；任何提示不得包含后续步骤的 leak；leak 片段不能是题面原文的一部分。
5. 批注只用问句；不说"对/错"。
6. 自检题 6–8 道，覆盖依据/作用/逻辑地位/去掉条件/模块/迁移，可用 {line:Kn} 引用学生写出 Kn 的那一行。
7. 迁移题：同一证明思路、换一个对象，难度不高于原题，并为它也写完整题目包（kind=transfer，透露预算 1）。
8. 参考证明取自解答，可规范化表述，不得改变数学内容。
只输出 JSON。
```

### P-IMP-2 · 仲裁

```text
系统：两位编写者为同一道题起草了题目包，下面是它们的分歧。按"既不泄题、又能帮助学生一步步写出证明"的标准，逐条给出采用 A、采用 B 或合并后的结果，并附一句理由（≤ 40 字）。
<diffs>[{path, a, b}]</diffs>
输出 JSON：[{path, decision: "A"|"B"|"merge", value, reason}]
```

### P-IMP-3 · 条目边界修正

```text
系统：下面是一页数学教辅的 OCR 文本（带行号）。只找出条目边界，不改写任何内容。
条目类型：example（【例 n】）、exam（【题 n.m】）、exercise（习题 n.m 及小题）、summary（内容提要）。
输出 JSON：[{type, no, start_line, end_line, parts: {stem:[s,e], analysis:[s,e], solution:[s,e]}}]
```

## 4. 概念库的导入

每章"内容提要"里的定义（数列极限、函数极限、连续、一致连续、级数收敛/绝对收敛/条件收敛……）用同样的双模型流程起草概念条目（`concept.schema.json`：直观卡五段 + 分步微课 + 图解参数），规则：**微课与图解永不使用任何具体题目的对象**。教师审核后发布。概念条目跨题复用，审核一次即可。

## 5. 工作量与节奏

| 项 | 估算 |
|---|---|
| 整本 OCR | 机器约 1 小时；人工抽检 30 分钟 |
| 每题起草 + 仲裁 + 校验 | 机器约 3–5 分钟；费用约 ¥0.2 |

| 每个概念条目审核 | 约 30 分钟 |
| 试点节奏 | 每周 3 道必做题 → 每周约 5–6 小时审核；建议每周一次性审下一周的题 |

## 6. P0 的 CLI

```bash
# 登记并渲染、OCR 指定页（例如第二章：PDF 第 27 页起，第三章约从第 59 页起）
pnpm import:pdf --file "华东师大版数学分析答案（上下册）.pdf" --pages 27-58
# 列出切出的条目，挑证明题
pnpm import:items --chapter 2 --proof-only
# 起草、仲裁、校验（输出到 imports/<jobId>/<problemId>.json 与 report.md）
pnpm import:draft --items <itemId,itemId> --max 4
# 教师在编辑器里改完 JSON 后：再跑门禁并发布（记录审核人与用时）
pnpm import:publish imports/<jobId>/<problemId>.json --reviewer T-01 --minutes 90
```

`report.md` 列出：两稿分歧与仲裁理由、透露量校准不一致的提示、自动校验结果，方便老师集中看。

## 6.1 批量导入（`import:batch`，U16）

上面的 P0 CLI 一次处理几道题，留给教师手工导入单题。练习区的题库走批量流水线，不经人工审核：

```text
目录遍历 ─► OCR ─► 模型切分（规则兜底）─► 规则过滤与去重 ─► 整理、拆小题
  ─► 第二模型校验（可修补一次，必须复核通过）─► 选题 ─► 起草（校验错误回喂，最多重试两次）
  ─► S8 + 回放 + 附加门禁 ─► 变式测试抽样 ─► bundle.jsonl.gz ─► import-bundle 发布
```

```bash
# 先看文件、页数和估算，不调模型
pnpm import:batch <目录> --out imports/batch-v3 --dry-run
# 试跑：20 题走完整流程，自己读一遍输出，确认能做完
node --env-file=infra/.env apps/import/src/cli.ts batch <目录> --out imports/batch-v3 --max 20 --concurrency 8 --budget-cny 150
# 全量；中断后加 --resume 继续，已花钱的结果按文件缓存，不会重做
node --env-file=infra/.env apps/import/src/cli.ts batch <目录> --out imports/batch-v3 --resume --max 500 --concurrency 8 --budget-cny 150
# 只重新打包，不调模型
pnpm import:bundle --out imports/batch-v3
```

| 阶段 | 做法 | 模型 |
|---|---|---|
| 目录遍历 | PDF、图片、Markdown；加密 PDF 记为跳过，不尝试绕过 | — |
| OCR | `pdftoppm -r 200 -gray` 后逐页识别，缓存 `ocr/<book>/page-NNNN.md`。10 页对比后选定 `qwen3-vl-plus`：SimpleTex 文档模式把“故”“即”排错位置、丢下标大括号，且并发只有 1；`qwen3.5-ocr` 有整行丢失和把“迫敛性”写成“收敛性”；`qwen3.8-flash` 便宜但偶有漏字 | `qwen3-vl-plus` |
| 切条目 | 模型只标行号边界，不改写，题面保真；条目结束 = 下一个边界，跨页拼接是自然结果；模型失败退回规则（`【例 n】`、`例 n`、`第 n 题`、接得上的连续编号，不在证明内部切） | `deepseek-flash`（batch-v3 的切分由 `qwen3.8-flash` 跑完并已缓存） |
| 过滤 | 证明题（题面含证明字样，或解答以“证”开头）；拒绝依赖图形、依赖别的题、残字、解答太短或太长；跨书按规范化题面去重，主书优先 | — |
| 整理 | 只修 OCR 问题；能独立证明的小题拆开，公共条件写全 | `deepseek-flash` |
| 校验（必做） | 严格 JSON：`statementComplete, selfContained, solutionProvesStatement, gaps[], difficulty, confidence`。任一为假、有缺口或把握低于 0.8 就拒绝并记原因。只有题面没问题而解答有洞时才允许修补，修补稿必须再过一次校验 | `deepseek-flash`（校验开思考） |
| 难度 | 校验模型按量表给 1–5（看关键步骤数、技巧、常规程度，提示词带锚点题）。学生词汇：1–2 入门、3 进阶、4–5 挑战；选题目标 35/40/25，每章都覆盖 | 同上 |
| 起草 | 模型只写关键步骤、提示、解题思路等要判断力的字段；题面用校验过的原文，结构字段（层、路线、透露量、预算）由工具组装。只开 L3、L6，所以不需要定义、骨架、自检与迁移题。校验错误连同参考证明逐行的 canon 结果回喂，重试时模型只输出改动的部分。能确定意思的问题组装时直接修：模式里的 LaTeX 命令和内联标志、没转义的绝对值竖线、提示开头的“H0:”标记；样例或模型指明的证明行没被命中时补字面模式；H2 里能照抄的句子去掉；带片段的错误追问丢掉 | `deepseek-flash`（batch-v3 首批由 `deepseek-v4-pro` 起草，结果保留） |
| 门禁 | S8、回放、附加门禁（见 §2 S8）；参考证明必须能追溯到已核验的证明。不过的进 `failed.json` | — |
| 变式测试 | 模型按学生写法重写 10% 抽样的证明，统计规则完成率与关键步骤命中率。只进报告。它和起草是同一个模型，写法可能偏像，完成率会偏乐观 | `deepseek-flash` |
| 打包 | 先按整理后的题面再去重一次（拆小题之后两本书仍可能相同）；按章、节分单元；路径每节最多 5 题（由易到难，质量低的靠后）；全部题都进练习区 | — |

**第二模型核验暂停**：owner 决定这一轮文本阶段全部用 `deepseek-flash`，同一个模型既起草又核验，所以题目能否证明只有这一道模型判断加上 S8 和回放（回放只说明关键步骤能走通，不说明证明正确）。`manifest.json` 每题记录 `writtenBy` 和 `checkedBy`，`costs.jsonl` 按题记录每次调用的阶段和模型，以后要补第二模型核验可以按它们筛。

每次模型调用按响应里的实际用量记入 `costs.jsonl`，达到 `--budget-cny` 就停止并报告；账户欠费或余额不足时也整轮停下，处理账户后 `--resume` 继续。`manifest.json` 记录每个文件、每页、每题的状态与原因，`report.json` 是漏斗与分布，`failed.json` 是所有没进题库的题。

**发布**：本机生成 bundle，用一次性容器经标准输入写入数据库。不开隧道，不加管理接口。工具不依赖 `apps/import`，只用服务端镜像里已有的依赖，需要先跑完 0006 迁移：

```bash
ssh bolimc-prod 'cd /var/www/proofgym && docker compose -p proofgym run -T --rm server node apps/server/src/db/cli.ts import-bundle' < imports/batch-v3/bundle.jsonl.gz
```

`import-bundle` 再跑一遍门禁（本机文件也不当可信输入），每题一个事务，单题失败不影响其它题，有被拒绝的题时退出码为 2。按内容哈希幂等：同内容什么都不改；内容变了发新版本，已有作答仍固定在旧版本上；教师下架（`hidden_at`）不会被导入覆盖。它自动创建服务审核账号 `T-AI-IMPORT`（教师角色、已禁用、没有登录凭据），写 `review_source='auto'` 和 `review_records`，并建 `courses`、`course_units`、`unit_items`。
