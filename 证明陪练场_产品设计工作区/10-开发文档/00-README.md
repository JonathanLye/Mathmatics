## 3. 三端边界

```text
学生端（uni-app H5 → 小程序）        教师端（Vue + TDesign）
   │  只渲染 state；不做判定             │  看板 / 详情 / 审核 / 导出
   └──────────── OpenAPI + 事件 schema（contracts/）────────────┘
                              │
                 服务端（Fastify + PostgreSQL + worker）
                 engine（纯函数，事件溯源）· 闸门 · 模型网关 · 识别 · 导入
```

### 4.3 对需求确认书矛盾项的处理

需求确认书（2026-10-27）多处自相矛盾，"甲方选择"栏为空。以下按本轮确认处理：

| 需求书 | 本目录 |
|---|---|
| 拍照：既"必须交付"又"明确不做" | 做，默认开启（U7） |
| 公式键盘：列为不做 | 做：自研证明键盘（U10） |
| 平台：原生微信小程序 | H5 先行、遵守小程序规范，小程序 P2（U11） |
| 境内模型 | Jev 境外 + 单独同意 + 去标识化（U5、13 §3） |
| 提示次数"不限但记录" | H0/H1 不限但记录；H2–H4 按透露量计，每题 ≤ 2（沿用 v3） |
| AI 判断对错 | 不判对错，只问（沿用 v3） |
| 错题本 / 错题集 | 证明本 + 错题页都做（U14 之后；证明本为自己的证明、总结、薄弱点、稍后重做） |
| 通用数学答疑 | 不做；求助只答本题涉及的概念 |
| 登录：邀请码 + 学号 / 微信授权 | P0 邀请码 + 学号；P2 微信登录绑定学号 |
| 开发周期 11.1–11.7 | Day 0–3 上线 P0，P1 两周 |
| 参考答案永不给 | 题目关闭后由教师决定是否发布（v3 D-07） |
| SymPy 验证 | 不用；参考证明可用 Lean 核验（08 server.mjs） |

## 5. 术语

| 术语 | 含义 |
|---|---|
| 层 L1–L6 | 记忆核验 / 证明骨架 / 构造与推导 / 自检 / 迁移题 / 总结 |
| 题目包 | 一道题的全部教学数据；`public`（可下发）+ `secret`（只在服务端） |
| 关键步骤 K1…Kn | 教师登记的、写出来就推进证明的步骤；可有多条路线 |
| leak 片段 | 关键步骤里"可以直接照写"的片段；外发文本含未透露片段即拦截 |
| 透露量 | 提示泄露关键步骤的程度：H2=0.5、H3/H4=1，按步骤取最高级、全题求和，上限 2 |
| H0–H4 | 提示阶梯：追问 / 定义或框架 / 方向 / 局部一步 / 示范一行（交还学生） |
| 批注 | 系统在学生提交后主动给的问句，锚在该行下 |
| 求助（三意图） | 卡住了（提示）/ 不懂这个（概念）/ 看这一行（行检查）+ 自由提问 |
| 闸门 gate | 所有外发文本的泄题检查；规则说了算，模型只能加拦 |
| MathText | 中文 + `$…$` 行内 LaTeX 的文本格式 |
| canon() | 把 MathText 规范化成线性串，用于匹配与闸门 |
| 概念库 / 微课 | 第 1–2 层的公共知识：直观卡、分步讲解、图解 |
| 影子模式 | 模型照常调用、结果只记录不生效 |
| 回放 / 镜像预览 | 用事件重建学生任意时刻的页面 / 实时只读查看学生当前页面 |
| 软着陆 | 透露额度用完后的出路：回定义、看讲解、先做下一题、求助老师 |
| 诚信信号 | 离开、粘贴、无输入来源、相似度等提示，不等于作弊结论 |
