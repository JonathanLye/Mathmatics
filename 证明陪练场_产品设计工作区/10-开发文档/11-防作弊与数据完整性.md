# 11 · 防作弊与数据完整性

> 已确认的策略：**分模式**——日常练习"记录 + 轻提醒 + 进看板，不锁"；教师设定的测验时段"全屏、关提示、切出 3 次锁题，教师解锁"。
> 本文先说清楚网页能做到什么、做不到什么，再给出具体实现。

## 1. 能做到 / 做不到

| 想要的 | 手机网页（P0） | 微信小程序（P2） | 说明 |
|---|---|---|---|
| 检测切出页面、切到别的 App、锁屏 | ✅ `visibilitychange` | ✅ `onHide/onShow` | 最可靠的信号 |
| 检测窗口失焦（分屏、悬浮窗） | ⚠️ 桌面可用；手机上通知栏、来电都会触发，误报多 | ⚠️ | 手机端只记录，不计入警告 |
| 检测截图 | ❌ 网页完全做不到 | ✅ Android `onUserCaptureScreen`；可用 `setVisualEffectOnCapture('hidden')` 让截屏/录屏变黑 | iOS 小程序只能处理**录屏**（iOS 16+、基础库 3.3.0+） |
| 检测录屏 | ❌ | ✅ iOS `onScreenRecordingStateChanged` | |
| 强制全屏 | ⚠️ Android/桌面可以；**iPhone Safari 不支持网页元素全屏** | 小程序本身全屏 | iPhone 测验降级为"切出计数 + 水印" |
| 禁止复制粘贴 | ✅ 可拦截并记录 | ✅ | 练习只记录，测验拦截 |
| 防止用另一台设备问 AI | ❌ 任何系统都做不到 | ❌ | 只能靠"手写过程证据 + 时间模式 + 相似度"间接发现 |
| 防止改前端代码绕过检测 | ❌ 前端钩子都能被油猴脚本关掉（学习通的切屏检测已有公开的破解脚本） | ⚠️ 难度更高 | 所以**关键判断都放在服务端** |

结论：前端钩子只能提供"大多数学生不会去绕过"的威慑与记录；真正有证据力的是**服务端信号**，尤其是"这一行是怎么写出来的"——手写为主本身就是最好的防作弊：每一行都有笔画、时间、擦改的过程。

## 2. 原则

1. **透明**：首次使用时在同意书里说明会记录什么；测验开始前再提示一次；页面上不搞隐蔽监控。
2. **只记录与提示，不自动处罚**：所有信号进教师看板，由教师判断（可标记"忽略 / 已记录 / 已面谈"）。
3. **服务端为准**：客户端事件标记为 `source=student`，可以伪造；服务端信号基于服务端自己的记录（识别请求、提交时间、作答状态），难以伪造。
4. **少打扰**：练习模式下每次会话只轻提醒一次。

## 3. 客户端信号（诚信 SDK，`apps/student/src/integrity`）

| 信号 | 实现 | 事件 | 练习 | 测验 |
|---|---|---|---|---|
| 页面隐藏/恢复 | `document.visibilitychange` + `pagehide/pageshow` | `integ.visibility{state, awayMs}` | 记录；当次会话第一次回来时轻提醒 | 离开 ≥ 2 秒计 1 次；第 1、2 次警告弹窗；第 3 次锁定 |
| 失焦 | `window.blur/focus`（**仅桌面**） | `integ.blur{awayMs}` | 记录 | 桌面计入次数 |
| 全屏 | Fullscreen API；`fullscreenchange` | `integ.fullscreen{state}` | — | 进入测验时请求全屏；退出 → 遮罩"回到全屏继续"，计 1 次；iPhone → `unsupported` |
| 复制/剪切 | `copy/cut` | `integ.copy/cut{chars}` | 记录 | 拦截（题面文字也禁止复制） |
| 粘贴 | `paste` | `paste{target, chars, blocked}` | 记录，提交时 provenance 记为 `paste` | 拦截 |
| 右键/长按菜单 | `contextmenu` | `integ.contextmenu` | 记录 | 拦截 |
| 敏感快捷键 | `keydown`（Ctrl/Cmd+C/V/P/S、F12、Ctrl+Shift+I） | `integ.shortcut{combo}` | 记录 | 拦截 |
| 开发者工具（启发式，桌面） | 窗口尺寸差、`debugger` 计时 | `integ.devtools{signal}` | 记录 | 记录（不作为锁定依据） |
| 多标签页 | `BroadcastChannel('attempt:<id>')` 互相 ping | `integ.multitab{tabs}` | 记录 | 后打开的标签页只读 |
| 网络 | `online/offline` | `integ.network{online}` | 记录 | 记录（断网期间时间不计入离开） |

上报：事件先进内存队列，每 5 秒或满 20 条批量 `POST /events/batch`；页面隐藏时用 `navigator.sendBeacon` 立即发；失败存 IndexedDB 下次补发。

## 4. 服务端信号（`apps/server/src/integrity`）

| 信号 | 判定 | 分数 | 说明 |
|---|---|---|---|
| `no_provenance` | 提交的文本声称 `ink/photo` 却没有已确认的识别记录；或声称 `keyboard` 但该 `draftId` 的 `kbd.session` 按键数 < 文本长度的 30% 且没有粘贴记录 | 0.6 | 可能是脚本直接调接口 |
| `paste_burst` | 单次粘贴 ≥ 30 字；或一行文本 80% 以上来自粘贴 | 0.5 | |
| `away_long` | 第 3 层离开 ≥ 3 分钟，回来后 60 秒内提交了一个新的关键步骤 | 0.4 | 单次不说明问题，教师看模式 |
| `timing` | 从进入第 3 层到链条闭合 < 该题中位数的 20%，且没有任何提示、没有任何擦改 | 0.4 | |
| `similarity` | 同班两人证明行 canon 后 3-gram Jaccard ≥ 0.9，且完成时间相差 < 20 分钟 | 0.5 | 两人都标记，证据里写对方匿名码 |
| `ai_style`（P1） | Jev noul："这段证明是否像是由 AI 一次性生成的完整证明（格式规整、措辞模板化、一次写出多个关键步骤）？" ≥ 0.8 | 0.3 | 只作参考 |
| `multi_device` | 同一作答 5 分钟内出现两个 deviceId 的事件 | 0.3 | 可能是换设备，也可能是两人共用 |
| `capture`（P2 小程序） | 截屏/录屏事件 | 0.3 | |

作答的诚信提示 = 各信号分数的最大值 + 信号列表。看板上 ≥ 0.5 显示"诚信提醒"标记。阈值在试点第一周后按实际分布调整。

## 5. 两种模式的完整流程

### 5.1 练习模式

```text
进入作答 → （首次）同意书已说明会记录
切出 → integ.visibility(hidden)
回来 → integ.visibility(visible, awayMs)
     → 本次会话第一次：页面顶部淡出提示 3 秒："离开期间的时长会记录给老师，不影响你继续做题。"
     → 之后：不再提示
看板：离开次数与时长；服务端信号 ≥ 0.5 标记"诚信提醒"
```

### 5.2 测验模式

```text
开始前：说明页（规则 + 剩余时间 + "切出 3 次将锁定，需要老师解锁"）→ 学生点"开始"
       → 请求全屏（不支持则记录 unsupported，开启水印）
作答中：求助关闭（或只留概念）；拍照关闭；粘贴拦截；题面禁止选中复制
切出 ≥ 2 秒（visibility hidden 或 桌面 blur 或 退出全屏）→ 计 1 次
     第 1、2 次：弹窗"你已离开 N 次（第 3 次将锁定本题）" → integ.warn
     第 3 次：服务端 attempt.lock → 遮罩"本题已锁定，请联系老师" → 看板出现锁定行
教师解锁：attempt.unlock（计数不清零，阈值 +1）
限时到：自动提交当前内容并结束（服务端计时为准，客户端只显示倒计时）
```

计数在服务端：前端上报的 `integ.visibility` 由服务端累加并决定是否锁定（前端被改也无法"永不锁定"——除非连事件都不上报，而那会触发心跳缺失：测验模式下 30 秒没有任何事件也记 1 次）。

### 5.3 水印（测验模式）

半透明（6% 不透明度）斜向平铺：`匿名码 · 日期 时:分`，每分钟更新时间；用 CSS 背景（SVG data URI）实现，不可选中、不影响点击。目的：截图外传时可溯源，起威慑作用。

## 6. 小程序（P2）

```js
// 做题页 onLoad（注意：不能写在 app.js 里，要写在页面里才生效）
wx.setVisualEffectOnCapture({ visualEffect: 'hidden' })   // Android：截屏/录屏黑屏；iOS 16+：仅录屏
wx.onUserCaptureScreen(() => report('integ.capture', { kind: 'screenshot' }))
wx.onScreenRecordingStateChanged(res => report('integ.capture', { kind: res.state === 'start' ? 'record_start' : 'record_stop' }))  // 仅 iOS
// 页面 onHide/onShow 等价于 visibilitychange
```

## 7. 数据完整性（防"数据造假"）

| 风险 | 对策 |
|---|---|
| 篡改历史 | 事件只追加（触发器 + 权限）；作答状态只由服务端写 |
| 前端伪造服务端事件 | `/events/batch` 只收 `ClientEvent` 类型；服务端事件在状态变化的事务里由服务端写 |
| 重复上报 | 事件 `id` 去重 |
| 客户端时间不准 | 排序与计时一律以服务端为准（`seq`、`tsServer`） |
| 绕过前端直接调接口 | 所有判定在服务端；`no_provenance` 信号；限流 |
| 一人多号 / 代做 | 名单认领（一个学号只能被认领一次）；`multi_device`；同班相似度 |
| 研究数据被选择性删除 | 软删除；删除操作写 `audit_log`；导出带生成时间与行数 |

## 8. 告知文案

同意书"过程监测"一节（白话版）：

> 为了让老师了解你的练习过程，系统会记录：你写下的每一行（包括手写笔迹、识别和修改）、你什么时候求助、看了哪些提示、在每一层停留多久，以及你离开页面的次数和时长。老师可以查看你的作答过程。这些记录只用于教学和（在你同意的情况下）匿名的教学研究，不用于评分处罚。测验模式下，离开页面过多会锁定本题，需要老师解锁。
