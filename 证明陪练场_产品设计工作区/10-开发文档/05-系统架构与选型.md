## 2. 选型

| 层 | 选择 | 理由 | 没选的 |
|---|---|---|---|
| 学生端框架 | **uni-app（Vue 3 + Vite + TS）** | 一套代码现在出 H5、以后出微信小程序；团队靠 AI 写，Vue 与 React 都可以，而 uni-app 离小程序最近；TDesign 有官方 uniapp 1.0 | Taro（React 运行时，小程序包体与性能略逊）；纯 Vue/React H5（以后要重写小程序） |
| 学生端组件 | **TDesign UniApp**（换皮） | 腾讯出品，与微信小程序视觉一致；与教师端 TDesign Vue Next 共用 token | Vant、uView、NutUI（组件可用，但三端无法统一一套 token） |
| 教师端 | **Vue 3 + TDesign Vue Next + ECharts** | 与学生端同栈同 token；表格、表单组件成熟 | Ant Design Vue（风格与学生端不统一）；Cloudflare Kumo（只支持 React，桌面控制台风格可参考） |
| 公式渲染 | KaTeX（H5）、katex-mini（小程序，P2） | 快、可离线、`trust:false` 安全 | MathJax（慢、体积大） |
| 公式编辑 | 自研证明键盘 + 源码/预览（P0）；MathLive（H5，P2） | 自研键盘两端可用；MathLive 依赖 DOM | — |
| 手写渲染 | perfect-freehand（纯函数） | 两端可用 | — |
| 服务端 | **Node 24 + TypeScript + Fastify**（Node 原生类型剥离，直接运行 `.ts`，无构建产物） | 与现有 `server.mjs` 同语言；前后端共享 TS 类型与 engine | Python FastAPI（不能共享 engine；04 技术方案也不建议引入 Python） |
| ORM / 迁移 | P0 薄 SQL 层（dev/test 用 PGlite，生产用 pg），`contracts/schema.sql` 为唯一 DDL；Drizzle 留 P1 评估 | 避免手写第二份表定义；SQL 可控 | Prisma（分区表、触发器支持差） |
| 数据库 | **PostgreSQL 16** | JSONB、分区、触发器、LISTEN/NOTIFY | MySQL（JSON 与分区不便）；Supabase（数据出境与可控性） |
| 队列 | pg-boss（基于 Postgres） | 不多引一个 Redis，3 天内少一个运维点 | BullMQ + Redis（P2 量大时再说） |
| 实时 | SSE + Postgres LISTEN/NOTIFY | 单向推送足够，穿透代理简单 | WebSocket（双向用不上） |
| 契约 | OpenAPI 3.1 + JSON Schema；`openapi-typescript` 生成前端类型；服务端用 Ajv 2020 直接按 OpenAPI schema 校验请求，契约测试校验响应 | 三端一份真相 | 手写类型 |
| 部署 | Docker Compose + Caddy（自动 HTTPS） | 单机够用，1 小时可重建 | K8s（过度） |

## 3. 代码边界

- `packages/contracts`：只有数据与生成的类型，无逻辑（`tools/` 里的参考实现除外）。
- `packages/engine`：**纯函数**，不读数据库、不发网络请求、不读时钟（时间由参数传入）。服务端、教师端回放、测试共用。
- `packages/ui-math`：Vue 组件，不调用接口；数据通过 props 进、事件出。
- `apps/server` 是唯一能读 `vault` 的地方；`apps/teacher` 通过教师接口拿完整题目包（审核用）。

## 4. 策略核心 packages/engine

### 4.1 事件溯源

作答状态由**领域事件**折叠而成：

```ts
init(pub: PublicPart, meta): EngineState
decide(state: EngineState, pkg: PackageV1, cmd: Command, ctx: { now: number; model?: ModelAdvice }): { events: DomainEvent[]; outbound: Outbound[] }
apply(state: EngineState, ev: DomainEvent): EngineState        // 只读事件 payload，不读题目包
replay(pub, meta, events) = events.reduce(apply, init(pub, meta))
toStudentView(state, pub, notes): AttemptState                  // DTO 白名单投影（openapi AttemptState）
```

- `Command`：`SubmitDefinition`、`SubmitFramework`、`AddLine`、`EditLine`、`DeleteLine`、`Finish`、`AnswerSelfcheck`、`StartTransfer`、`SubmitSummary`、`EnterLayer`、`SkipLayer`、`Help{intent,text,lineId}`、`ClaimHint{token}`、`FlagTeacher`、`Park`、`IntegritySignal`、`Unlock`。
- `DomainEvent` 就是 `events.schema.json` 里 `source=server` 的那些类型（`def.submit`、`line.submit`、`hint.deliver`、`layer.done` …），payload 必须包含 `apply` 需要的全部信息（例如 `line.submit` 带 `keys/newKeys/cls`，`hint.deliver` 带 `revealAfter`）。这样**回放不需要题目包保密部分**，教师端也能回放。
- `Outbound`：要发给学生的文本（通道、文本 ID、原文、允许的关键步骤），由服务端过闸门后写成 `annotation` / `hint.deliver` 等事件的附带记录（`app.annotations.text_shown`、`app.hint_deliveries.text_shown`）。
- 模型建议只能通过 `ctx.model` 进入 `decide`，`decide` 决定用不用（P0：归类只用规则，模型建议写进事件的 `jevShadow`）。

### 4.2 引擎内部状态

```ts
interface EngineState {
  v: 1; attemptId: string; problemId: string; version: number; kind: 'main' | 'transfer'; mode: 'practice' | 'test';
  layer: LayerId; layerStatus: Record<LayerId, 'locked' | 'active' | 'done' | 'skipped' | 'disabled'>;
  def:   { submissions: number; passed: boolean; lessonSuggested: boolean; lastLineId?: string };
  frame: { submissions: number; passed: boolean; templateShown: boolean; lastLineId?: string };
  lines: Array<{ id: string; n: number; keys: KeyId[]; cls: string; flagged: boolean; demoPending?: KeyId; deleted: boolean }>;
  matched: KeyId[];                    // 学生自己写出的关键步骤（H4 示范过的，写出依据后才计入）
  demoShown: KeyId[];                  // 已用 H4 示范的关键步骤
  hintLv: Record<KeyId, number>;       // 每步下一条提示的级别 0–4
  keyCost: Record<KeyId, number>;      // 每步已到达的最高透露量（0 / 0.5 / 1）
  reveal: number;                      // Σ keyCost，≤ budget.reveal
  lastHintAt: number | null; submitsSinceHint: number; hintTimes: number[]; rapidLockUntil: number | null;
  noProgress: number; lastProgressAt: number; stuckOffered: boolean;
  exhausted: boolean; flaggedTeacher: boolean;
  teacherOverride: KeyId[];            // 额度耗尽后经教师授权补发的 H4（本题不计独立完成）
  selfcheck: Array<{ id: string; line: number | null; status: 'open' | 'accepted' | 'followup' }>;
  summary: { followupAsked: boolean; done: boolean };
  transfer: { childAttemptId?: string; status: 'not_started' | 'active' | 'completed' | 'skipped' };
  integrity: { warnings: number; locked: boolean; awayCount: number; awayMs: number };
  completedAt?: number;
}
```

规则细节（与 v3 一致，05 §4.2）：

- 透露量：每个关键步骤按已到达的最高一级计（H2=0.5、H3/H4=1），全题求和；H3 与 H4 落在同一步骤只算 1。
- 升级门槛（H2 起）：`submitsSinceHint ≥ 1`；`now − lastHintAt ≥ dwellSec`；30 秒内 3 次请求 → `rapidLockUntil = now + 60s`。服务端只读可信状态，不读学生文本。
- 预算：`reveal + delta > budget` → 拒绝，`exhausted = true`，返回软着陆选项。
- 额度耗尽的唯一出口：教师 `unlock` 时可带 `grantH4`（06 §3.6），`decide` 允许下发一次 H4（`hint.deliver.override=true`），不再增加 `reveal`，写入 `teacherOverride`；完成判据允许闭合，但 `attempt.complete` 带 `teacherOverrides`，指标层不计入"独立"。
- H4 示范：`demoShown` 中的步骤，学生再写出时若依据 < 6 字，归类为 `demo_needs_reason`，不计入 `matched`。
- 改行与删行：`matched` 永远等于"所有未删除行命中的关键步骤之并"（H4 示范规则照样适用）。改行会重新归类，`line.edit` 事件带 `keys/newKeys/lostKeys`；删行的 `line.delete` 带 `lostKeys`。`keysOwn` 可能因此减少，完成判据重新计算；但 **`keyCost` 与 `reveal` 永不减少**（提示已经看过了）。
- 卡住：`noProgress ≥ 2 && now − lastProgressAt > stuckMs` → `stuckOffered = true`（界面温和询问，不自动给提示）。
- 完成判据：任一路线的关键步骤全部在 `matched` 中，且学生点了"写完了"。

### 4.3 测试

- `CANON_CASES` 回归；v3 三个演示场景（独立完成 13 步、中档 23 步、需要不断指点 27 步）改写为场景测试，事件序列逐条断言。
- 性质测试（fast-check）：任意命令序列下 `reveal ≤ budget`；`replay(events) == state`；任何 `Outbound` 在闸门规则层下不含未透露片段。

## 5. 一次"加入证明"的完整流程

```text
POST /attempts/{id}/lines  {statement, justification, input:{provenance:'ink', recogId, draftId}}  Idempotency-Key, If-Match
1. 鉴权、同意书、作答归属、作答状态（未锁、布置未关闭）、If-Match 版本
2. 校验 recogId 已确认且属于本作答；provenance 与记录一致（否则记 no_provenance 信号，但不阻止）
3. canon(statement + 依据)
4. （并行，带超时）Jev 归类 → ctx.model（P0 仅影子）
5. engine.decide(state, pkg, AddLine, ctx) → events: [line.submit, annotation, (proactive.offer)]，outbound: [批注文本]
6. 闸门处理 outbound（规则 → 格式 → Jev → Qwen，fail-closed；见 09 §7）；被拦 → 回退文本 + gate.block 事件
7. 事务：插 attempt_lines、annotations、events（seq = ++last_event_seq）、更新 attempts.state/state_version/reveal/keys_own
8. NOTIFY class_{classId}（看板）与 attempt_{id}（镜像）
9. 返回 { state: toStudentView(...) }
```

## 6. 实时

- 服务端维护 SSE 连接表；Postgres `LISTEN class_*`、`attempt_*`；事务提交后 `NOTIFY`，载荷只带 ID 与 `state_version`，SSE 推送前再查一次权限与数据。
- P0 单实例；P2 多实例时 NOTIFY 天然广播到所有实例。
- 心跳 20 秒；客户端断线重连带 `Last-Event-ID`。

## 7. 安全

| 项 | 做法 |
|---|---|
| 会话 | `pg_sid` HttpOnly、Secure、SameSite=Lax；学生 30 天、教师 12 小时；登出即作废 |
| CSRF | SameSite=Lax + 写接口要求 `X-Requested-With: proof-gym` 头 |
| 限流 | 登录：同 IP 10 次/分、同邀请码失败 5 次锁 10 分钟；识别、求助、生成按 09 §10 |
| 输入校验 | 所有请求体用由 OpenAPI 生成的 zod 校验；MathText 长度上限；KaTeX `trust:false` |
| DTO | 学生响应只经 `toStudentView` 投影；契约测试做泄露扫描 |
| 个人信息 | 学号、姓名 AES-256-GCM 加密（密钥在环境变量/KMS）；学号登录匹配用 HMAC-SHA256 + pepper；日志不打学号姓名；IP 存掩码（IPv4 /24，IPv6 /48） |
| 题目包 | `vault` schema 单独授权；参考证明读取写 `reference_access_log` |
| 镜像令牌 | HS256 签名，5 分钟，绑定教师与作答 |
| CSP | `default-src 'self'`；图片允许 `data:` 与对象存储域名；禁止内联脚本（KaTeX 不需要） |
| 密钥 | 只在服务器环境变量；90 天轮换；前端不持有任何模型或 OCR 密钥 |
| 审计 | 教师/管理员的导出、改判、解锁、参考证明读取、开关切换写 `audit_log` |

## 8. 部署（P0）

### 8.1 拓扑

一台香港云主机（4 vCPU / 8 GB / 100 GB SSD，带宽 ≥ 10 Mbps；选香港是为了免 ICP 先上线，风险见 13 号文档），Docker Compose：

| 服务 | 镜像 | 说明 |
|---|---|---|
| caddy | caddy:2 | 自动 HTTPS；`/` → 学生端静态文件；`/t/` → 教师端静态文件；`/api/` → server |
| server | 自建 node:24-slim（Node 原生运行 TypeScript） | 2 个进程（cluster）即可支撑 120 人同时在线 |
| worker | 同镜像不同入口 | 识别队列并发 = SimpleTex 已购 QPS |
| postgres | postgres:16 | `shared_buffers=2GB`；数据卷单独挂载 |
| lean（可选） | 自建，含 elan + mathlib 缓存 | 只给教师端审核用，可放教研室本机（沿用 `LEAN_PROJECT`） |

### 8.2 环境变量（`.env.example`）

```text
NODE_ENV=production  PUBLIC_ORIGIN=https://…  DATABASE_URL=postgres://…
SESSION_SECRET=…  PII_KEY=…(32字节 base64)  STUDENT_NO_PEPPER=…  MIRROR_TOKEN_SECRET=…
JEV_BASE_URL=…  JEV_API_KEY=…  DEEPSEEK_API_KEY=…  DASHSCOPE_API_KEY=…
SIMPLETEX_APP_ID=…  SIMPLETEX_APP_SECRET=…
STORAGE_DIR=/data/files   (P1 换 S3 兼容对象存储)
DAILY_COST_ALERT_CNY=50  DAILY_COST_CUTOFF_CNY=100
ALERT_WEBHOOK=…(企业微信/飞书机器人)
```

### 8.3 备份与恢复

- `pg_dump -Fc` 每 6 小时一次，保留 30 天；上传到另一地域的对象存储。
- 上传文件（照片、大笔迹）每日同步。
- 恢复演练：Day 2 一次、之后每月一次；目标恢复时间 < 2 小时、数据丢失窗口 < 6 小时。

### 8.4 监控与告警

- `/health`：数据库、队列、各外部依赖、开关状态。外部探活每分钟一次。
- 告警（webhook）：5xx 比例 > 2%（5 分钟）；识别 P95 > 8 秒；队列积压 > 50；任一模型错误率 > 20%；日花费超阈值；磁盘 > 80%。
- 日志：pino JSON，保留 14 天；不含学号、姓名、学生原文（原文在数据库里，有权限控制）。
- 前端错误：`sys.error` 事件 + 采样上报。

## 9. 容量估算

| 项 | 估算 |
|---|---|
| 同时在线 | 60–120 人（一个到两个班） |
| 写请求 | 峰值约 5 次/秒（每人每 20 秒一次提交/求助） |
| 事件 | 每次作答约 300–600 条；一学期 3,000 次作答 ≈ 150 万条，按月分区足够 |
| 笔迹 | 每行约 5–20 KB（gzip）；每次作答约 0.5 MB；一学期约 1.5 GB |
| 照片 | 每张 ≤ 2 MB；按每生每周 3 张估算，一学期约 10 GB（P1 迁对象存储） |
| 识别并发 | 60 人同时写时约 2–4 次/秒 → 需 SimpleTex QPS 包或 Qwen 分流 |

## 10. 小程序与境内迁移（P2）

- 学生端加 `mp-weixin` 编译目标；`src/platform/` 补小程序实现（存储、网络、截屏 API、公式渲染）。
- 登录改为微信登录 + 首次绑定学号（服务端增加 `wechat_openid` 映射表）。
- 诚信：`wx.setVisualEffectOnCapture({visualEffect:'hidden'})`（Android 截屏/录屏黑屏；iOS 16+ 仅录屏）、`wx.onUserCaptureScreen`、`wx.onScreenRecordingStateChanged`（iOS）、`onHide/onShow`。
- 小程序要求业务域名 ICP 备案，服务器迁到境内；Jev 云服务涉及出境，届时评估换成自部署的 Jev 同类开源模型（如 Ollama 提供的 `/v1/systemone` 接口，接口形态相同）。
