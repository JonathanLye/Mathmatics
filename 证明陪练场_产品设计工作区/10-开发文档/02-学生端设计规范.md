# 02 · 学生端设计规范

> 适用：`apps/student`（uni-app，P0 编译 H5，P2 编译微信小程序）、`packages/ui-math`。
> 手机第一，平板第二，电脑第三。所有页面在 390 / 768 / 1280 三个宽度都要验收。

## 0. 视觉改版 v3「自有青绿系」（2026-11-06，现行）

> **本节优先于 §1 与 §2.1–§2.3 中与之冲突的内容**（纸与红笔、暖白纸色、红=批注），也取代此前的 v2「厚边积木」一节（其配色、动效上限与吉祥物限制作废）。§1 保留作历史取舍记录。只改观感（排版、色彩、动效、音效、图标、吉祥物），不改契约、引擎与业务规则（AttemptState 只渲染原则不变）。游戏化的产品规则见 00 U14 与 01 §7、§10。

- **语言**：沿用硬下沿（无模糊阴影）、2px 描边、圆角 12/16/24 的形状语言；配色换成**自有青绿系**：以青绿为主操作与完成色，配一套自选的辅助色（助教的话、会计入透露量的提示与预算、求助、强调）。**具体色值只以 token 文件为准，本文不再抄录**。字体：Nunito（`@fontsource/nunito` 自托管）+ 系统中文粗体（不加载中文 webfont）；公式仍用 KaTeX/衬线。
- **token 的权威位置**：`packages/ui-tokens/tokens.css`（后续任务创建；亮/暗/`html[data-theme]` 三处同值）。学生端与教师端都从它引用，不再各存一份；在它建成之前，现有的 `apps/student/src/styles/tokens.css` 与 `apps/teacher/src/styles/theme.css` 仍是临时来源。
- **不使用多邻国的品牌资产**：不用其猫头鹰形象、Feather 字体、品牌绿等品牌色与图形；游戏化只借通用机制（经验、连胜、目标、徽章），视觉与形象全部原创。
- **吉祥物（原创「∎ 小方」，QED 方块加表情）**：全程陪伴（首页、做题页、微课、完成页、空状态），随进度与停顿换表情；原“只用于空状态、登录、微课反馈和完成页”的限制撤销。连胜、经验、每日目标、徽章可做（规则见 01 §7）；仍无扣命、无公开排行。吉祥物不替代追问，也不在证明行上出现“对/错”表情。
- **首页**：学习路径（done / 当前层 / todo / 锁定灰）；节点状态只映射真实字段（`done`、`inProgress`+`currentLayer`、`todo`/`open`、`scheduled|closed|cancelled`）；游戏化数字（经验、连胜、每日目标）同样只展示服务端给的值。
- **动效与音效**：原“动效 ≤700ms”“循环动画只允许有限次数”的限制撤销，可以做更丰富的庆祝与过渡。**动效与音效都必须能关**：设置里有独立开关；`prefers-reduced-motion` 下自动关闭动效（只保留不动的状态变化）；音效默认由用户设置决定、首次交互前不自动播放；**测验模式一律无音效、无游戏化展示**。
- **语义色**：主色（青绿）= 主操作/完成；助教的话 = 一种冷色（`--margin`）；会计入透露量的提示与预算 = 一种暖黄；求助与危险操作 = 红系；证明行上仍**不出现红叉、红色错误徽标**（红只用于微课小核验答错和求助，不用于证明行）。
- **可访问性**：对比度要求不变——按钮文字与正文 ≥4.5:1（主色底上是否用深色字由对比度决定，不是预设白字）；`apps/student/tests/dark-mode.test.ts` 以 token 对比度断言守住（#164）。
- **图标/吉祥物资源**：`packages/ui-math/src/design/icons.ts`（学生、教师端共用）；H5 用 v-html 内联 SVG，**小程序端尚未验证**。

## 1. 设计方向："纸与红笔"

学生打开的不是一个聊天机器人，而是**一张证明稿纸**：题面在上，自己写的证明一行一行往下排，助教的红笔批注写在这一行旁边。沿用 v3 原型已经验证过的视觉语言，在 TDesign 组件之上换掉默认皮肤，避免"一看就是某某模板"的感觉。

参考取舍：

| 参考 | 学什么 | 不学什么 |
|---|---|---|
| v3 原型（08） | 稿纸 + 页边批注的结构；衬线题面；克制配色 | 桌面优先的三栏在手机上直接堆叠（批注跑到页面最下面，离输入太远） |
| TDesign（腾讯） | 移动端组件的交互细节（弹层、Toast、Cell、Steps）；有 uniapp / 小程序 / 桌面四个 1.0 版本，三端同一套 token | 默认蓝色主题、默认圆角卡片堆叠的观感 |
| Cloudflare Kumo | 语义色 token 的组织方式；信息密度与留白的平衡（教师端尤其） | 它是 React + 桌面控制台，学生端不直接用 |
| Brilliant / Khan Academy | 交互图解后立刻跟一道小核验；提示有代价时先告知 | 游戏化、连胜、吉祥物 |

**防疲劳要点**：暖白纸色背景而不是纯白；正文 16px、行高 1.65；一屏只有一个主操作；颜色只用于表达含义（见 §2.2）；动效短且可关；完整深色模式。

## 2. 设计 token

### 2.1 颜色

所有颜色用 CSS 变量（小程序端用同名 page 级变量），并映射到 TDesign 的 `--td-*` 变量：

| token | 浅色 | 深色 | 映射 / 用途 |
|---|---|---|---|
| `--paper` | `#F7F6F2` | `#12161D` | 页面背景；`--td-bg-color-page` |
| `--sheet` | `#FFFFFF` | `#1A1F28` | 稿纸、卡片、输入框；`--td-bg-color-container` |
| `--ink` | `#1D2430` | `#E4E8EF` | 正文；`--td-text-color-primary` |
| `--ink-2` | `#5D6878` | `#9AA5B5` | 次要文字；`--td-text-color-secondary` |
| `--rule` | `#E2E4E8` | `#2C3442` | 分隔线、格线；`--td-component-border` |
| `--accent` | `#2B4FA3` | `#8FB0FF` | 主操作、当前层、链接（墨蓝）；`--td-brand-color` |
| `--accent-soft` | `#E8EEFB` | `#1F2B45` | 当前层底色、系统消息底色 |
| `--margin` | `#9A3B4F` | `#E58AA0` | **只用于批注**（红笔） |
| `--margin-soft` | `#F7ECEF` | `#33202A` | 批注底色 |

| `--ok` | `#2F7A54` | `#6FCF9B` | "衔接上了"、层完成；`--td-success-color` |
| `--focus` | `#2B4FA3` | `#8FB0FF` | 焦点环 2px |

### 2.2 颜色语义规则

- **红色只表示"助教在这一行有一个问题想问你"**，不表示"你错了"。证明行上不出现红叉、红色错误徽标。
- 琥珀色只出现在"会计入透露量"的地方（H2–H4 提示、预算条、预览卡），让学生一眼看出"这条有代价"。
- 绿色只用于"衔接上了""本层完成""本题完成"。
- 不用纯黑、纯红、高饱和蓝绿。

### 2.3 字体与排版

| 角色 | 字体栈 | 字号（手机 / 桌面） | 用途 |
|---|---|---|---|
| 题面、层标题 | `"Noto Serif SC","Songti SC","SimSun",serif` | 17 / 17，层标题 16 粗 | 像教材 |
| 正文、证明行 | `"Noto Sans SC","PingFang SC","Microsoft YaHei",system-ui,sans-serif` | 16 / 15 | 行高 1.65，最长 62 字/行 |
| 输入框 | 同正文 | **16（防 iOS 自动缩放）** | |
| 行号、预算、元信息 | `"IBM Plex Mono",ui-monospace,monospace` | 12–13 | 数字等宽 |
| 公式 | KaTeX（自带字体，按需加载） | 跟随所在文字，系数 1.05 | 所有数学都渲染，不显示 LaTeX 源码 |

字体不从外网加载（系统字体 + 本地 KaTeX 字体），首屏不等字体。

### 2.4 间距、圆角、阴影、动效

- 间距：4 / 8 / 12 / 16 / 24 / 32（px；uni-app 内写 rpx，按 750 设计稿换算）。手机左右安全边距 `max(16px, env(safe-area-inset-left))`。
- 触控目标 ≥ 44×44；相邻按钮间距 ≥ 8。
- 圆角：输入框/按钮 6，卡片 10，底部弹层顶角 16。
- 阴影：只有底部操作坞和弹层用一层淡阴影；稿纸靠分隔线，不靠阴影。
- 动效：150–200 ms ease-out；批注出现用 120 ms 淡入；`prefers-reduced-motion` 时全部关闭。

## 3. 布局

### 3.1 手机（< 600px）：单栏 + 底部操作坞

```text
┌──────────────────────────────────┐ ← safe-area-top
│ ‹  数列极限 · ε-N       ●●◉○○○  L3 │ 顶栏：返回、题名、6 点进度（点开 = 层列表弹层）
├──────────────────────────────────┤
│ 用 ε-N 定义证明 lim (3n+1)/(n+2)=3 │ 题面：默认展开；向上滚动后收成一行"看题"胶囊
├──────────────────────────────────┤
│ 构造与推导                          │ 层标题（衬线）
│ 每次写一行：结论 + 依据。顺序由你决定。  │ 任务说明（≤ 2 行）
│                                    │
│ 1  |aₙ−3| = 5/(n+2)            ✍  │ 证明行：行号 · 结论 · 来源徽标
│    依据  通分                        │ 依据（次要色小字）
│  ┃ 第 1 行和前面衔接上了。             │ 行内批注（红笔左边线；"衔接上了"用绿色边线）
│ 2  5/(n+2) < 5/n                ✍  │
│    依据  （未写）                     │
│  ┃ 依据没写。它由哪条定义或已证结论得到？ │
│                                    │
│ [ ＋ 写下一行 ]          [ 写完了 ]   │
├──────────────────────────────────┤
│ 透露 0.5 / 2   ·   自己写出 1 / 4     │ 预算条（点开看解释）
├──────────────────────────────────┤ ← 底部操作坞：固定在底部，键盘弹出时上移
│  ✍ 手写   ⌨ 键盘   📷 拍照     [ 求助 ] │ 输入方式切换 + 求助（拇指区右侧）
└──────────────────────────────────┘ ← safe-area-bottom
```

要点：

- 批注**跟着行走**（行内），不再像 v3 那样堆在页面最下面。最新一条批注出现时，页面自动滚到该行并短暂高亮。
- 底部操作坞只放两类东西：输入方式、求助。"写完了""核对"之类的提交按钮放在内容流里，避免误触。
- 层列表弹层：六层逐项（已完成 ✓ / 进行中 / 跳过 / 未解锁），可跳的层显示"已掌握，跳过"。
- 题面过长（级数题）时折叠为两行 + "展开"。

### 3.2 平板（600–1023px）：稿纸 + 页边

```text
┌─────────────────────────────────────────────────────────┐
│ ‹ 数列极限 · ε-N   ① 记忆核验 ✓ ② 骨架 ✓ ③ 构造与推导 ④ ⑤ ⑥   │ 层导航横排
├───────────────────────────────────┬─────────────────────┤
│ 题面                               │ 页边（批注 / 求助）      │
│ 构造与推导                          │ ┃ 第 2 行：依据没写……   │
│ 1 …                               │ ┃ H2 · 透露 0.5        │
│ 2 …                               │   通分以后……           │
│ ┌──────────── 手写区（笔）────────┐ │ ───────────────     │
│ │                                │ │ [卡住了][不懂][看这行]  │
│ └────────────────────────────────┘ │ 问一句…  [发送]        │
│ [识别]  [⌨]  [📷]                   │ 透露 0.5/2 · 1/4       │
└───────────────────────────────────┴─────────────────────┘
```

- 触控笔可以直接在稿纸下方的手写区写，不必进入全屏（`pointerType === 'pen'` 时只认笔，手掌触摸忽略）。
- 页边栏固定（sticky），批注同时在行内用一个红点标出，点红点滚到页边对应条目。

### 3.3 电脑（≥ 1024px）：三栏（沿用 v3）

左 220px 层目录与预算 | 中 稿纸（最大 720px）| 右 320px 页边。最大总宽 1280px 居中。键盘输入为主，手写区保留（触屏笔记本）。

## 4. 关键界面

### 4.1 登录与同意

- 登录：两个输入框（邀请码 6 位、学号）+ 一个按钮。邀请码可从链接参数带入，学生只需填学号。
- 同意页：五段（服务所需 / 香港服务器存储 / 境外决策模型 / 过程监测 / 教研使用），必选三段直接勾选并标"必选"，两段可选用开关、默认关；每段 2–3 句白话 + "展开全文"。底部固定按钮"同意并开始"。不同意必选项时说明"不能使用练习功能，可联系老师"。

### 4.2 首页

```text
  交错级数 · 收敛性   周五 23:59 截止      [开始]

```

### 4.3 做题页各层

| 层 | 主体 | 主按钮 | 次按钮 |
|---|---|---|---|
| L1 记忆核验 | 任务说明 + 一个输入区（默认手写） | 核对 | 看不懂（打开微课）、已掌握，跳过 |
| L1 微课 | 全屏步骤页：顶部"第 2 / 5 步"，卡片文字 + 图解 + 小核验（单选） | 下一步（答对后可点） | 返回题目 |
| L2 证明骨架 | 同 L1 | 核对 | 看通用骨架、看骨架讲解、跳过 |
| L3 构造与推导 | 证明行列表 + 写下一行 | 加入证明（在编辑器内）、写完了 | — |
| L4 自检 | 只读的证明 + 3 道题（每题一个输入区，题目里的行号可点击跳到该行） | 提交自检 | 跳过 |
| L5 迁移题 | 新题面 + 与 L3 相同的编辑区（子作答） | 同 L3 | 跳过（推荐下一题） |
| L6 总结 | 五问，每问一个短输入区（默认键盘） | 提交总结 | — |
| 完成 | "本题完成"；自己写出 x / n；用了哪些提示；mathlib4 对照（只列定理名）；"加入证明本" | 回首页 | 做迁移题 / 下一题 |

### 4.4 写一行（行编辑器）

点"写下一行"后，手机（<600px）从底部升起行编辑器；平板/电脑（≥600px）用居中的对话框卡片，**不做稿纸内联展开**（2026-11-03 PR #90 复审决策：保持组件内的居中卡片实现，以本节与 `apps/student/src/components/README.md` 为准）：

```text
┌ 第 3 行 ───────────────────────────────┐
│ 这一行  [✍ 写] [⌨ 打] [📷 拍]            │
│ ┌──────────────────────────────────┐  │
│ │ （识别确认后的公式预览）              │  │
│ └──────────────────────────────────┘  │
│ 依据    [✍] [⌨]                       │
│ ┌──────────────────────────────────┐  │
│ │                                  │  │
│ └──────────────────────────────────┘  │
│                        [取消] [加入证明] │
└───────────────────────────────────────┘
```

- "依据"默认键盘（多为中文短句，配"证明句式"层），"这一行"默认手写。
- "加入证明"在"这一行"为空时禁用；依据可空（服务端会追问）。
- "这一行"和"依据"是两个独立输入落点，各自带 `provenance` 与 `draftId`（03 §1）；依据非空时提交必须同时带 `justificationInput`。
- 平板/电脑的批注正文在页边栏（§3.2），行内只保留颜色标记，不在两处各渲染一遍全文。

### 4.5 全屏手写

手机上点 ✍ 进入全屏（提示"横过来写更舒服"，不强制）：

```text
┌──────────────────────────────────────────────────────┐
│ 写"这一行"       ↶  ↷  ⌫橡皮  🗑清空         取消  识别 ▶ │
│──────────────────────────────────────────────────────│ ← 淡格线（两条基线，提示书写高度）
│                                                      │
│──────────────────────────────────────────────────────│
│ 小提示：写错了直接划掉（来回涂抹）即可删除                  │
└──────────────────────────────────────────────────────┘
```

- 画布高度按横屏可视高度的 60% 计；内容超出时横向自动续写（向左平移）。
- 划掉删除：来回涂抹覆盖已有笔画 → 删除被覆盖笔画（03 §2.4）。
- 识别中显示"识别中…"，超过 3 秒显示"还在识别，也可以先用键盘"。

### 4.6 识别确认

```text
识别结果 · 请核对
  |aₙ − 3| = 5/(n+2)                  ← KaTeX 渲染，大号
  ⚠ 这一处两种识别不一致： 5/(n+2) ｜ 5/(n+z)    [选左][选右]
  [✍ 重写]   [⌨ 改一下]             [确认 ✓]
```

- 两路结果一致且置信度高：直接显示，单按钮"确认"。
- 不一致：高亮差异片段，让学生选或改。
- 识别不出：说"没认出来，再写一次，或者用键盘"。
- 识别结果**永远不替学生改正**；界面文案也不暗示对错。

### 4.7 证明键盘

替换系统键盘（输入框 `inputmode="none"`），高度取 max(38vh, 360px)：大屏约屏高 38%，**844 屏上因 360px 下限约 43%**（2026-11 修订，原写"约 38%"）。360px 下限是因为右侧固定一列 7 个动作键、每个触控目标 ≥ 44px，再压缩会掉到 44px 以下。分层标签：常用 / 证明句式 / 关系·集合 / 希腊 / 函数·分析 / 123。右侧固定一列动作键：← → ⇥（跳到下一个占位）⌫ 中（切系统键盘写中文）✍（改手写）完成。长按出变体（如 `<` 长按出 `≤ ≪`）。布局数据见 `contracts/keyboard-layout.json`，说明见 03 §4。

### 4.8 求助抽屉与提示预览

见 01 §4 的线框。预览卡：

```text
┌ 下一条：方向提示（H2） ───────────────┐
│ 会计入透露 0.5。你已用 0.5 / 2。          │
│ 领取后，下一级要等你再写一行、并停留 20 秒。  │
│              [先不要]   [领取]          │
└────────────────────────────────────┘
```

- 琥珀色边框。H0/H1（不计透露量）不弹预览，直接显示。
- 不能领取时说明原因和剩余秒数（倒计时），按钮置灰。
- 额度用完：卡片换成四个出路按钮（回定义 / 看讲解 / 先做下一题 / 求助老师）。

### 4.9 微课与图解

- 一步一屏（手机）或一卡（平板/电脑）。顶部步骤点，底部"上一步 / 下一步"。
- 图解区高度 ≥ 屏宽 × 0.6；滑块放在图的**下方**（手指不遮住图）；滑块旁实时显示数值（等宽字体）。
- 小核验答错：卡片下方出现一句引导（红笔样式），可重选；答对：绿色"对"+ 一句解释，"下一步"变为可点。
- 图解组件见 03 §7。

## 6. 键盘与视口

- 根元素 `min-height: 100dvh`（回退 `100vh`）；固定元素加 `env(safe-area-inset-*)`。
- 软键盘弹出：用 `visualViewport` 计算被遮挡高度，写到 `--keyboard-inset`；底部操作坞与行编辑器 `bottom: var(--keyboard-inset)`；键盘打开时隐藏操作坞的输入方式按钮，只留"完成"。阈值 80px 区分键盘与工具栏伸缩。
- 证明键盘打开时系统键盘不出现；切到"中"时反之。
- `viewport` 不禁用缩放（不写 `user-scalable=no`），输入框 16px 防止 iOS 聚焦缩放。

## 9. 小程序迁移约束（现在就遵守）

- 业务代码只用 uni API（`uni.request`、`uni.getStorage`、`uni.createSelectorQuery`），不直接用 `window` / `document` / `localStorage`；确需浏览器 API 的（KaTeX DOM 渲染、MathLive、`visualViewport`、`Fullscreen API`、`BroadcastChannel`）放在 `#ifdef H5` 条件编译块，并在 `src/platform/` 提供小程序替代实现或空实现。
- 公式渲染组件 `<MathText>` 对外接口固定为 `text: MathText`；H5 用 KaTeX 输出 HTML，小程序用 katex-mini 输出 rich-text nodes（P2）。
- 手写画布用 `canvas type="2d"`，绘制逻辑写成与平台无关的纯函数（输入笔画、输出绘制指令）。小程序端逻辑层与视图层通信有开销，P2 时评估是否改为在 web-view 里运行手写页。
- 不使用 TDesign UniApp 之外的 UI 库；不使用只在 H5 可用的 CSS（如 `:has()`）做关键布局。
- 网络请求统一经过 `src/api/client.ts`（封装 Cookie/Token 差异：H5 用 Cookie，小程序 P2 改为 `Authorization` 头）。
- 包体：主包只放登录、首页、做题页；微课、证明本、图解放分包。
