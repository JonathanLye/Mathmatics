## 0. 一页纸结论

1. **国内产品（豆包爱学、作业帮）赢在「拍照即得答案」，学生用它们的动机跟我们完全相反**——我们要的不是「更快得到答案」，而是「更愿意自己写」。抄它们的输入体验（拍照/结构化），**不抄它们的闭环目标**。
2. **Khanmigo 是「不给答案」路线里最成熟的商业参照**：苏格拉底式追问 + 教师/家长可见对话。它的口碑风险（有时答非所问、成本高）正是我们要用「单题深度 + 教师审核题库」来对冲的。
3. **OATutor 是目前最值得抄「提示机制」的开源实现**：hint 按顺序解锁、后一条提示依赖前一条、有「到底提示（bottom-out）」、还有「用了提示是否扣分」的三档策略。**这些几乎可以一一映射到我们的 L0–L4 与提示预算。**
4. **interactive-proof 最值得抄「交互形态」**：选中一段就提问、提供「更简单」档位、答完给两个下一步动作、还有证明依赖图。它的「选中即锚定」正好对应我们「必须引用学生原话 ≥3 字」。
5. **SocraticMath / Lea / ScaffoldLM 是研究参考，不是产品参考**：一个给数据集与四阶段策略，一个是 Lean 形式化证明 IDE（重、许可有问题），一个是最新 ACL 论文的「规划+记忆」提示框架（二手，需验证）。
6. **我们的空位很清楚**：**「分步写 + 只指第一处可疑 + 最小提示阶梯 + 教师过程数据」** 这个组合，国内产品不做（它们要答案），开源项目要么是选择题式 ITS（OATutor），要么是论文/Lean 阅读器（interactive-proof/Lea）。**这是可讲的差异化。**

**证据等级**：本文件统一标 **[已核实]**（我打开并读过源码/网页原文）与 **[二手]**（检索摘要、项目自述、未读全文）。标 **[待验证]** 的不要进对外材料。

## 2. 逐个拆解

### 2.1 豆包爱学（字节跳动，国内 AI 学习 App）

**它是什么**：面向学生的 AI 学习助手，主打拍照/输入题目后讲解、口语化答疑、生成同类练习。[二手] App Store 页面：https://apps.apple.com/cn/app/id6469102455 ；应用宝页面：https://sj.qq.com/appdetail/com.aitutor.hippo

**学生使用流程（推断，二手）**
1. 打开 App → 拍照或输入题目；
2. AI 识别后**直接给出讲解**（通常包含完整解题过程）；
3. 学生追问「为什么」「再讲简单点」；
4. 可能生成同类题/知识点卡片；
5. 结束。

**提示/反馈机制**：以「讲懂这道题」为目标，允许完整讲解；追问是自由对话，不限制提示轮次，不给「最小提示」。**这正是我们红线禁止的形态。**

**做得好的**
- 输入门槛极低（拍照/语音），学生不用打字；
- 语言口语化，符合「看不懂教材」的学生需求；
- 反馈即时，不会让学生等。

**不适合我们的**
- **目标函数相反**：它优化「这道题会不会做」，我们优化「下次能不能自己做」；
- 完整讲解会直接破坏我们的核心指标（独立完成）；
- 自由对话没有「阶段、预算、拒绝模板」，无法保证红线。

**可借鉴的交互点（落到契约）**
- S3 草稿区的**语音/拍照输入**（本轮不做，但可留入口占位，对应契约 §9「拍照识题不做」→ 只做「语音转文字」待评估，[待验证]）；
- S3c 小白解释卡的**口语化表达风格**（一句类比优先于术语）；
- S1 的「今日任务」可以用它那种**卡片流**呈现，降低认知负担。

### 2.2 作业帮（国内拍照搜题）

**它是什么**：拍照搜题起家，题库匹配 + 解析 + 视频 + 错题本 + 练习。[二手] 百度百科：https://baike.baidu.com/item/作业帮 ；学生版：https://baike.baidu.com/item/学生作业帮

**学生使用流程（二手）**
1. 拍照题目 → 2. 题库匹配出原题 → 3. 看解析/视频 → 4. 抄写或收藏错题 → 5. 下次继续拍。

**提示/反馈机制**：**答案优先**。解析通常完整，视频是「老师讲一遍」。没有「按需最小提示」的概念，也没有「提示次数/独立性」数据。

**做得好的**
- 识题速度快、题库覆盖广（这是学生「秒出答案」心智的来源）；
- 错题本 + 知识点标签，把「一道题」沉淀成「一类题」；
- 解析分层（文字/视频/知识点），照顾不同耐心。

**不适合我们的**
- **搜题心智 = 抄答案心智**，一旦学生把我们的产品当「不给答案的作业帮」，差评会集中在「没用」；
- 完整解析 + 视频，与红线冲突；
- 家长/商业导向的付费墙，不适合课堂试点。

**可借鉴的交互点**
- S2 选题的**知识点标签与题目卡片**（难度、预计时长、必做/选练）；
- S5 完成页的**「错题/薄弱点」沉淀**（我们对应「自检卡 + 复测提醒」）；
- S6 教师端可以借鉴「班级错题分布」这种**聚合视图**（契约 S6 已要求卡点知识点 Top5）。

### 2.3 Khanmigo（Khan Academy，商业 AI 导师）

**它是什么**：Khan Academy 的 AI  tutor，定位「不直接给答案、用提问带学生思考」，教师/家长可查看对话记录。[二手] 官方：https://www.khanmigo.ai/ ；Khan 家长介绍页（视频）：https://www.khanacademy.org/khan-for-parents/khan-for-families/x47d2dcef03b6d5f6:welcome-to-khan-academy/x47d2dcef03b6d5f6:meet-khanmigo/v/khan-academy-for-families-what-is-khanmigo

**学生使用流程（二手）**
1. 在 Khan 的练习/文章里点「Tutor me」；
2. 与 AI 多轮对话（AI 先问「你卡在哪」/「你先说说思路」）；
3. 学生回答，AI 追问或给一个小提示；
4. 若学生要求答案，AI 通常拒绝并继续引导；
5. 教师/家长端可看到对话与使用情况。

**提示/反馈机制**：苏格拉底式追问 + 拒绝直接给答案 + 安全/合规过滤。**没有我们这种 L0–L4 的分级预算**，提示强度依赖模型即兴发挥。

**做得好的**
- **「不给答案」被做成了商业卖点**，说明家长/老师愿意为「防止抄答案」付费——这对我们向罗老师/甲方讲价值很有用；
- 教师端「看到对话」的设计，和我们的 S6「过程数据」是同一逻辑；
- 拒绝话术成熟，不会让学生觉得被敷衍（值得抄语气）。

**不适合我们的**
- K-12 场景，数学深度不够（数分证明题的严格性要求远高于 Khan 的题目）；
- 通用对话式，无「题库/阶段/预算」约束，红线不可控；
- 成本高（每轮都调大模型），国内部署要考虑 API 成本（见 `04-技术方案`）。

**可借鉴的交互点**
- S3b 拒绝模板的**语气与结构**（接住 → 规则 → 替代动作）；
- S6 教师端「**抽看学生过程**」的抽屉式设计（契约 S6「学生详情抽屉」）；
- S7 对外话术：**「不给答案」是功能，不是缺陷。**

### 2.4 OATutor（开源智能导师系统，最值得抄提示机制）[已核实]

**它是什么**：UC Berkeley 等开源的 ITS（智能导师系统），React + Firebase，主打代数/统计练习 + BKT 知识追踪 + 提示系统。仓库：https://github.com/CAHLR/OATutor ；研究者页：https://oatutor.webflow.io/researchers ；本地源码：`D:\DeepSeek Harness\数学分析证明题智能体\_research\repos\OATutor-main\`

**学生使用流程（按源码还原）**
1. 选课/选 lesson（`src/components/problem-layout/LessonSelection.js`）；
2. 做题卡（`ProblemCard.js`）：输入答案 → 判对错（`src/platform-logic/checkAnswer.js`）；
3. 卡住时展开提示：提示按顺序解锁，**第 n 条提示依赖第 n−1 条**，还能有子提示（`src/components/problem-layout/HintSystem.js`、`SubHintSystem.js`）；
4. 提示类型里有 `scaffold`（脚手架）与 `bottomOut`（到底提示，直接给答案）；
5. 答对/答错都会更新 BKT 掌握度（`src/models/BKT/BKT-brain.js`）；
6. 系统记录「提示是否影响得分」（`src/util/helpPenaltyMode.js`），教师可配置。

**提示/反馈机制（关键源码证据）**
- **提示链 + 依赖锁**：`SubHintSystem.js` L44–L52 `isLocked(hintNum)`——第 0 条默认开，之后每条要检查 `dependencies.every(d => hintStatus[d] === 1)`。**含义：不给「跳级提示」**，跟我们的 L1→L4 递进同构，但 OATutor 是「卡片逐条展开」，我们是「对话式逐级追问」。
- **提示类型**：`SubHintSystem.js` L73–L96 区分 `bottomOut` 与 `scaffold`；`hint.type === "scaffold"` 时才渲染子提示。**含义：最后一级提示是「到底」**，对应我们的 L4（示范 1–2 行 + 交还），但 OATutor 的 bottom-out 会直接给答案——**这里必须改**，我们的 L4 也不给最终答案。
- **提示扣分三档**：`src/util/helpPenaltyMode.js` 定义 `Never / AnswerReveal / OnOpen`：从不扣分 / 仅到底提示扣分 / 打开第一条提示就标记「本次不计分」。**含义：OATutor 已经把「求助 vs 独立性」做成可配置策略，这直接支撑我们契约 §8「是否独立完成」字段的设计。**
- **学生状态建模**：`analyzeStudentState-parameters.md` 列出 10 类状态（BKT、Student State、Problem/Step/Hint State、Agent Chat、Platform、Conversation History、Problem Context、Student Analysis），其中 `studentState` 含 `currentAnswer / isCorrect / attemptCount / hintsUsed / timeOnStep / skillMastery`。**含义：我们要的「过程数据」它基本都有字段，可直接作为我们数据字典的参照。**
- **AI 助手**：`AgentChatbox.js` / `AgentHelper.js` / `DynamicHintHelper.js` 把学生状态打包给 LLM 生成提示。**注意：它默认「AI 聊天不扣分」（`DEFAULT_CHAT_PENALTY_MODE = Never`），也就是学生在聊天里问 AI 不影响成绩——这与我们「过程数据要反映独立性」的目标相反，不能照抄。**

**做得好的**
- 提示的**顺序性、依赖关系、到底级**都有工程化实现，不靠模型即兴；
- 把「求助代价」做成显式策略（教师可配），为「独立完成」指标打了地基；
- BKT 掌握度 + 题目推荐，有学习科学依据（知识追踪）。

**不适合我们的**
- 题型是**填空/选择/短答案**，不是「写证明」；它的 `checkAnswer.js` 无法判断证明步骤；
- bottom-out 直接给答案，违反红线；
- 界面是「答题卡 + 展开提示卡片」，没有「对话式陪练」的温度；
- BKT 四参数（0.1 初始）是通用默认值，不适用于证明题的能力刻画。

**可借鉴的交互点（落契约）**
| 借鉴点 | 怎么改 | 落点 |
|---|---|---|
| 提示逐级解锁、不可跳级 | L1→L4 必须按序，点 L2 前先看 L1 是否用过 | **S3a 提示阶梯浮层**（契约已定「当前可用级别/剩余次数/升一级理由」） |
| 提示依赖锁 | 同一错误点连续 n 次才解锁下一级（契约 L3/L4 触发条件已有） | S3 状态机 |
| 提示扣分三档 | 改成「**记录但不惩罚**」：L1/L2 记「半独立」，L3/L4 记「依赖」，学生端不显示惩罚 | 契约 §8 字段 + S6 看板 |
| 学生状态 10 类 | 抽 8 个做我们的数据字典（题号/轮次/阶段/提示等级/诊断/输入/覆盖/用时） | 契约 §8 |
| 掌握度 | 用「要点覆盖 + 独立完成率」替代 BKT 概率 | S5 掌握度 |

### 2.5 interactive-proof（开源「证明阅读 + 解释」产品，最值得抄交互）[已核实]

**它是什么**：Next.js 应用，把数学论文与 Lean 形式化证明并排阅读，选中任意文本/声明让 AI 解释。[已核实] 本地源码：`D:\DeepSeek Harness\数学分析证明题智能体\_research\repos\interactive-proof\` ；仓库：https://github.com/jjjhenriksen/interactive-proof

**学生使用流程（按源码/文档还原）**
1. 打开一个 proof package（论文页 + Lean 文件 + 映射）；
2. **选中一段文本**（最小 2 字符，`components/selection-menu/selection-types.ts` `MIN_SELECTION_LENGTH = 2`）；
3. 弹出 5 个动作：**更多细节 / 讲简单点 / 连到 Lean / 这在哪用到 / 侧聊提问**（`EXPLANATION_ACTIONS`，同文件）；
4. 解释面板流式返回，带「证据芯片」（引用来源）与「深度档位」（concise/standard/foundational，`docs/features/02-guided-learning.md`）；
5. 解释完给**恰好 2 个**后续动作（"Keep exploring"，`components/explanation-panel/explanation-panel.tsx` L267–L277）；
6. 可切到**证明地图**看这一步依赖什么、被谁用（`components/proof-map/proof-map.tsx`、`lib/proof-map/derive.ts`、`docs/features/03-proof-map.md`）。

**提示/反馈机制**
- **不是「提示阶梯」，而是「选中-解释」**：学生自己指定「哪里不懂」，AI 围绕这段解释，不评价整份证明；
- **深度档位**：concise / standard / foundational，其中「Simpler」= 更基础的解释（对应我们的 S3c 小白解释卡）；
- **结构化后续动作**：固定 2 个建议（服务端校验来源，不允许模型乱编），避免「开放式聊天」把学生带偏；
- **证据芯片**：每个解释都挂来源，防止幻觉（我们的「定义原文/定理原文」可借鉴）；
- **边界**：无账号、无进度、无题库；教师层只是 P2 spec（`docs/features/06-instructor-layers.md`）。

**做得好的**
- **「学生选哪里，就解释哪里」** —— 把控制权交给学生，天然避免「整题讲解」；
- 深度档位是「一次只调一个旋钮」，跟「每轮只推进一个认知动作」同构；
- 后续动作用结构化数据约束，防止 AI 自由发挥；
- 证明地图的「依赖/被用」视角，可以迁移成我们的「这一步用了哪条定义/定理」。

**不适合我们的**
- 对象是**数学论文/Lean 代码**，不是本科证明题；没有「题目—阶段—提示预算」；
- 无账号/班级/教师数据，不能支撑 S6；
- 依赖 Lean 工具链（重），我们本轮不接真模型、不接 Lean。

**可借鉴的交互点（落契约）**
| 借鉴点 | 怎么改 | 落点 |
|---|---|---|
| 选中即锚定 | 学生点「这一步」或选中自己写的某一句 → AI 只针对这句反馈（**天然满足「引用学生原话」**） | S3 分步草稿区（每步可被选中/提交） |
| 5 个动作 | 抽成我们的「**我卡在哪**」三选一：看不懂概念 / 不知道下一步 / 不确定依据 | S3 提示按钮的入口分流 |
| 深度档位 | 映射 L1（点名定义）/L2（方向）/L3（一步操作）与 S3c 小白解释 | S3a、S3c |
| 恰好 2 个后续动作 | 「60 秒替代动作」后给 2 个可点选项（如「先只写第一步」/「换一道更简单的同类题」） | S3b |
| 证据芯片 | 定义/定理提示必须附「教材原文出处」占位（本轮可写「定义原文」不编页码） | S3、S3c |
| 证明地图 | 极简版：本题「5 个关键要点」的依赖关系（学生不可见全文，只显示覆盖状态） | S4 覆盖表 |

### 2.6 SocraticMath（研究项目，数据集参考）[二手]

**它是什么**：CIKM'24 论文与开源研究代码，SocraticLLM（Qwen1.5-7B+LoRA）+ SocraticMATH 数据集（6,846 组多轮苏格拉底对话、513 个小学数学知识点）。代码 MIT、数据集 CC BY-NC 4.0（**禁止商用**）。依据本地调研：`D:\DeepSeek Harness\数学分析证明题智能体\_research\notes\02-项目源码体检与底座调研.md` §2.2-5；仓库：https://github.com/ECNU-ICALK/SocraticMath

**学生使用流程（研究设定）**：学生做题 → 模型按「review（复述题意）→ heuristic（启发式提问）→ rectification（纠错）→ summarization（总结）」四阶段对话 → 学生自己得出答案。

**提示/反馈机制**：四阶段教学策略 + 多轮追问；强调「不直接给答案」，与我们的红线同源。

**可借鉴**
- **四阶段可以作为我们 P1–P4 的交叉验证**：review≈P1/P2（复述题意）、heuristic≈P3（追问）、rectification≈P3（只指第一个错）、summarization≈P5（复盘）；
- 对话数据结构可用于构造我们的**评测集**（什么问题算「好提示」）；
- 领域是小学算术，**不能直接迁移到数分**（数学严谨性、量词、反例构造完全不同）。

**不适合**：无前端/账号/题库；数据许可禁止商用；模型是 7B 规模，数分推理能力不足。

### 2.7 Lea（Lean 4 证明代理，远期参考）[已核实]

**它是什么**：npm workspaces monorepo：本地 React UI + FastAPI adapter + Lean 4 定理证明代理（`apps/lea-standalone`、`apps/overleaf-extension`、`packages/lea-model-catalog`）。本地源码：`D:\DeepSeek Harness\数学分析证明题智能体\_research\repos\Lea-main\README.md`；仓库：https://github.com/VIDA-NYU/Lea

**学生使用流程（README 还原）**：选定理/论文块 → AI 在 Lean 里尝试证明 → 看运行时间线、编译结果、证明产物；支持 Overleaf 扩展把论文定理转成 Lean。

**提示/反馈机制**：**形式化验证反馈**（对/错由 Lean 编译器判定），不是教学提示；证明过程完整可见（时间线）。

**做得好的**
- 「对错可验证」的确定性，是我们远期「证明步骤校验」的终极形态；
- 过程时间线/事件流设计，可借鉴做「学生过程回放」（教师端抽看）。

**不适合我们的**
- 部署重（README 提到 Docker 镜像数 GB 级，含 Lean+Mathlib）、Windows 支持差；
- **根目录无 LICENSE，默认保留所有权利，不可改造分发**（依据 `_research/notes/02` §2.2-7）；
- 面向形式化证明，大一大二学生不需要写 Lean。

**可借鉴**：S6 教师端「学生过程回放」的交互（按时间轴看每轮提交与提示）——本轮可只做静态抽屉，**P1**。

### 2.8 Proof Blocks / ScaffoldLM（研究参考）[二手]

**Proof Blocks**
- 是什么：把证明拆成若干「证明块」，学生**拖拽/排序**拼出证明，系统自动判分（ITiCSE 2022）。论文：https://dl.acm.org/doi/abs/10.1145/3502718.3524774
- 学生流程：读题 → 从块库拖出必要块 → 排序 → 提交 → 自动判分/看哪块错。
- 可借鉴：**降低「写证明」的输入摩擦**——把「想」和「打公式」分开。对应我们的 S3 草稿区可做「插入常用推理模板」的轻量版（[待验证] 是否算泄题，因为块库本身可能提示方法）。
- 不适合：块库会**替学生做结构选择**，可能变成「选择题式证明」，降低生成性；自动判分需要形式化或预定义结构，数分证明自由度太高。

**ScaffoldLM**
- 是什么：ACL 2026 论文 *Planning-Guided Tutoring with Assessment-Driven Memory for Pedagogical LLM Tutors* 提出的教学框架（标题已在 ACL Anthology 核实：https://aclanthology.org/2026.acl-long.325/ ；PDF：https://aclanthology.org/2026.acl-long.325.pdf）；检索结果中提到 ScaffoldLM 在教学表现上优于基线（[二手]，未读全文）。
- 可借鉴：**「先规划再对话」+「评估驱动的记忆」**——即 AI 内部先有教学计划（对应我们的六阶段与内部「关键要点」），每轮根据学生状态更新记忆（对应我们的轮次/提示预算/薄弱点记录）。
- 不适合：研究框架，无产品壳；具体效果未独立验证。

## 3. 横向对比：提示强度谱系与我们的位置

| 档位 | 谁在这 | 给学生的信息量 | 风险 |
|---|---|---|---|
| **① 直接给答案** | 作业帮、豆包爱学 | 完整解析/答案 | 抄完就忘，独立性归零 |
| **② 分步讲解** | 通用 AI（豆包/DeepSeek）、Khanmigo（部分） | 3 步以上推导链 | 看懂但复现不出；红线擦边 |
| **③ 逐级最小提示 + 只指第一处** | **OATutor（提示链）**、**我们** | L0 追问 → L1 定义 → L2 方向 → L3 一步 → L4 示范 1–2 行 | 提示设计成本高；容易变「挤牙膏」 |
| **④ 结构化拼装/自动判分** | Proof Blocks、logic learner | 块库 + 判分 | 替学生做结构选择 |
| **⑤ 形式化验证** | Lean/Lea、DeepSeek-Prover | 对/错确定 | 门槛高、工具链重 |

**我们的位置 = ③，且是「对话式 + 只指第一处可疑 + 过程数据」的 ③。**
两个必须守住的差异：
1. **不给完整证明**（③里 OATutor 的 bottom-out 会破例，我们不）；
2. **不给整题判分**，只标第一处可疑（契约 D1 默认口径）。

## 5. 给甲方/评审的三条差异化主张（可直接用）

1. **「不给答案」不是能力不足，是产品定位。** Khanmigo 证明「不给答案」可以成为卖点；国内搜题产品证明「给答案」的留存靠抄，学习效果差。
2. **「只指第一处可疑」比「整题判对错」更适合证明题。** 证明题错一处全错，整题判错会打击学生；只指第一处，学生有明确的下一步动作。
3. **「教师看过程数据」是学校采购的真正理由。** 竞品给学生的是一份解析，给老师的是一份成绩；我们给老师的是「卡点、提示次数、是否独立完成」——这正好对应罗老师能用来改进教学的东西。
