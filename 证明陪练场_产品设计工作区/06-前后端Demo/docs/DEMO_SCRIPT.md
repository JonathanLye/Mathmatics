# 前后端 Demo · 演示脚本（v2 六层版，8–10 分钟）

> 版本 v2.1 ｜ 日期 2026-10-31 ｜ 作者：产品设计（product-designer）｜ 适用：罗老师/甲方/答辩评审
> 依据：`SIX_LAYER_V2_CONTRACT.md`（v2 契约）、`../README.md`（v2 说明）、实际实现（`node tests/e2e.mjs` **111/111 PASS**；前端 QA 截图 `../_qa-v2/shots/`）
> 目标：10 分钟讲清三件事——① 六层全部看得见、每层都有明确提交入口；② AI 是教练（主动指令 + 主动 offer），不是旁白；③ 红线在后端执行（第 4 层由学生讲，AI 只核对）。

## 5. 翻车预案

| 情况 | 立刻怎么做 |
|---|---|
| 端口被占/服务没起来 | `set PORT=8788` → `start-demo.cmd`（PowerShell：`$env:PORT="8788"`） |
| 页面白屏/接口 500 | 切 `../05-演示原型/index.html`（纯前端原型）或播 30 秒录屏 / QA 截图 |
| 提交后层不前进 | 先看 AI 教练反馈里缺哪项（这是设计行为）；不要连点；可展示 409 原因 |
| 提示按钮点不动 | 正常：未解锁（409）或预算用尽（429）；展示原因并走软着陆 |
| proactive 没出现 | 确认连续两次同一处失败（第 3 层）；或口头说明「两次失败才 offer」 |
| 教师端数字被演示改乱 | 后端面板 reset；演示学生本就不计班级统计 |
| 对方问「怎么没有 10 节点了」 | 「v2 把 10 节点教学顺序升级为六层工作台，六层 = 前置知识/解析/步骤/讲解/同类题/总结；旧接口保留兼容，/review 已停用。」 |
| 对方问「能不能直接看参考证明」 | 「参考证明只在服务端内部用于重合度检测（guard），学生端接口做了字段白名单，拿不到；这是产品红线。」 |

## 6. 可复制文本（演示时直接粘贴）

**L1 复述**：`条件收敛就是级数本身收敛，但取绝对值后发散。`

**L2 四栏**：
- 要证什么：`判断级数是否收敛，若是，是条件收敛还是绝对收敛。`
- 要证几件事：`两件：先证收敛，再证绝对值级数发散。`
- 关键词与量词：`交错级数、条件收敛、p 级数`
- 可能用到的知识点：`莱布尼茨判别法、p 级数判别法`

**L3 先故意错两次**：结论 `分母变大`，依据留空（两次）。

**L3 四步正确内容**：
1. 结论：`1/√(n+1) < 1/√n，{u_n} 单调递减`；依据：`因为 n+1 > n，所以分母变大，值变小。`
2. 结论：`lim 1/√n = 0`；依据：`因为 n^{1/2} 趋向 +∞，所以 1/√n 趋向 0。`
3. 结论：`由莱布尼茨判别法，该级数收敛`；依据：`因为前两步满足判别法的条件。`
4. 结论：`∑1/√n 是 p=1/2 的 p-级数，故发散`；依据：`因为 p≤1，p 级数发散。`

**L4 完整讲解**：`这道题要判断级数是否收敛，若是，是条件收敛还是绝对收敛。先证原级数收敛，再证绝对值级数发散。关键步骤是：用不等式说明单调递减，说明极限为 0，由莱布尼茨判别法得收敛。因为 p≤1 所以发散。结论是条件收敛。`

**L5 同类题**：`绝对收敛，因为 1/n² 是 p=2>1 的 p 级数。`

**L6 总结三栏**：
- 我学到的知识点：`条件收敛：原级数收敛，取绝对值后发散。`
- 最容易错的重难点：`最容易错的是莱布尼茨判别法的单调性条件。`
- 下次的解题步骤：`先核对单调递减，再确认极限为 0，然后用判别法，最后补绝对值发散。`
