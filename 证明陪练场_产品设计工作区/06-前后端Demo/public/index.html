演示提示

讲解用

1. 看请求：切到「学生端」在六层工作台点一次大提交（如「提交我的理解」），再回「后端与数据」看请求日志，能看到 POST /api/attempts/:id/knowledge、状态码与耗时。

2. 看红线：故意点未解锁的 L4、或在终稿里粘贴含「证毕/综上」的文本，观察 guard 拦截与 4xx。

3. 看数据：点「事件流」刷新，能看到六层每步提交、提示、拒绝都被记录；点「重置数据」会重新 seed 回 36 人班级。

4. 看预算：提示次数、独立性三档、卡点 Top5 都由后端聚合，前端不写死。

这里不是 mock 面板：每个卡片都对应契约中的一个 API；后端未启动时会显示「等待后端启动」而不是崩溃。
④ 说明

六层引导工作台：每一层都由学生先做，AI 再反馈

零依赖：原生 HTML/CSS/JS + Node.js 内置模块；六层全部显式可见，提交入口在每层输入区下方；默认 mock AI，可选 DeepSeek。

架构

浏览器 ↔ Node ↔ JSON
浏览器（public/） index.html + app.js + styles.css 学生端 / 教师端 / 后端与数据 / 说明
fetch HTTP ↓ ↑ JSON

服务端内部调用

guard.mjs红线闸门：预算/解锁/泄题
store.mjsdb.json 持久化 + seed
metrics.mjs教师看板聚合

一次点击的数据流

真实请求
  1. 学生在 S3 写一步 → 点「提交这一步」
  2. 前端 api('POST','/api/attempts/:id/step',{text})，携带 Bearer token
  3. 后端校验 token / 预算 / 解锁 / guard 红线
  4. ai.mjs 按脚本节点返回三段式；guard 拦截则返回安全兜底
  5. store 把这轮写入 attempt + events；返回 state / draft / guard
  6. 前端渲染 AI 气泡与草稿；「后端与数据」记录 method/path/status/耗时
评审重点：前端不自己算预算、不自己判断解锁、不存完整证明；这些都是服务端返回值。

红线在后端哪一层

服务端执行

不给完整证明：guard.mjs 禁用词 / 编号步骤 / 关键要点泄漏 / 与 referenceProof 重合度；命中返回 L0 兜底句。

提示预算与解锁：/hint 由服务端返回 409 HINT_LOCKED 或 429 BUDGET_EXHAUSTED + softLanding。

不下发答案：GET /api/problems/:id 字段白名单，不含 keySteps / hints / referenceProof。

教师数据：CSV 默认匿名账号码；独立性按 C1 三档（仅 L0 / L1–L2 / L3–L4 或粘贴）聚合，不合成单一百分比。

完整 8 条 guard 规则：禁用词、编号骨架、长度、关键步骤泄漏、referenceProof 重合、连读检测、每轮三段式、问句唯一——均以 server/guard.mjs 为准。
