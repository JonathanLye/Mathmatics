# 项目背景与目标

> 来源：《数学分析证明题辅导智能体_需求确认书20261027》《证明陪练场_技术方案_v2.0》《学生端回答方案_v1.0》《关键条件》
> 用途：让任何第一次接触本项目的人，5 分钟内知道「为什么做、给谁做、做到什么算成功」。

## 1. 问题：不是不会算，是写不出

数学分析课的核心训练是**证明写作**。学生的典型困境不是看不懂参考证明，而是：

- 看答案时「懂了」，合上答案写不出第一步；
- 不知道下一步该调用哪个定义或定理；
- 写下了几步，但说不清每一步的依据；
- 作业反馈周期以天计，卡住时没人即时拉一把；
- 通用 AI 一问就给完整证明，看完更不会写。

一句话：**难点在「从看懂到写出」的过程，而现有工具要么不反馈，要么直接给答案。**

## 2. 我们要做的产品

一个手机/平板可用的**证明题分步练习系统**：

1. 学生分步写证明，每一步都要写依据；
2. AI 不写证明，只指出**第一处可疑步骤**，并用提问把学生推回思考；
3. 学生卡住时，按 **L0–L4 提示阶梯**逐级给最小帮助，每给一步就交还学生；
4. 教师能看到班级卡点、提示次数、是否独立完成；
5. 一个月后自动复测，数据可导出用于教改论文。

**内部项目名**：证明陪练场。**类比**：驾校陪练——教练不替你开车，只在你快压线时点一句；你最终得自己把车开回去。

## 3. 服务对象

| 对象 | 描述 | 核心诉求 |
|---|---|---|
| 主要：大一/大二数分学生 | 正在学数学分析（上下册），手机/平板为主 | 卡住时有即时、不给答案的帮助 |
| 次要：考研复习学生 | 需要系统练证明、查漏补缺 | 按知识点刷题 + 过程反馈 |
| 教师（罗老师） | 任课教师，负责题库审核与试点组织 | 看到真实卡点，不做额外大量工作 |
| 项目组/研究者 | 开发、教研、论文 | 可复现的干预 + 可导出数据 |

## 4. 成功标准（来自需求确认书）

| 指标 | 目标 | 说明 |
|---|---|---|
| 前后测平均分提升 | ≥10%，实验班比对照班多 ≥8 个百分点 | 同知识点、同难度、不同题 |
| 学生周活跃 | ≥70% | 每周至少使用 1 次 |
| 教师愿意继续使用 | ≥4/5 | 试点结束问卷 |
| 数据导出可用 | 100% | 可直接进 SPSS/R/Excel |

## 5. 产品形态与范围

- 需求确认书写的是：**原生微信小程序 + 管理员后端网页**。
- 技术方案 v2.0 写的是：**Next.js 网页应用**（手机/平板可用），并明确首版不做开放拍照问答。
- **本轮（2026-10-31）定位**：先做**单文件 HTML 快速原型**，把学生端流程和教师端看板演示清楚，验证「学生怎么用、老师看什么」；视觉与真实 AI 后续再升级。
- 只做**数学分析证明题**，不铺开做高数全科、线代、多门课。

### 5.1 交付必须包含（需求确认书）

登录/入班；50 题题库；分步作答；L1–L4 提示；步骤诊断；总结；学生进度；教师看板；防泄题；CSV/Excel 导出；一个月复测；（需求书另提到）拍照上传自己做的题，AI 给出修改指引。

### 5.2 明确不做（需求确认书）

家长端；学生社交/排行榜；自动批改完整证明并给分；原生 App；多学校多租户；拍照识题；公式键盘；错题本/变式题；作业布置。

> 注意：需求书内部对「拍照上传」与「拍照识题」、「L1–L3」与「L1–L4」、「AI 问答区」与「不做拍照识题」存在表述冲突，已列入《决策记录与待确认清单》，本轮原型按「不做拍照问答、只做证明分步练习」执行。

## 6. 时间与成本（需求确认书）

| 项目 | 内容 |
|---|---|
| 开发时间 | 2026-11-01 至 2026-11-07 |
| 收费方式 | token 套餐费用定金 + 完成开发后支付尾款 |
| 成本构成 | AI 套餐费用、人工费用、后期维护（小程序内容维护、服务器、认证等） |
| 免费原则 | 长期免费（甲方自筹，学校提供服务器/网络/教研支持） |

技术方案 v2.0 给出的更细里程碑：11-07 前完成技术验证并冻结选题与提示规则；11-21 前全量开发与功能冻结；11-29 前通过内测门槛；12-01 至 12-27 实验期。

## 7. 本项目的三条命门

1. **不能变成答案机**：一旦学生能稳定拿到完整证明，整个干预和论文都不成立。
2. **干预要稳定可复现**：提示词、模型版本、题目包要冻结并记录版本。
3. **过程数据要真的有用**：教师看板不是装饰，指标必须能回答「学生卡在哪、是否独立完成」。
